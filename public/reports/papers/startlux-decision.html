核心结论

决策模型平时用一次前向读出选项概率；只有最高概率低于 0.9 时才生成推理，再把推理前后两次读出按 1:3 融合。推理能力用 RLCD² 训练：奖励是「推理让概率质量提升了多少」减去超长惩罚，而不是「答对没有」。

01 · 问题

现有开源决策模型都是单次前向、不生成 token，碰到算术、排期、规则核对这类要多步计算的决策就不行；而做过决策训练的模型，直接打开生成也想不出来或停不下来。

02 · 做法

同一套「选项字母读出」接口，分出两个变体：Instant 在全注意力层用双向注意力；AutoThink 按置信度决定要不要推理。推理先用 SFT 教会生成和结束，再用 RLCD² 压长度、保质量。

03 · 结果

DI 0.3 公开子集上各规模都领先同级模型 7.4–16.9 分；在独立的 DecisionPivot 上 AutoThink 比 Instant 高 11.5–18.4 个点。RLCD² 让 9B 的推理正常结束率从 45.9% 提到 93.9%。

01 · DECISION MODEL

决策模型：一次前向，读出选项概率

LLM 系统里有大量「小判断」：这条请求该路由给谁、这段检索结果相不相关、这次工具调用参数对不对、agent 这一步算不算完成。决策模型就是专门做这类判断的模型。

这里的决策模型不生成回答，只回答带类型的问题（typed decision）。一次请求包含一个输入状态（字符串或任意 JSON，可以带图片）和若干个有名字的问题；每个问题是三种类型之一：多选一、是或否、2–10 级的有序等级。选项还可以附上一段自然语言判定标准。模型对每个问题输出一个选项上的概率分布。

概率本身是产品的一部分：下游系统拿它决定是自动执行、换一个更强的模型，还是转人工。所以这类模型除了要选对，还要概率可信，即模型说 80% 的那些判断，真的大约有 80% 是对的。

选项字母读出

StartLux-Decision 不加分类头。每个问题单独拼成一个 prompt：状态、问题、用单个字母 A–Z 标号的选项。只跑一次前向，在最后一个 prompt 位置取这几个字母 token 的 logits，过一个带温度的 softmax：

几个工程细节：一次最多 26 个选项，更长的列表按每组 25 个并行打分，每组前 3 名进决赛轮；同一请求里的多个问题作为 batch 的不同行处理；上下文最长 262,144 token；视觉塔冻结不训练。论文拟合出来的温度全部大于 1，说明训练完的模型天然偏自信。

已有的几类决策模型

论文的对照对象都在这个范式里，下面三类和本文关系最直接。

Jev（TypeSafe AI）
托管模型 · 2026.09 · 参数量未公开
本文 RL 方法的起点

和 Jev 一起发布的 RLCD（Reinforcement Learning for Calibrated Decisions）是面向决策概率的强化学习；RLCD² 明确建立在它之上。

缺口：Jev 只能调 API，训练算法没有公开，本文也没有复述 RLCD 的细节；能看到的 RLCD 做法来自开源复现 OpenJev-RLCD（见第 05 节的对照）。在 DecisionPivot 上 Jev 成对准确率 31.0%，校准误差 13.8 个百分点，系统性偏自信。
TypeSafe 公开了什么，以及相关工作

发布博客（Diogo Almeida，Introducing System One Models & Jev ↗，2026-09-15）只给了定位和产品指标，下面是博客自己的说法：

  • System One Model：名字取自 Kahneman 的快思考 / 慢思考。放弃生成字符串，输入非结构化状态，输出预先定义好类型的决策和概率，「一次查询并行给出所有输出」。
  • 三样新东西：新模型架构、并行采样器、RLCD。博客把 RLCD 和 RLHF、RLVR 并列：前两者分别优化人类偏好和可验证奖励，RLCD 优化「概率如实的决策」。
  • 指标：端到端 70–500 ms；选项最多 255 个，选项特别多时先逐个独立打分、再显式选择。
  • 博客没有给出 RLCD 的训练目标或算法。

其他相关工作：

  • OpenJev-RLCD（arXiv 2609.38850 ↗，arXiv preprint，2026.09）：给推理模型做的 RLCD 开源实现，作者明确说只在行为上和 Jev 对比，不对 Jev 的内部算法做任何断言。
  • 社区里 Jev 风格的开源权重：JEV-9B / JEV-27B（AutoTrust AI）、FlyMyJev-4B、OneJev 0.8B，在 DI 0.3 上 22–54 分。
  • 第三方评测：JevBench（本文训练时剔除了它的 231 道公开题），以及研究 Jev 校准和概率公理一致性的工作。

这三类做法的共同点：全部是单次前向，延迟低，但一个 token 都不生成。这对「这条评论是不是讽刺」这类判断够用，对需要逐条核对规则或做算术的判断就不够了。下一节看具体卡在哪。

02 · GAP

单次前向的两个短板：算不动，也想不动

第一个短板大家能猜到；第二个是论文实际训练时撞上的，也决定了后面的训练顺序。

计算类决策，一次前向答不好

DecisionPivot 是论文配套发布的 benchmark，题目由程序生成、答案可程序验证，内容是策略核对、算术、排期这类要多步计算的决策。题目大多成对出现，一对题只差一个改变答案的细节；成对准确率（pair accuracy）要求两道都答对，专门检查模型能不能分清「看起来几乎一样、答案却不同」的情况。

在同一个 AutoThink checkpoint 上关掉推理和打开推理对比：9B 的成对准确率从 22.3% 变成 59.9%，27B 从 48.0% 变成 86.9%。权重完全相同，差别只在有没有生成推理。

做过决策训练的模型，打开生成也不会想

直接给决策模型打开生成并不能恢复推理能力。论文观察到两种方向相反的失败：

  • 4B：想不出来。被要求推理的题里，约 40% 几乎不生成任何推理。
  • 9B：停不下来。约 70% 一直生成到长度上限，陷入重复循环。

这也解释了为什么不能直接上 RL：附录里把 policy gradient 直接用在一个经常输出空推理的 checkpoint 上，结果模型在约三分之二的决策上干脆跳过推理，平均每题只有 57 个推理 token。所以 Stage 3 必须先用 SFT 教会生成和结束，RL 才有东西可优化。

这个现象不是 StartLux 独有的。OpenJev-RLCD 在 Qwen3-1.7B 上用概率评分直接端到端训练推理，MMLU-Pro 上约 100 步后，每题的 4 条推理全部退化成空推理，模型变回一个直接打分器；他们把它叫作 System-One collapse。原因是推理模型写完推理后结论往往很果断，读出接近 one-hot，适当评分规则会重罚每一次自信的错误；而「不推理、直接给一个保守的概率」学得更快，policy gradient 就把概率全推向了空推理。

全文要回答的问题

怎样让决策模型在保留单次前向和概率输出的前提下，只在需要时加入能可靠结束的推理，并且推理之后的概率仍然可信？

03 · ARCHITECTURE

Instant 与 AutoThink：同一个读出接口，两种用法

两个变体都用上一节的选项字母读出，区别在注意力掩码和要不要生成。论文 Figure 2 把训练和推理放在一张图里，先看整体，再逐个拆开。

  • Base model（Qwen3.5 / Qwen3.8）：线性注意力层与全注意力层混合的架构。后面所有改动都不加新模块，只改训练数据、掩码和读出位置。
  • Stage 1 · Full-parameter SFT：所有规模共用的起点，在 Lux-Release 上做全参训练（0.8B–9B 约 270 万条，27B 约 80 万条），学会在最后一个位置给出选项概率。
  • Stage 2 的两条分支：同一份数据（Lux-Rounds，约 170 万条）各训一个 adapter，然后合并回主权重。上面一支打开双向注意力并做多次训练的权重平均，直接产出 Instant（0.8B–27B）；下面一支保持因果注意力，因为后面要做自回归生成。
  • Stage 3 · Reasoning Supervision + RLCD²：只有因果分支走这一步，先 SFT 教会推理，再用 proper score 奖励做 RL，产出 AutoThink（4B–27B）。
  • 下半部分的色块：灰色是 prompt，紫色是最后一个 prompt 位置，从这里读出 p0；红色是推理轨迹，推理结束位置再读一次字母 logits 得到 p1。两次读出用的是同一套权重。
  • 一句话总结：两个变体共享 Stage 1 和数据，分叉点在注意力掩码；AutoThink 多了一个「读 → 想 → 再读」的回路。

Instant：prompt 已经完整，就让前面的 token 看见后面

单次前向时整个 prompt 在预测前就全部可见，因果掩码其实没有必要。Instant 在全注意力层去掉因果掩码（4B 和 9B 的 32 层里有 8 层），让「状态」部分的表示也能参考后面的问题和选项；线性注意力层保持因果，读出位置不变。

  • 为什么要训练时就用双向掩码：直接给因果训练过的模型换掩码会打乱预测（论文引用 LLM2Vec 的结论），所以 Stage 2 就用新掩码训练。关掉双向时，实现与原始因果实现逐比特一致。
  • 收益：同一个 Stage 1 checkpoint、同一份数据、只差注意力配置的对照里，5 个规模中有 4 个提升，最多 +2.4 分（种子间波动 0.2–0.7）。另一组实验里，它在 Stage 2 数据没覆盖的 16 个任务上也提升了 3.0 分。
  • 代价：部署时每个运行时都要单独实现。vLLM 用插件在全注意力层不带掩码重算 prompt，llama.cpp 把 GGUF 标成 non-causal 并打一个小补丁，MLX 自己实现掩码。

AutoThink：先读，没把握再想

AutoThink 保持因果注意力，推理时走 Read-or-Think 流程。每个问题先做一次因果单次前向得到 p0；如果最高概率不低于门槛 g = 0.9，直接返回 p0。否则开启推理，重新处理 prompt，最多生成 4,096 个推理 token，在推理结束处再读一次字母 logits 得到 p1。最终输出的「默认答案」不是只用 p1，而是把两次读出融合：

论文式（2）。门控对每个问题单独判断；推理没在 4,096 token 内结束时，运行时会强制收尾。

门槛 0.9 和权重 0.75 是怎么定的

两个数都在训练分布的留出数据上确定，没有用评测集：

  • 门槛 g = 0.9：在留出数据上，9B 用 0.9 已比单次读出高 1.0 分，平均每题 596 个推理 token；改成「总是推理」不再涨分。把没把握的题送去推理，就拿到了大部分收益。
  • 权重 α = 0.75：按「默认答案的 Brier 分数最小」选出，9B 和 27B 上 0.75 最优，4B 接近最优。它不是准确率最高的选择：9B 在 DecisionPivot 上等权融合 56.6%、α=0.75 为 59.9%、只用 p1 为 61.5%。保留 25% 的 p0，是因为推理后的概率有些偏自信，在留出数据上单次读出本来就挺准。
04 · TRAINING

三阶段训练：Lux-Release → Lux-Rounds → Lux-Think + RLCD²

Stage 1、2 训练和细化概率读出，Stage 3 只给 AutoThink 加推理，同时不能把单次读出的能力训坏。

RLCD²

几个容易被忽略的设计选择：

  • Stage 1 用全参而不是 adapter：4B 上把 Stage 1、2 都换成在原始底座上训一个 adapter，DI 0.2.1 只有 63.3 和 58.2，全参训练是 64.8。
  • Stage 2 的种子平均：Instant 是多次训练的权重平均，而且是用 DI 公开分数挑出来的，这一点影响下文对 DI 结果的解读。
  • 按 parent group 去污染：同一个状态派生出的记录共享一个 parent group，训练集剔除与 DI 测试集、JevBench 公开题、DecisionPivot 重叠的样本时，整组一起剔除。
05 · RLCD²

RLCD²：按推理带来的概率提升给奖励

常见的推理 RL（DeepSeek-R1、DAPO 一类）奖励的是答案对不对。决策模型的输出是概率分布，「对不对」看不出概率是否变得更可信，所以 RLCD² 换了一个奖励。

奖励：推理后的评分减去推理前的评分

对输入 x，先用冻结的起点模型（推理监督之后、RL 之前的那个 checkpoint）读出单次概率 p0(x)；策略模型生成一条推理 τ 后，再由同一个冻结模型读出 p1(x, τ)。奖励是两次读出在适当评分规则下的差，再减去超出预算部分的长度惩罚：

p0 那一项什么时候起作用

同一道题的所有 rollout 共享同一个 p0。如果一组里全是非空推理，S(p0) 是常数，组内中心化后直接抵消，相对优势只由推理后的评分和长度惩罚决定。它真正起作用的地方是和空推理比较：空推理奖励固定为 0，而非空推理的奖励是「相对 p0 的提升」。按这个定义可以推出三种情况：

r > 0
推理让正确选项的概率质量变好，且没超预算太多。比空推理好，被强化。
r = 0
空推理（≤8 token）。相当于「不想」的基准线。
r < 0
推理反而把概率带偏，或长度惩罚超过了收益。比「不想」还差，被压制。

论文说初始评分是「解读推理增量价值的参照」，上面三种情况就是这句话的具体含义。不按标准差归一化（沿用 Liu et al. 2025 的做法），是为了让奖励差异小的组只贡献相应小的更新。

评分规则：为什么用适当评分规则，又为什么加权

适当评分规则（proper scoring rule）的定义是：如果真实分布是 π，报告 q = π 时期望得分最高。用它当奖励，模型拿最高分的方式就是如实报概率，而不是把概率推到 0 或 1。Brier 分数和 log 分数都是适当的，后者就是 Stage 1、2 用的负交叉熵。

  • B = 512：长度约减半，但成对准确率掉到 52.9%（Brier 奖励为 53.8%）。预算太紧，计算类决策想不完。
  • B = 2,048：59.2%。
  • B = 3,072（发布版）：59.9%，比 RL 前低 0.4 个点（区间 [−1.8, +0.8]），正常结束率约 99%。

  • 所有配置下留出集准确率变化不超过 0.6 个点；预算 512 时，Brier 和决策加权两种奖励都能改善校准和结束率。
  • 另一个对照：把生成上限放大 4 倍，对一个陷入重复循环的模型几乎没用，结束率只从 11% 到 13%。光放宽上限解决不了停不下来的问题。

和 OpenJev-RLCD 的做法对照

Jev 的 RLCD 没有公开，目前能看到的完整 RLCD 做法来自 OpenJev-RLCD（Gao & Wang，arXiv preprint，2026.09，原文 ↗ · 代码 ↗）。它在 Qwen3-1.7B 上实现，读出方式和 StartLux 几乎一样：推理以 Answer: 结尾，直接读选项 token 的 next-token 分布 u(x, r)，不采样答案。两篇的分歧集中在三个选择上。

第一，给每条推理单独打分，而不是给一组推理的混合分布打分。OpenJev 用 Brier 分数下的一个恒等式说明原因：

OpenJev-RLCD 命题 1。J 是正向的 Brier 分数（越大越好），u(r) 是推理 r 之后的读出，p 是多条推理读出的平均，q 是真实结果分布。

给混合分布打分，等于逐条打分的平均再加上各条推理之间的分歧。分歧不需要任何依据就能拿分，策略可以靠随机改结论来刷分。同一个恒等式还说明了 RLVR 为什么让模型过度自信：答案按 one-hot 采样时，逐条打分正好就是 RLVR 的目标，它等于混合目标去掉多样性项，最优解变成众数而不是真实分布。StartLux 的 RLCD² 也是对每条推理单独读出 p1、单独算分。

第二，先校准读出，再强化推理。端到端一起优化会出两种问题：一是第 02 节提到的 System-One collapse（加 β = 0.04 的 KL 锚可以避免）；二是 policy gradient 项的梯度范数是读出项的 7–12 倍，主导了 Adam 的二阶矩估计，把低方差的读出信号淹没。于是配方拆成两段：

  • Stage 1 校准：在模型自己采样的推理之后，用适当评分规则训练读出；推理只当作 on-policy 的隐变量，不被强化。
  • Stage 2 强化：从 Stage 1 的模型出发，用同一个适当评分作奖励做 REINFORCE（leave-one-out baseline），score-function 项乘 0.3 降权，KL 锚定在校准后的模型上。

第三，谁来打分。OpenJev 用策略模型自己的读出算奖励，Stage 1 里读出器本身也在被训练；StartLux 用冻结的起点模型读出 p0 和 p1，奖励只随推理文本变化，而且奖励的是 p1 相对 p0 的提升。StartLux 没有 OpenJev 那样单独的读出校准阶段，读出靠 Stage 1、2 的交叉熵训练和温度缩放，推理时再用 p0 融合压低推理后的偏自信。

  • RL 帮不上的情况：在 ChaosNLI 上，不确定性来自标注者之间的分歧，推理消除不了。没有哪种 RL 变体超过直接用交叉熵训练，逐条打分的目标会自己学会不再推理。
  • 局限：只用了 1.7B 模型、400–800 步、3 个种子；GSM8K-Verify 是作者自己构造的任务。

概率可靠性的另外两项检查：证据敏感性与跨问法一致性

08 · POLICY-AWARE CALIBRATION

best-of-N 和路由之后，置信度会失真

这是论文里最值得单独拿出来的发现：单条预测校准得再好，经过下游的「挑选」或「分流」之后，同样的置信度就不再对应同样的准确率。AutoThink 的门控本身就是一种分流。

一个具体数字：用 9B 当 verifier，单独看时被打了 80–90% 置信度的回答有 92% 是对的；但从 32 个候选里挑出得分最高的那个之后，同一置信区间的准确率只有 78%。模型没变，变的是「哪些预测被返回」。

  • 挑最高分会挑中向上的噪声：候选越多，赢家的分数越可能是偶然偏高的（论文类比为 optimizer's curse）。
  • 落选者的分数也有信息：如果所有候选得分都低，说明题难；只看赢家一个分数会丢掉这个信号。
  • 普遍性：N = 16 时 113 组 generator–verifier 中有 111 组的选中回答偏自信；126 次运行里校准差距全部随 N 增大。按置信度做门控也一样，12 个模型中 11 个在相同报告置信度下，经过门控的预测准确率更低。
  • 对阈值的影响：在单条预测上认证过「错误率 ≤ 5%」的阈值，用到 best-of-16 的选中回答上，67 组里有 44 组实际错误率超标；直接在选中回答上认证就没有超标。

做法：在部署策略的输出上重新拟合校准映射

不重训模型，只在有标签的校准集上把部署时的策略完整跑一遍，用策略实际返回的预测来拟合校准：

  • 门控、级联：按路由置信度的分位数分层，每层内单独做 isotonic 校准。
  • 候选挑选：用报告置信度、候选平均分、N、log N 拟合一个 logistic 模型，再做 isotonic 校准。
  • 接受阈值按策略的每条路线分别认证。

在 best-of-N、门控、级联、先挑后想四类流程共 184 个设置上，有符号的置信度–准确率差距从 [−11.7, +20.5] 缩小到 [−2.7, +2.1] 个百分点。但它对分布偏移敏感：在留出分布上拟合的映射，迁移到没见过的数据集时仍有最多 6.1 个百分点的偏自信。

落到 AutoThink 自己身上

留出集上，默认答案的校准误差为 3.7 / 2.2 / 1.6（4B / 9B / 27B），只用推理后读出则是 8.1 / 3.7 / 2.8。按 5% 目标错误率设接受阈值时，9B 和 27B 约一半的默认答案可以自动接受，4B 只有 2%；4B 只接受推理后的预测，覆盖率能升到 23%，因为它的错误集中在高置信的单次读出里。直接作答和推理后作答两条路线，需要分别认证阈值。

09 · BOUNDARIES

什么时候别用 AutoThink，什么时候别全信这些数字

论文自己给出的限制，加上数据表里能读出来的边界。

对延迟敏感就用 Instant

Instant 不生成 token：H200 上 1,024 token 的 prompt，0.8B 单次读出约 31 ms，27B 约 98 ms（BF16）。AutoThink 被门控送去推理的那部分题要多付整段生成的时间。

收益集中在训练覆盖过的任务族

Stage 2 加入评分、安全、偏好、逻辑类数据后，对应的 18 个任务涨 8.6 分，其他任务只涨 0.3 分；加流程类训练数据让 4B 在生成的事实判断题上从 61.5% 到 75.8%。论文把「泛化到没覆盖的任务族」列为未来工作。

DI 分数带有选型偏差

Instant 的数据配方、注意力变体和种子平均组合都是按 DI 公开分数选的，而且只评了占排行榜 20% 的公开部分。真正独立的证据是 DecisionPivot。

融合权重在不同分布上方向相反

α = 0.75 让 27B 在留出集上的校准误差从 3.7 降到 1.6，但在 DI 上按排行榜指标反而让校准误差增加 0.8–2.0 个点。权重要按自己的目标分布、同时看概率质量和准确率来定。

跨运行时只保证最高选项一致

vLLM 插件、MLX 与参考实现的最高选项一致率在 99.4–99.9%，但概率数值并不完全相同。如果下游用概率阈值做决策，换运行时或换量化版本后要重新校准。
