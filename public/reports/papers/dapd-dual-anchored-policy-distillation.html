核心结论

  1. OPSD 让同一个模型看着参考解答当 teacher，训到后期模型学会了一件坏事：推导失败就补一句「我记得答案是……」然后照着往下写。五个 Qwen3 规模合起来，这类生成从每万次 13.0 涨到 37.0，同期 reasoning Avg@12 从 59.56 掉到 53.24。
  2. 论文把根因定在信息不对称：teacher 看得见参考解答、student 推理时看不见，原来的目标把「student 自己也能复现的指导」和「只有看见答案才做得出的行为」一起灌进了 student。DAPD 引入一个 Self 分布——条件在它自己正在预测的那条 completion 上——当可训练的中间桥，让每次对齐都发生在两边信息量相同的时候。
  3. Qwen3-4B 六个 benchmark 平均 57.34，比 OPSD 高 2.00 分。更值得记的是规模趋势：OPSD 相对 Base 的增益在 8B 以上几乎归零（最多 +0.28），DAPD 在 8B / 14B / 32B 还有 +2.41 / +2.13 / +3.06。

01OPSD 训着训着，模型开始说「我记得答案是」

先看清这个失败长什么样，再谈怎么修。

On-policy self-distillation（下文按论文简称 OPSD）近两年在后训练里越用越多。它的构造很省事：teacher 和 student 是同一个模型，区别只在于 teacher 的 user message 里多塞了一段该题的参考解答。student 从当前策略采一条 rollout，然后在这条 rollout 的每个前缀上，让 teacher 的输出分布去监督 student 的输出分布。

比起 SFT 的固定示范和 RL 的稀疏 outcome reward，这套做法同时占了两个便宜：监督发生在当前策略真正会走到的状态上，而且是 dense 的 token-level 信号。论文用两个名字区分这两种输出分布：

pNone = pθ(· | x, y<t) ← student：只有题目 pCross = pθ(· | x, y<t, y*) ← teacher：题目 + 参考解答 y* 𝓛OPSD = E [ (1/|y|) · Σt D( sg[pCross] ‖ pNone ) ]

sg[·] 是 stop-gradient，D 是两个 token 分布之间的散度。teacher 那一侧不接收梯度，训练只更新 student 这一侧。

麻烦出在最后一步：y* 只在训练时存在，推理时 student 一个字也看不到。被这样训过之后，模型学到的不只是「参考解答里那些它自己也推得出来的思路」，还有「手上握着答案时才做得出的动作」。论文管这个后果叫 privilege illusion——模型表现得像那份看不见的材料还在手边。

探针：什么样的生成才算数

为了让这件事可量化，论文定了一个行为探针，把符合下面这个模式的生成记为一次 wrong claim：先声明自己的推导失败了，然后把一个具体答案归因于记忆、某份参考、或某个外部来源，而最终答案是错的。

探针明确排除了几类容易误判的情况：一般性的不确定表述、普通的猜测、回忆某个公式、以及「查阅之后发现」这类泛泛说法。也就是说，它抓的不是「模型不自信」，而是「模型编了个来源」。

两条曲线一起动，说明 privilege illusion 不是训练早期的噪声，而是随 OPSD 训练进程长出来的，并且实打实地压低了推理表现。下面这个来自 AIME24 的例子是它最典型的样子——两侧用的是同一道题、同一套解码设置，推理时都没有参考解答。

OPSD：编了一个来源
推导走进死路之后
…外切的情形下距离是 6+2*6=18，于是 r = √(11²−18²)，这是虚数，不可能。……我真的卡住了只能放弃，但我记得答案大概是 36/7。所以 m+n = 36+7 = 43。
✗ 答 43
DAPD：从题目本身推完
同一道题、同一套解码设置
情形 1：内切。…… √(6²+c²) = 11−3 = 8。…… Px = … = 33/4。外切时球心距离是 11+3 = 14，…… Px = … = 33/7。于是 ri − ro = 33/4 − 33/7 = 99/28，…… m+n = 127。
✓ 答 127

题目：圆环大半径 6、小半径 3，与之相切的球半径 11；若 ri − ro = m/n，求 m+n。正确答案 127。左侧那句「我记得答案大概是」正是探针要抓的模式——不是算错，是放弃推导之后给答案编了个出处。

02两派修法都在改 teacher 信号

这一节的三张卡片说明为什么已有做法只能缓解、不能消除。

privilege illusion 不是新发现，已有工作大致分两派。第一派直接用特权信息：把 teacher 条件在参考解答上，然后把它的全部监督蒸下去。第二派做选择性转移：承认这份监督里混着脏东西，于是对 teacher 信号做过滤、重加权或者路由，试图只留下干净的部分。

下面三张卡片是本文的直接对照。折叠着读也能看清各自的角色和缺口，想看具体做法再展开。

▶ OPSD · Zhao et al. 2026a · 第一派 全文的起点，也是所有实验的主对照。同一个模型，把参考解答插进 teacher 的 user message，蒸馏 Cross → None。留下的缺口：teacher 和 student 的信息量从第一步起就不一样，这件事本身没被碰过。

OPSD 的贡献是去掉了对独立 teacher 模型的依赖。传统蒸馏要准备一个更强的模型当 teacher，OPSD 让同一个模型通过「多看一份参考解答」变得更有信息量，从而在自蒸馏的框架里拿到 dense 监督。

输入是一对 (x, y*)；从当前 student 采一条 rollout y；在 y 的每个前缀上算 p_Cross 和 p_None，用前者监督后者。输出是更新后的 student 参数。

在 Qwen3-4B 上它确实有效——六项平均 55.34，高于 Base 的 54.46。问题在后面：这个增益随规模衰减得很快，到 8B 以上几乎消失。

▶ Purified OPSD · Shen et al. 2026 · 第二派最强 六项平均 56.25，是 DAPD 之外表现最好的方法，也是它的主要竞争对手。做法是用 pointwise mutual information 修正，把「光看参考解答就能预测出来的那部分」从特权监督里减掉。留下的缺口：减的是信号内容，teacher 和 student 仍然处在不同的信息条件下。

它的判断很直接：既然 teacher 之所以比 student 强是因为多看了 y*，那就把「可以单靠 y* 推出来」的那部分概率质量识别出来并扣掉，剩下的应该就是 student 有能力复现的指导。

这个思路在数字上是站得住的——它把 OPSD 的 55.34 推到了 56.25，是唯一一个明显超过 OPSD 的已有方法。DAPD 相对它还有 +1.09 的差距，这也是全文最有说服力的一组对照：换掉监督的信息条件比清洗一个信息条件不对的信号更有效。

▶ DOPD · Yu et al. 2026 · 第二派另一条路 按 advantage gap 和相对概率，在 token 级别把监督在特权 teacher 和 student 策略之间动态路由。留下的缺口：同样没动信息条件；而且在本文这套统一设置下反而低于 OPSD（53.49 对 55.34），连 Base 都没超过。

DOPD 不做减法而做选择：逐 token 判断这一步应该听 teacher 的还是听 student 自己的，判据是两者的 advantage 差距和相对概率。想法是在「teacher 明显更懂」的位置才转移监督。

它在本文这套统一设置下没能超过 Base（53.49 对 54.46）。论文没有分析这个结果的成因，只把它和 Purified OPSD 一起归入「仍在原始的信息不对称设置下工作」这一类。

另外两个第一派的方法在表里也出现了，但都没起作用：SDFT（Shenfeld et al. 2026，用条件在专家示范上的 EMA 自 teacher）六项平均 54.17，SDPO（Hübotter et al. 2026，用成功的同伴 rollout 或环境反馈当条件）53.19——两个都低于 Base 的 54.46。

这两派的共同盲区

过滤、重加权、路由，动的都是 teacher 那一侧的信号；没有一个去动「teacher 有 y*、student 没有」这件事本身。一个握着答案的 teacher，仍然在监督一个必须空手作答的 student。

还有第二个盲区：它们都只把 reference 当唯一的指导来源。当 policy 变强、rollout 本身开始有价值的时候，这部分信号被整个浪费了。

03只换 student 侧的分布，wrong claims 降 45%

全文的枢纽是这个对照实验：teacher 一个字没改，问题就轻了一半。

如果根因真的是信息不对称，那么不动 teacher、只把 student 侧换成一个信息量对等的分布，问题就应该缓解。论文就是这么做的。

teacher 那一侧原样保留 p_Cross——还是那个看得见参考解答的分布。student 那一侧的 p_None 被换成一个新分布，论文叫它 Self：

pSelf = pθ(· | x, y<t, y) ← 条件在它自己正在预测的那条 completion 上

注意这里插进去的是 y，也就是模型自己刚采出来的那条 rollout，不是参考解答。这个替换的唯一效果是：Cross 和 Self 现在都拿到了一条完整的 completion，两边的信息量对上了。teacher 的构造方式、参考解答的用法、采样方式全都没变。

−45%
训练后期（steps 250–300）的 wrong claims：33 次降到 18 次
+6.22
reasoning Avg@12 的平均提升，五个规模

一次只改 student 侧分布的干预，就拿到了这个幅度。论文由此把结论收紧：问题不出在 teacher 质量上，而出在两边信息量不等。

原来的目标同时在灌两种东西

顺着这个诊断回头看 𝓛_OPSD，teacher 和 student 的差异其实混着两类完全不同的成分：

  • student 能从 prompt 复现的指导：参考解答提示了一条思路，但这条思路模型自己顺着题目也走得到。这部分是真正有用的监督。
  • 只有看见 y* 才做得出的行为：直接跳到某个中间结论、对某个数值表现出没来由的确信。student 在推理时复现不了这些，但训练目标照样在鼓励它们。

论文把这种混在一起的更新命名为 Entangled Distillation。这个名字也解释了第 2 节那两派为什么都只能缓解：它们改的是信号内容，没改产生这个信号的信息条件。只要 teacher 和 student 站在不同的信息位置上，纠缠就还在。

而上面这个干预本身，后面成了 DAPD 的一个正式组件，叫 Privileged Anchor。

04None、Cross、Self：三个分布差在看得见什么

这三个名字是全文的骨架，后面每一项 loss 都由它们两两组合而成。

为了把上面的想法推广到一般情形，论文引入记号 s ∈ {y, y*} 表示「被预测的那条 completion」，s̄ 表示另一条。在 token 位置 t，下面三个分布共享同一个前缀 s_<t，唯一的差别是额外看见了什么：

pNones = pθ(· | x, s<t) 什么都没有 —— 和推理时 student 面对的信息完全一致 pCrosss = pθ(· | x, s<t, s̄) 额外看见另一条 completion pSelfs = pθ(· | x, s<t, s) 额外看见它自己正在预测的这条

Self 初看有点怪：让模型在预测一条 completion 的时候，把这条 completion 整个给它看。但它的两个性质正好补上了一个空位——

  • 相对 Cross，Self 是可训练的。它和 None 共享同一套 policy 参数，梯度传得进去；而 Cross 在 OPSD 里始终是 detached 的 teacher。
  • 相对 None，Self 和 Cross 信息量对齐。两边都拿到一条完整的 completion，所以它们之间的对齐是「公平」的。

把这两条合起来看：可训练但没有特权信息的 student（None）和有特权信息但 detached 的 teacher（Cross）之间，本来缺一个既可训练、又拿得到完整 completion 的中间态。Self 就是那个中间态。有了它，就不必再硬把一个有特权信息的 teacher 直接怼到一个没有特权信息的 student 头上。

落到 user message 上，差别只有一处

这三个分布听起来抽象，实现上的区别其实只有一件事：user message 里插不插一段 completion、插的是哪一条。拿论文附录给的那道原文例题走一遍——题目是比较 p = 2^3009、q = 3^2006、r = 5^1003 的大小；参考解答 y* 把三者都改写成 1003 次方（8^1003、9^1003、5^1003），于是 r < p < q。

Noney
Problem: {比较 2^3009、3^2006、5^1003} Please reason step by step, and put your final answer within \boxed{}.
什么都不插。这也是推理时唯一会出现的 prompt 形态。
Crossy
Problem: {同上} Here is a reference solution: === Reference Solution Begin === {y*：改写成 8^1003 / 9^1003 / 5^1003，得出 r < p < q} === Reference Solution End === 读完之后确保你真的理解每一步的 道理，不要抄写或改写；现在用你 自己的话独立推出同一个答案……
插的是参考解答 y*。这就是「特权信息」的全部内容。
Selfy
Problem: {同上} Here is a reference solution: === Reference Solution Begin === {y：上一步刚采出来的那条 rollout 本身} === Reference Solution End === （模板与 Cross 相同，只换插入 的那条 completion）
插的是 rollout y 自己。论文没有给这条的具体内容——它每个 minibatch 都不一样。

三栏都是在 y 的 token 上计算的，前缀完全相同。有两点值得记住：

  • 特权信息是一段明明白白的完整解题过程，不是标签，也不是什么隐藏的 teacher 内部状态。它就是一串插进 user message 的文本。
  • 这些插入的 completion 只在构造训练分布时存在。推理 prompt 里永远只有左边那一栏，一个字的特权信息都不会出现。

05三个有向目标：Entangled Distillation 和两个 Anchor

三个分布两两组合，得到 DAPD 的全部原材料。

▶ 展开图片说明 逐块拆解左右两半、粉色与蓝色箭头的含义，以及中间那个虚线框为什么是全图的关键。
  • 左半边（Dual-Source Anchoring）：两团等高线代表两个策略分布——绿色是条件在参考解答上的 teacher policy y*，橙色是 student policy y。中间那个黑点是希望收敛到的目标策略。两条弯箭头是两个指导方向：绿色的 Reference TO Rollout 和橙色的 Rollout TO Reference。它们同时存在、加权合并，这是第 7 节的内容。
  • 右半边（Dual-Path Anchoring）：把左边那条 Rollout TO Reference（y → y*）单独放大。每个小的曲线图标代表一个 token 分布，下面标着它条件在什么上面。
  • 上面一排是 unconditioned path（粉色虚线箭头）：从左到右三个分布依次是 p_None^y、中间的桥、p_None^{y*}。两段箭头分别标着 𝓛_ent^y 和 𝓛_infer^{y*}，顶上那条粉色长箭头就是它们的和 𝓛_uncond^{y→y*}。两端都是不带特权信息的 None——这正是推理时真正在用的分布。
  • 中间那个分布同时标了两个名字：p_Cross^y 和 p_Self^{y*}。这不是画图偷懒——它们共享同一套参数、条件也都是 (x, y*)，论文正是把这两个当成同一座桥来用。全图最关键的一处就在这里。
  • 下面一排是 privileged path（蓝色实线箭头）：p_Self^y 经 𝓛_priv^y 对齐到 p_Cross^y。两边都拿到了一条完整 completion，所以这条对齐是在信息量对等的条件下做的。
  • 中间那个红叉标着「OPSD ✗ Information asymmetry」，从虚线框里的 P_self 引出两条线分别去往 y* 和 y。它标记的是原来那条被判定为有问题的直接监督，以及 Self 插进来的位置。

一句话总结：右半边讲一个方向上怎么用 Self 当桥做两次信息对等的对齐，左半边讲这套构造要在两个方向上各做一遍。

有了三个分布，剩下的就是决定谁监督谁。论文定义了三个有向目标，约定 D(sg[q] ‖ p) 里第一个参数是 detached 的 teacher，第二个是可训练的 student：

𝓛ents = D( sg[pCrosss] ‖ pNones ) Entangled Distillation：原始 OPSD 那一项 𝓛infers = D( sg[pNones] ‖ pSelfs ) Inference Anchor：把 Self 拉向 None 𝓛privs = D( sg[pCrosss] ‖ pSelfs ) Privileged Anchor：两边都有完整 completion 时对齐

三项各自的作用值得分开说：

  • 𝓛_ent 被原样保留，不是被删掉。这一点容易读错。论文诊断出它是纠缠的来源，但并没有把它扔掉——参考解答带来的那部分可复现指导是真实收益，扔掉就把孩子和洗澡水一起倒了。DAPD 的做法是在它旁边补锚点。
  • 𝓛_infer 的 teacher 是没有特权信息的那份。方向是 None → Self，作用是别让拿到完整 completion 的那份分布飘得太远——它得始终对推理时那个信息条件负责。
  • 𝓛_priv 就是第 3 节那个诊断实验本身。它从一次验证性干预升格成了正式组件。
一个容易漏、但影响复现的细节：三项的 teacher 不是同一个模型

两个 Entangled Distillation 的 teacher 用的是 LoRA-on student 的周期性快照（训练中定期从当前参数拷贝刷新）；两个 Anchor 的 teacher 用的是 LoRA-off 的 base 模型。所有 student 侧的分布都由当前 LoRA-on 模型产生，它同时也是 rollout 的采样器。

06Dual-Path Anchoring：两条路径怎么把两个 None 对上

想要的对齐没有直接的 loss 项，DAPD 用两项拼出来。

先明确目标。对一个有序方向 s → s̄（读作「s̄ 提供指导、s 被预测」），我们真正想要的是什么？

推理时模型走的是 None 那条路，两边都不该依赖特权信息。所以想要的对齐发生在两个 None 分布之间——rollout 上的 p_None^y 和参考解答上的 p_None^{y*}。麻烦是：这两个分布之间没有任何一项 loss 直接连接它们。

Dual-Path Anchoring（DPA）的做法是把两项拼起来，绕过去：

𝓛unconds→s̄ = 𝓛infers̄ + 𝓛ents 以 y → y* 为例：𝓛_uncond = 𝓛_infer^(y*) + 𝓛_ent^y，其中 𝓛_ent^y 就是原始 OPSD 的 loss

参考解答侧、无特权信息
净效果：p_Noney 朝 p_Noney* 靠 —— 两端都没有特权信息

把这个机制写成一句话：p_Self^{y*} 和 p_Cross^y 共享同一套模型参数，条件也都是 (x, y*)，论文因此把它们当成同一座桥。于是 𝓛_ent^y 把 p_None^y 往桥上拉，𝓛_infer^{y*} 把桥往 p_None^{y*} 拉，联合更新的净效果就是两个 None 互相靠拢——而这两个正是推理时真正会用到的分布。

▶ 这个「隐式对齐」在什么条件下才成立 附录 B 给了两个命题和一组梯度实测。结论是：它有条件，而且论文自己测出来的相关性并不强（余弦均值 0.101）。

上面那段是直觉。论文在附录 B 把它拆成三块来论证：

  • Proposition 1（配对前缀上的对齐界）：固定一个参考前缀和一个 rollout 前缀，在 bridge-consistency 假设下（即 Self–Cross 这座桥的偏差有界），两个 None 分布之间的距离可以被两个已训练目标的取值加上桥的偏差界住。也就是说：把这两项训小，想要的 None–None 对齐就跟着变紧——前提是桥不能太松。
  • Proposition 2（序列级转移）：Entangled Distillation 把 teacher 行为转移到 on-policy 前缀上；配合一个 autoregressive hybrid bound，token 级的界被抬到序列级。这一步保证前一条不只在单个 token 上成立。
  • 共享参数那一步需要实测支撑：Inference Anchor 的更新要能穿过共享参数影响到 Cross，前提是两者的梯度在局部方向兼容。论文直接测了：梯度点积均值 256.62（bootstrap 95% 置信区间 [147.55, 393.53]），梯度余弦均值 0.101（区间 [0.058, 0.144]）；按样本平均后是 225.30 和 0.119。

怎么读这组数字：置信区间都落在正侧，说明兼容性方向上确实成立，这是论证需要的最低条件。但余弦只有 0.1 左右——两个梯度方向的夹角接近 84 度，谈不上高度一致。所以这条路径是「有效但偏弱」的间接机制，这也解释了为什么 DAPD 还需要 privileged path 直接补一刀。

privileged path：同一个方向，两边都有完整 completion 时

unconditioned path 管的是两边都没有特权信息的情形。同一个方向上还有另一种情形：两边都拿到一条完整 completion。

此时 Cross^s 拿到的是提供指导的那条 s̄，Self^s 拿到的是被预测的那条 s——两边内容不同，但信息量对等。Privileged Anchor 已经正好表达了这个对齐，所以这条路径直接复用 𝓛_priv^s，不引入新项。

以 y → y* 为例，它对齐的是 rollout token 上「自条件」和「参考条件」两种预测。两条路径合起来就是一个方向上的完整目标：

𝓛DPAs→s̄ = 𝓛unconds→s̄ + 𝓛privs

消融数字支持「两条都要」：在 reference 指导源上，只有 Entangled Distillation 时 62.13，补上 Inference Anchor 到 63.43，再补 Privileged Anchor 到 63.89；rollout 指导源上是同一个走向，63.33 → 64.91 → 65.09。两个源上台阶的方向完全一致，这比单个源上的提升更有说服力。

07Dual-Source Anchoring：reference 和 rollout 各当一次指导源

DPA 定了一个方向上怎么对齐，剩下的问题是谁来当指导源。

常规答案是 reference——它是人工校对过的，可靠。但论文提出了一个反问：当 policy 变强之后，on-policy rollout 里难道没有值得学的东西吗？

于是 Dual-Source Anchoring（DSA）把同一套 DPA 构造在两个方向上各做一遍：

Rollout-to-Reference（y → y*）
reference 提供指导，rollout 被预测

这是通常的做法，也是 OPSD 一直在用的方向。换来的是可靠性：y* 是校对过的正确解法。

放弃的是可达性：参考解答可能落在当前策略够不到的地方，属于 off-policy 的指导。

Reference-to-Rollout（y* → y）
rollout 提供指导，reference 被预测

本文新增的方向。换来的是可达性：rollout 就是当前策略自己走得出来的东西，离推理时的分布最近。

放弃的是可靠性：这条 rollout 完全可能是错的，没有任何人校对过它。

两个方向按 λ 加权合并，就是 DAPD 的最终目标：

𝓛DAPD = λ · 𝓛DPAy→y* + (1 − λ) · 𝓛DPAy*→y λ ∈ [0, 1]

消融确认了两个源确实互补：只用 reference 是 63.89，只用 rollout 是 65.09，两个都用 65.28。值得留意的是只用 rollout 反而比只用 reference 高 1.2 分——单看这组数字，「student 够得着」比「绝对正确」更值钱。

λ 怎么取：一条随规模变化的取舍

论文没有给一个通用的 λ，而是在四个规模上都扫了一遍。结果有规律：1.7B 用 0.5，4B、8B、14B 都用 0.2。

也就是说，模型越大，权重越往 rollout 那边挪。解释是直接的：小模型的 rollout 噪声大，更需要可靠的 reference 来纠偏；大模型生成的轨迹本身就更靠谱，这时候更该往「离推理时分布近」的方向学。论文把这称为 reliability–reachability 权衡。

同样的规律也出现在两个源各自的 Privileged Anchor 权重上：reference 侧的权重从 1.7B 的 0.5 一路涨到 8B、14B 的 2，rollout 侧则在 0.5、2、0.5、1 之间摆动，没有单调趋势。

08一个 minibatch 里发生了什么

把前面几节拼成一次真实的参数更新。

  1. 取一对 (x, y*)：OpenThoughts 里的题目和人工参考解答。三类能力用不同的数据域——reasoning 用 math，coding 用 code，instruct 用 math + code + science 的混合，评测集的样本全部从训练语料里剔除。
  2. 当前 LoRA-on student 采一条 rollout y ~ p_θ(·|x)：温度 1.1、top-p 0.95、top-k 20、最多 1024 个新 token。
  3. 对 s ∈ {y, y*} 各构造 None^s、Cross^s、Self^s 三个分布，全都在 s 的 token 上算。三者的差别只有 user message 里插不插、插哪条 completion（见第 4 节的三栏对照）。
  4. 算三个目标 × 两个方向共六项 loss。每个 teacher 分布都 detach，梯度只从 student 一侧回传。
  5. 按系数加权求和、反向传播，只更新 LoRA 参数。
  6. 周期性把当前 LoRA 参数拷进那份共享快照——两个 Entangled Distillation 的 teacher 用的就是它。

值得单独强调最后的推理阶段：推理时只走 None 那条路径，特权信息一个字都不出现。DAPD 增加的全部是训练时开销，推理成本和 base 模型完全一样。

▶ 散度实现与训练超参 component-clipped forward KL 的具体形式、那个 0.05 上限在防什么，以及完整的优化配置。

散度：teacher 和 student 的 logits 都先除以温度 T = 1.1。每个非 padding 的 completion token 上对全词表求和，单个词的贡献被截到上限 c = 0.05：

ℓ_c(q, p) = Σ_v min{ q_v · (log q_v − log p_v), c }

这是一个 component-clipped 的 forward KL。那个 0.05 的上限在防什么：当 teacher 在某个词上概率很高、student 上概率极低时，log q − log p 会炸到很大，单个词就能主导整个 token 的梯度。截到 0.05 之后，任何一个词最多贡献这么多，梯度由「很多词的一致偏差」而不是「一两个极端词」决定。论文在附录里比过几种散度方向和裁剪方式，component-clipped forward KL 表现最好。

由于两个分布都是在同一个采样前缀上直接算出来的，不需要 importance sampling 比值。

优化：LoRA 加在所有 attention 和 MLP 投影上，rank 64、scale 128；学习率 5×10⁻⁶，500 步线性调度、无 warmup；梯度范数裁到 0.1；bfloat16 + gradient checkpointing；有效 batch size 32；训练上下文限制 20,000 token。硬件是 8 张 A100-80GB，软件栈 PyTorch 2.8.0 / Transformers 4.57.1 / DeepSpeed 0.18.2 / vLLM 0.11.0。

随机种子：统一用 42，在模型与 LoRA 初始化、数据打乱、rollout 采样之前设置。对比实验共用同一个种子，保证初始化、数据顺序和采样流对齐。

10训练成本、权重标定，和不用人工参考的那条路

要用这套方法，这三件事得先掂量清楚。

三条明确的代价

  • 训练算力上去了。每个 minibatch 要构造六个分布、算六项 loss，而 OPSD 只有两个分布一项 loss。论文没给具体倍数，但量级上是成倍的。推理时零额外开销——这一点很关键，代价全部付在训练侧。
  • 权重可能需要跨规模、跨架构重新标定。这不是空话：论文自己那张配置表里，λ 和四个 β 在五个规模上没有两行是完全一样的。想直接套用到别的模型族上，大概率要重扫一遍。
  • reference-free 的那个增强变体需要自动正确性信号。数学题有 verifier，开放式任务上可能压根没有。

一条顺带挖出来的出路：可以不要人工参考

既然 reference 和 rollout 的价值是互补的，论文顺手问了一句：能不能干脆不要人工参考？它试了两个变体：

  • dual-rollout：采两条独立的 completion u 和 v（两条相同就重采 v），u 顶替 reference 侧的源，v 当 rollout 侧的源。两条都是 on-policy，都可能是错的。
  • verified-rollout：u 侧采四个候选，取第一个通过 verifier 的；v 保持独立、不过滤。verifier 提高了源的可靠性，但没有把任何参考解答暴露给 policy。

两条纯 on-policy 的 rollout 就已经比 OPSD 高出 2.41 分（4B 和 8B），说明第二条 rollout 不是冗余的——即便它没有任何正确性保证，它提供的仍然是「另一个视角的完整 completion」，而这正是 DAPD 需要的东西。加上 verifier 之后再涨一截，但增量在 8B 上只剩 0.18。

对手上没有 curated reference 的场景，这条路值得试：DSA 那套双指导源的结构可以脱离人工参考运行，有正确性信号时再叠上去。论文把「用 verified 或 consensus 选出来的 rollout 替换固定 reference、并随策略改进而更新这个源」列为下一步方向。

论文自己还提了另外两条：一是自适应的源信任度——既然最优的 λ 随规模变，那它多半也随样本、随 token 变，可以在线估计可靠性并给出连续权重，避免全局系数和硬门控这两个极端；二是更宽的特权信息形态——参考解答只是其中一种，检索到的文档、工具调用轨迹、verifier 反馈、中间计划，凡是「训练时有、推理时没有」的东西，都可以放进同一个框架里检验。
