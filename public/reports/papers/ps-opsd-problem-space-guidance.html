核心结论

完整参考解答更详细，却不一定更可迁移。它把通用数学关系与某一道题的最终答案、推理顺序、措辞和具体算术绑定在一起；教师据此给出的 token 目标，可能依赖学生推理时无法恢复的信息。

PS-OPSD 不改变学生 rollout，也不改变逐 token 蒸馏目标，只把教师看到的完整解答换成问题空间指导：初始状态、目标条件、约束和一条连贯的状态迁移路径。

01 · 问题

OPSD 的训练—推理接口不对称

学生始终只看问题，教师却在训练时拿到验证过的完整解答。信息更丰富与信息可迁移是两件不同的事。

On-Policy Self-Distillation（OPSD）让学生从问题 q 生成自己的推理轨迹，再让同一模型的特权教师沿着学生实际访问的前缀给出下一 token 分布。它避免了固定示范轨迹与部署时学生状态之间的偏移，也不需要永久依赖一个更强的外部教师。

拥有问题、完整参考解答、学生当前前缀
输出下一 token 的目标分布
参考答案与具体推理顺序只在训练时存在。

推理时 · 学生视图

读取q + ŷ<t
拥有问题和自己已经生成的前缀
输出推理过程与最终答案
解答、提示、教师和提取器全部缺席。

这会引出论文真正研究的表示问题：教师应该看到什么特权信息？如果 token 目标依赖「参考解答接下来怎么写」，学生可能学到训练接口中的捷径，而不是仅凭问题也能重建的状态关系。

OPSD 与其他基线分别改变了什么展开查看 SFT、GRPO、OPSD 与 AVSD 在实验中的角色。
  • SFT：学习固定参考序列，不沿学生自己访问的前缀提供监督。
  • GRPO：从可验证答案得到序列级 reward，而不是逐 token 教师分布。
  • OPSD（arXiv 2026）：让完整解答条件下的同模型教师，对学生的 on-policy 前缀逐 token 评分，是本文直接修改的起点。
  • AVSD（arXiv 2026）：组合完整解答、部分解答与仅答案等多个教师视图，重建共识与残差信号；它改变的是教师目标组合，而 PS-OPSD 重新设计单个教师视图中的信息表示。

03 · 表示

从完整解答提取四字段指导

作者没有枚举完整问题空间，而是保留一份验证解答实际走过的那部分结构。

经典问题空间可以写成 ：状态空间、初始状态、可用 operator、目标条件和约束。但一般无法枚举全部可达状态与所有 operator，一份参考解答也只暴露一条路径。

s0

Initial State

题目给出的变量、实体、已知量和关系。它描述求解从哪里开始。

G

Goal Conditions

目标与可验证的成功条件。终态满足什么，才算完成。

C

Constraints

定义域、全局不变量和合法性条件。路径上的所有状态都要遵守。

π

Selected State-Transition Path

从验证解答抽出的有序迁移记录；每一步写明 operator、前置条件、变换和结果状态。

这里的 Problem-Space Guidance 不是完整问题空间，也不是推理时追加给学生的 plan。 它只记录一条验证路径及其全局条件，离线缓存后仅供训练期教师读取。

船速问题：gPS(q,r) 是怎样合成的

离线提取器同时读取问题 q 和验证解答 r。它不是把解答压缩成摘要，而是把解答里的起点、成功条件、合法性条件和操作顺序分别写进四个固定字段。

输入问题

船分别以顺流速度 v+u、逆流速度 v-u 行驶。两次行程满足：

验证解答 r · 论文中的关键步骤
  1. 顺流与逆流速度分别是 v+u 和 v-u，因此得到两条时间方程。
  2. 令 p=1/(v+u)、q=1/(v-u)，把原问题改写成关于 p,q 的二元线性系统。
  3. 解出 p,q，再用 v=(1/p+1/q)/2、u=(1/p-1/q)/2 恢复原变量。
  4. 把结果代回两条时间方程，并检查 v > u > 0。

同一条件内，教师和学生来自相同 Qwen3 模型族与初始化。教师使用初始 checkpoint、禁用 LoRA 且不记录梯度；优化只修改学生的 LoRA。这样，OPSD 与 PS-OPSD 的直接比较主要隔离出教师上下文表示这一处变化。

坐标裁剪后的 KL 形式目标loss 机制保持不变，但实现并非标准 KL。

教师与学生 logits 先按温度 T 转成分布。对词表中每个 token 的 贡献分别裁剪到阈值 c，再对完整词表求和，并在非 padding 位置上取平均。

温度和裁剪阈值随 run manifest 记录，不同规模与运行的配置并不完全相同。论文强调这一目标应称为 coordinate-clipped KL form，而不是未经修改的 KL divergence。

学生较少显式引用看不见的答案

论文把生成中直接提及「参考解答」「答案键」「提示」或「指导」的行为记为显式 PI invocation。它是一种可观察症状，不等于对信息泄漏做了因果证明。

与 OPSD 逐题比较

23 : 9

90 道题中，23 题的正确生成数更偏向 PS-OPSD，9 题更偏向 OPSD，58 题打平；总准确率差为 +2.62 个百分点。

Base 难题覆盖

4.35%

PS-OPSD 在 Base 完全做错的题上达到 4.35% 准确率，OPSD 为 1.69%；同时保留 98.51% 的 Base 已解问题。

收益不是简单来自更尖锐的 token 分布正确路径 entropy 诊断说明了什么，也说明不了什么。

作者沿各方法自己的正确生成路径重放模型，计算每个非结构 token 的完整词表 entropy。相对 Base，OPSD 和 PS-OPSD 在三个规模上都提升平均准确率，却都没有表现出更低的正确路径 entropy。

与 OPSD 直接比较时结果随规模变化：1.7B 的 PS-OPSD entropy 更低，但 4B 与 8B 的 entropy 更高，同时覆盖率继续提升。因此实验不支持「PS-OPSD 只是让正确 token 分布更集中」这个简单解释。entropy 也不能代表语义策略多样性。

06 · 边界

论文没有证明的部分

结果支持「如何表示特权信息很重要」，但还不能把结论直接外推到所有模型、领域和求解路径。

领域范围实验只有竞赛数学，以及 AIME24、AIME25、HMMT25 三个 benchmark。
模型范围只测试 Qwen3 的 1.7B、4B、8B 三个规模，其他模型族尚未验证。
不是完整搜索空间指导来自一份验证解答的一条选定路径，没有枚举替代解法与全部可达状态。
提取成本与误差Qwen3.6-35B-A3B 离线提取增加预处理成本；提取质量本身可能成为新瓶颈。
中途纠错未验证论文没有测试多条验证路径，以及学生偏离路径后从中间错误状态恢复的能力。
诊断不是因果识别PI invocation 与 token entropy 都是表面或行为指标，不能完整定位特权信息依赖的原因。

因此，这项工作的实用启发不是「所有完整解答都应删除」，而是：当训练期教师掌握部署期学生拿不到的信息时，应把信息量和可由学生输入重建的结构分开评估。PS-OPSD 给出了一种具体、可控的表示方式，也留下了跨领域与多路径验证的问题。
