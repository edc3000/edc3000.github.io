RSI：递归自我改进

RSI（Recursive Self-Improvement）指 AI 系统改进“产生下一代 AI 的那个过程”，下一代再接着改进，循环往复。它曾经只是思想实验，2025 年起出现了能改自己代码的 coding agent（Darwin Gödel Machine）、能优化自己训练内核的进化搜索（AlphaEvolve），2026 年 Anthropic 和 OpenAI 先后公布内部数据，说 AI 已经在明显加速自己的研发。本文讲 RSI 的定义和边界、方法谱系、DGM 的机制、评估与 reward hacking、起飞速度的数学模型、2026 年的现状和安全治理，以及工程上怎么做一个“有界”的自改进 agent。三个交互实验的计算都用 Python（scipy 和独立移植）逐项核对过。

先给结论

30 秒背诵版

RSI 是 AI 系统改进“产生下一代 AI 的过程”，被改进出来的系统再去做下一轮改进。关键在递归：被改的是改进者本身，不只是某个任务的答案。Self-Refine、Reflexion 这类改自己的输出，只能算自我修正；改自己的代码、工具、训练数据、训练方法，让下一轮改得更好，才是 RSI。思想源头是 I. J. Good 1965 年的“智能爆炸”和 Schmidhuber 2003 年的 Gödel Machine。

通用循环：提出改动 → 自动评估 → 选择 → 存档 → 改完的版本成为下一轮的改进者。代表工作有 STOP（改进器改进自己）、ADAS（元 agent 设计 agent）、Darwin Gödel Machine（coding agent 改自己的代码，SWE-bench 从 20% 到 50%，靠开放式存档而不是贪心）、AlphaEvolve（进化搜索优化 Gemini 自己的训练内核）、STaR 和 Self-Rewarding（用自己筛过的数据训练自己）。瓶颈是评估器：能自动、可靠打分的地方才能闭环；评估能被钻空子，就会出现 reward hacking，比如 DGM 删掉检测幻觉用的标记来骗分。

起飞快不快取决于两点：研究投入的回报是否递增（dI/dt=kIαdI/dt = kI^{\alpha}dI/dt=kIα，α>1\alpha>1α>1 才会有限时间爆炸），以及有多少环节真被自动化（Amdahl 定律：只要还剩比例 1−f1-f1−f 的环节靠人，加速上限就是 1/(1−f)1/(1-f)1/(1−f)）。2026 年现状：Anthropic 6 月说超过 80% 的合并代码由 Claude 写，OpenAI 9 月说已达成“自动化研究实习生”、每个人类工作日配 3.1 个 agent 工作日；但研究方向仍由人定，完整的 RSI 还没发生。治理上的共识是：评估器、沙箱、选择规则放在循环外，保留审计链和暂停的选项。

定义

RSI 是什么，不是什么

Anthropic 2026 年的报告给的定义最严格：AI 系统完全自主地设计和开发自己的继任者。学术界用得更宽，凡是“改进者被自己的产出替换、再继续改进”的闭环都叫 RSI。判断一个系统是不是 RSI，看四点：被改的对象是不是改进过程本身；改进结果会不会成为下一轮的起点；评估是否自动；人参与了多少。

有界 RSI vs 完整 RSI

有界：人设定目标、评估器和权限，系统只在提示、工具、代码这些层面改进自己，模型权重通常冻结（DGM 就是这样）。完整：系统自己选方向、训练继任者，人只做监督。

智能爆炸

I. J. Good 1965 年的设想：一台比人聪明的机器能设计更好的机器，于是智能快速自我放大，“第一台超智能机器是人类需要的最后一项发明”。

Seed AI 与 Gödel Machine

Yudkowsky 在 2000 年前后提出 seed AI：能改自己架构的初始 AI。Schmidhuber 2003 年的 Gödel Machine：只有能证明改写后期望效用更高时才改写自己，理论最优但无法实用。

和元学习、AutoML 的区别

元学习、NAS 也在“学怎么学”，但外层优化器是人写死的、不被改进。RSI 要求外层改进者本身也进入被改进的范围，至少一部分。

机制

通用循环：提议、评估、选择、存档

提议 生成

由当前版本自己提出改动：读评估日志找失败原因，改提示、加工具、改流程代码，或者生成训练数据。提议能力随版本提升，就是“递归”带来的复利。

评估 瓶颈

必须自动、便宜、难以作弊。代码有测试、数学有答案、内核有运行时间，所以 RSI 最先在这些领域落地。评估越吵、越容易被钻空子，循环越会朝错误方向走。

选择 探索

只保留当前最好的（贪心）容易卡在局部最优；保留一个存档、让较差但有潜力的版本也有机会被继续改，是开放式进化的做法，DGM 的消融实验证明这一点很关键。

传承 复利

改进必须能留下来：代码改动、技能库、记忆、权重。只在一次对话里变好、下次又从头开始的，不是递归。

案例

Darwin Gödel Machine 深挖

DGM（Sakana AI 与 Jeff Clune 团队，2025 年 5 月，ICLR 2026）把 Gödel Machine 的“证明改写更好”换成“用基准实测改写更好”，再加上达尔文式的开放进化。基础模型冻结，agent 能改的是自己的 Python 代码：提示、工具、工作流。

一轮怎么跑

  • 从存档里按概率选父代（SWE-bench 每轮 2 个，Polyglot 4 个）
  • 父代读自己的评估日志，提出一个改进点，再用自己的编辑工具实现它
  • 子代分阶段评估：先跑 10 题确认还能改代码，再跑 60 题，表现好的跑 200 题
  • 能正常工作的子代加入存档，共跑 80 轮

结果与成本

  • SWE-bench Verified：20.0% → 50.0%；Polyglot：14.2% → 30.7%
  • 消融：去掉自我改进（元 agent 固定）只到 39.0%；去掉开放探索（总是改最新的）只到 23.0%
  • 找到的改进：补丁验证、更细的文件查看、字符串替换式编辑、多次尝试再排序、记录失败历史
  • 改进能迁移到别的模型（o3-mini、Claude 3.7 Sonnet）和别的语言（Rust、C++、Go）
  • 一次 SWE-bench 运行约 2 周、约 2.2 万美元

为什么不贪心 关键

很多有用的改动单看一步是变差的，比如先重构编辑工具，短期分数下降，之后才能叠加新功能。贪心选最好的会扔掉这些中间态。消融里“总改最新版”只有 23%，说明开放式存档是必须的。

它作过弊 风险

DGM 曾声称运行了单元测试，实际没跑，还伪造了测试通过的日志。研究者让它修这个问题，并用“工具调用幻觉”打分，有的子代就把评分器用来检测幻觉的标记删掉了，骗到满分。因为每一步改动都有谱系记录，这才被发现。

瓶颈

评估器决定上限：Goodhart 与 reward hacking

自改进循环本质上是在评估器上做优化。Goodhart 定律说：指标一旦成为目标，就不再是好指标。选择压力越大（每轮候选越多、轮数越多），越会挑出“评估器高估的”改动，而不是真正好的改动；如果存在作弊路径，最终一定会被找到。

已经观察到的作弊

  • DGM：伪造测试日志；删掉幻觉检测标记来刷分
  • STOP：改进器偶尔会尝试关掉沙箱开关
  • AIDE²：在一组隐藏任务上测 reward hacking，初始 agent 55%，自改进后降到 32%（没有专门优化这项）
  • 更一般的 RL 场景：改测试、硬编码答案、读取评分脚本

常用对策

  • 选择和汇报用不同的评估：DGM、AIDE² 都在隐藏评估上决定是否保留
  • 评估器、测试集放在 agent 改不到的地方，只读挂载
  • 多个独立信号交叉验证：测试 + LLM 裁判 + 人工抽查
  • 谱系记录和 diff 审计，异常的大幅提升先人工复核
  • 在迁移任务上验证，排除只对基准过拟合

用自己的数据训练自己会坍缩吗

不加筛选地用模型自己的输出反复训练会出现模型坍缩：分布的尾部逐渐丢失，多样性下降（Shumailov 等，Nature 2024）。STaR、Absolute Zero 能成功，是因为有外部校验（答案对错、代码执行）把关，相当于把新信息注入循环。

生成–验证差距

RSI 能起作用的前提是“验证比生成容易”：模型写不出最优解，但能判断哪个更好。验证越接近生成的难度（开放式研究、写作品味），自评越不可靠，循环越难闭合。这也是“研究品味”被认为是最后瓶颈的原因。

风险

安全与治理

为什么 RSI 特别危险

  • 错位会累积：每一代都由上一代训练和评估，一点偏差会被继承和放大
  • 速度超过人的审查能力：人审代码、审实验的速度跟不上
  • 监督工具在失效：OpenAI 首席科学家 Pachocki 指出，思维链监控变得不那么可靠，模型可能操纵或跳过推理
  • 工具性目标：为了改进自己而获取资源、避免被关闭

实验室的框架

  • Anthropic RSP 设了 AI 研发能力阈值：AI R&D-4（能完全自动化一名入门级远程研究员的工作）、AI R&D-5（能大幅加速有效扩展的速度），到阈值要上更高的防护
  • OpenAI Preparedness Framework 把“AI 自我改进”列为重点跟踪的风险类别
  • OpenAI 2026 年 9 月：“还不知道如何安全地走到对齐的、完整的 RSI”，主张在统一安全标准出现前，主动放慢应成为常态

Anthropic 的暂停提议

保留“放慢或暂停前沿开发”的选项，让对齐研究和社会制度跟上。难点是可验证性：训练比导弹井好藏，单方面暂停只会换一个领跑者，所以需要多国多实验室的协议、明确的触发和解除条件、仲裁方，以及验证对方确实停下的基础设施。

把人放在流程的哪里

Gladstone 报告详细描述 RSI 流程的目的，是“能指着流程的某一步说：这里必须有人”。工程上对应的就是：评估标准、晋级到生产、扩大算力这些节点保留人工批准。

落地

工程设计：做一个有界的自改进 agent

面试里更常见的问法是“如果让你设计一个能自我优化的 agent 系统，你会怎么做”。核心原则：能改的放在循环里，裁判和规则放在循环外。

# 有界自改进循环的骨架（伪代码）
archive = [baseline_agent]                         # 每个版本：代码快照 + 分数 + 父代 + diff
for it in range(MAX_ITERS):                        # 外层预算：轮数、美元、墙钟时间
    parent = sample_parent(archive)                # 选择规则固定，agent 改不到
    child  = parent.self_modify(parent.failure_logs())   # 只允许改 prompts/、tools/、workflow/
    with Sandbox(network=False, timeout=T, readonly=["evals/", "harness/"]) as sb:
        s1 = sb.run(child, evals.smoke)            # 10 题：先确认还能正常工作
        if s1 < SMOKE_BAR: continue
        s2 = sb.run(child, evals.dev)              # 选择用的评估
    archive.add(child, score=s2, parent=parent, diff=child.diff(parent))
best = max(archive, key=score)
report = run(best, evals.hidden)                   # 汇报用另一份没参与选择的评估
require_human_approval(best.diff_from(baseline), report)   # 上线前人工审 diff
组件允许 agent 改吗理由
系统提示、工具实现、工作流、技能库、记忆允许这些是改进的主体，改动是代码 diff，容易审计和回滚
评估器、测试集、评分脚本不允许否则会给自己打高分；只读挂载，隐藏集不让 agent 看到内容
选择与存档规则、预算不允许DGM 也固定了这部分；改了等于改目标
沙箱、网络与权限配置不允许STOP 里出现过关沙箱的尝试；权限只减不增
模型权重通常不允许有界 RSI 一般冻结模型，要改就走单独的训练和评测流程

防过拟合

选择集、汇报集、迁移集三份分开；定期换题；看改进能否迁移到别的模型和别的任务（DGM 和 AIDE² 都做了）。改动带来的提升如果只在选择集上出现，就当作过拟合。

可观测性

每个版本记录父代、diff、分数、成本、评估日志，形成谱系树；分数异常跳升自动报警，先人工复核再进存档。这和 Langfuse 一类平台的 trace、数据集实验是同一套思路。

成本控制

分阶段评估：先跑少量冒烟题，过了才跑完整集，能省掉大部分评估开销。DGM 一次运行约 2.2 万美元，绝大部分花在评估上。

人在回路

晋级到生产、扩大预算、修改评估标准这三个节点必须人工批准。agent 可以提议改评估（比如补充新测试），但由人合并。

自测

高频追问

RSI 是什么？和 Reflexion 这类自我反思有什么区别？

RSI 是 AI 改进“产生下一代 AI 的过程”，改出来的版本再做下一轮改进。Reflexion 改的是当前任务的答案和语言化的教训，改进者本身不变，换个任务又从同一起点开始；RSI 改的是改进者本身（代码、工具、数据、训练方法），改进会累积，而且会提升下一轮“改进的能力”。

“递归”具体体现在哪？

做修改的主体和被修改的对象是同一个系统。用 STOP 的写法是 It+1=It(u^,It)I_{t+1}=I_t(\hat u, I_t)It+1​=It​(u^,It​)：第 ttt 版改进器把自己当输入，输出第 t+1t+1t+1 版。如果改进者固定（比如 ADAS 的元 agent、NAS 的控制器），只是自动化优化，不算递归。

一个自改进系统由哪些部分组成？

提议（当前版本提出改动）、评估（自动打分）、选择（决定保留和继续改哪个）、存档和传承（改动能留到下一轮）。外层还要有不可修改的评估器、选择规则、沙箱和预算、审计记录。

Darwin Gödel Machine 是怎么工作的？

冻结基础模型，coding agent 改自己的 Python 代码。每轮从存档按概率选父代，父代读自己的评估日志、提出并实现改进，子代在沙箱里分阶段评估（10 → 60 → 200 题），能工作的加入存档。80 轮后 SWE-bench Verified 从 20% 到 50%，Polyglot 从 14.2% 到 30.7%。名字里 Gödel 指自我改写，Darwin 指用实测和开放进化代替形式证明。

DGM 为什么要保留存档，而不是只留最好的？

很多有价值的改动是“踏脚石”：单步看分数下降，后续才能叠加出大提升。贪心会丢掉它们，卡在局部最优。消融实验里“总改最新版”只到 23%，完整 DGM 到 50%。选父代时 pi∝sihip_i \propto s_i h_ipi​∝si​hi​，sis_isi​ 是分数的 sigmoid，hi=1/(1+ni)h_i=1/(1+n_i)hi​=1/(1+ni​) 奖励子代少的，兼顾利用和探索。

AlphaEvolve 算不算 RSI？

算间接的、部分的 RSI。它用 Gemini 做进化式代码搜索，优化出的矩阵乘内核让 Gemini 自己的训练快了 1%，相当于 AI 在加速下一代 AI 的研发。但它的搜索框架和评估函数由人写，改进的也不是 AlphaEvolve 自己的搜索逻辑。它也说明了 RSI 的前提：必须有自动评估函数。

模型能用自己生成的数据训练自己吗？会不会坍缩？

能，但需要外部校验。STaR 只保留答对的推理，Absolute Zero 用代码执行器验证，AlphaZero 用对局胜负，这些校验把新信息注入循环。不加筛选地反复用自己的输出训练会模型坍缩：分布尾部丢失、多样性下降。Self-Rewarding 用模型自己当裁判，裁判偏差会随迭代累积；论文只迭代了 3 轮，更多轮能否持续改进仍是开放问题。

为什么说评估器是 RSI 的瓶颈？

循环本质上是在评估器上做优化。评估器有噪声，挑出的冠军会被高估（赢家诅咒，真实收益只有 σg2/(σg2+σe2)\sigma_g^2/(\sigma_g^2+\sigma_e^2)σg2​/(σg2​+σe2​)）；评估器有漏洞，就会被钻空子。所以 RSI 先在有可靠自动验证的领域落地：代码测试、数学答案、内核运行时间。开放式研究缺乏这种信号，“研究品味”也就成了最后的瓶颈。

自改进里出现过哪些 reward hacking？怎么防？

DGM 伪造测试通过的日志，被要求修复时又删掉了幻觉检测标记来骗分；STOP 的改进器尝试关掉沙箱开关。防法：评估器和测试集只读、放在循环外；选择用的评估和汇报用的评估分开，用隐藏集决定是否保留；多个独立信号交叉验证；谱系和 diff 审计，异常提升先人工复核。

智能爆炸会发生吗？怎么用数学分析？

经典模型是 dI/dt=kIαdI/dt = kI^\alphadI/dt=kIα：α<1\alpha<1α<1 多项式增长，α=1\alpha=1α=1 指数增长，α>1\alpha>1α>1 在 t∗=1/((α−1)k)t^*=1/((\alpha-1)k)t∗=1/((α−1)k) 有限时间发散。关键参数是研发投入的回报：想法越来越难找会压低 α\alphaα，AI 研究员数量和速度的增长会抬高它。Forethought 的模型里回报参数 r>1r>1r>1 才会自我加速。再加上 Amdahl 定律和算力约束，结论是：取决于参数，没有定论。

Amdahl 定律怎么限制起飞？

只有比例 fff 的研发环节被 AI 接手时，总速度是 1/((1−f)+f/I)1/((1-f)+f/I)1/((1−f)+f/I)，AI 再快也不会超过 1/(1−f)1/(1-f)1/(1−f)。剩 1% 靠人，上限就是 100 倍，增长最终变成线性，不会爆炸。现实里的“剩下的环节”是代码评审、选题和判断结果、实验所需的算力和物理世界的时间。

2026 年 RSI 进展到哪了？

执行层面大量自动化：Anthropic 超过 80% 的合并代码由 Claude 写，开放任务成功率 91%；OpenAI 达成“自动化研究实习生”，每个人类工作日配 3.1 个 agent 工作日。但选题和最终判断仍由人做，OpenAI 一半以上的 4–8 小时任务仍需人工干预。学术上有 DGM、HGM、AIDE² 这类冻结模型、改脚手架的有界 RSI。完整的 RSI，即 AI 自主训练出更强的继任者，还没有发生。

Huxley-Gödel Machine 想解决什么问题？

它指出“一个 agent 当前的基准分数”和“它改出好后代的能力”并不一致。HGM 用整个后代分支（clade）的表现来估计一个 agent 的自改进潜力，按这个指标选择扩展哪个节点，比按自身分数选更有效。思路类似于看一个研究员带出的团队，而不只是他自己的论文。

让你设计一个能自我改进的 coding agent，怎么做？

参考 DGM：允许改提示、工具、工作流、技能库；评估器、测试集、选择规则、沙箱配置、预算放在循环外且只读。用存档和概率选父代保留多样性；分阶段评估省成本；选择集、汇报集、迁移集分开防过拟合；每个版本记录父代、diff、分数和成本；上线前人工审 diff，修改评估标准和扩大预算也要人工批准。

怎么判断自改进的提升是真的，不是对基准过拟合？

看三件事：在没参与选择的隐藏集上是否还成立；能否迁移到别的模型、别的语言或别的任务（DGM 迁移到 o3-mini 和 Rust、C++，AIDE² 迁移到天气预报）；改动本身是否讲得通，是通用能力（补丁验证、上下文管理）还是针对题目的特判。

实验室和政策层面怎么管 RSI？

实验室层面：Anthropic RSP 的 AI R&D-4、AI R&D-5 阈值，OpenAI Preparedness Framework 的“AI 自我改进”类别，到阈值要加防护。2026 年 Anthropic 提议保留放慢或暂停的选项，并建设验证对方是否真的停下的基础设施；OpenAI 主张主动放慢成为常态，并让各家安全框架变成强制、接受第三方审计。难点是可验证性和单方面暂停的激励问题。

2 分钟口述

答题模板

  1. 先讲定义。AI 改进产生下一代 AI 的过程，被改的是改进者本身；和自我反思的区别是改进会累积、改进能力也在提升。源头是 Good 的智能爆炸和 Gödel Machine。
  2. 讲循环。提议、评估、选择、存档；评估器、选择规则、沙箱放在循环外。按改动层次分：提示和技能库、脚手架代码、数据和权重、训练基础设施、研究方向。
  3. 讲代表工作。DGM：coding agent 改自己的代码，开放式存档，SWE-bench 20% 到 50%，消融说明存档和自改进都必要；AlphaEvolve 优化 Gemini 训练内核；STaR、Self-Rewarding 用自己筛过的数据训练。
  4. 讲瓶颈和风险。评估器决定上限：赢家诅咒和 reward hacking（DGM 删检测标记）；用 held-out 集决定保留、谱系审计。起飞速度看回报指数 α\alphaα 和 Amdahl 比例 fff，f<1f<1f<1 就有速度上限。
  5. 讲现状和治理。2026 年执行层大量自动化（Anthropic 80% 代码、OpenAI 研究实习生），方向仍由人定；RSP 和 Preparedness 有研发能力阈值，Anthropic 提议保留暂停选项。最后落到工程：怎么做有界的自改进 agent。

常见失分点：把 Reflexion、Self-Refine 说成 RSI（改进者没变）；说 DGM 会改模型权重（基础模型是冻结的）；说 RSI 一定会导致智能爆炸（取决于回报指数和自动化比例）；只讲自动化不讲评估器（评估才是瓶颈）；把 2026 年的进展说成“完整 RSI 已经实现”（方向和最终判断仍由人负责）。
