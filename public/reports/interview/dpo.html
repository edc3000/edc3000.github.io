DPO：从 RLHF 推到一个分类损失

DPO 常被问三件事：损失是怎么从 RLHF 的目标推出来的？具体怎么算，一个回答的概率怎么由每个 token 拼起来？训练时为什么 chosen 的概率也会往下掉？本文把推导、手算和梯度都摊开。

30 秒背诵版

不训奖励模型、不采样：用策略和参考模型的对数概率比当隐式奖励，做一个二分类

出发点：RLHF 的目标是 最大化奖励，同时用 KL 约束不偏离参考模型。这个目标的最优策略有闭式解 π∗(y∣x)∝πref(y∣x)exp⁡(r(x,y)/β)\pi^*(y\mid x)\propto\pi_{\text{ref}}(y\mid x)\exp\big(r(x,y)/\beta\big)π∗(y∣x)∝πref​(y∣x)exp(r(x,y)/β)，反过来就能把奖励写成 r(x,y)=βlog⁡π∗(y∣x)πref(y∣x)+βlog⁡Z(x)r(x,y)=\beta\log\dfrac{\pi^*(y\mid x)}{\pi_{\text{ref}}(y\mid x)}+\beta\log Z(x)r(x,y)=βlogπref​(y∣x)π∗(y∣x)​+βlogZ(x)。

损失：代入 Bradley-Terry 偏好模型，两个回答的奖励相减，难算的配分函数 Z(x)Z(x)Z(x) 正好消掉，得到 L=−log⁡σ(r^w−r^l)\mathcal{L}=-\log\sigma\big(\hat r_w-\hat r_l\big)L=−logσ(r^w​−r^l​)，其中隐式奖励 r^=βlog⁡πθ(y∣x)πref(y∣x)\hat r=\beta\log\dfrac{\pi_\theta(y\mid x)}{\pi_{\text{ref}}(y\mid x)}r^=βlogπref​(y∣x)πθ​(y∣x)​。本质是对“chosen 比 rejected 好”做逻辑回归。

怎么算：一个回答的 log⁡π(y∣x)\log\pi(y\mid x)logπ(y∣x) 是它每个 token 的 log 概率求和（不是平均）。每步只需要策略和冻结的参考模型各前向一次，不用奖励模型、不用采样、不用价值模型。

梯度：chosen 的每个 token 被推高、rejected 的每个 token 被压低，系数都是 β σ(r^l−r^w)\beta\,\sigma(\hat r_l-\hat r_w)βσ(r^l​−r^w​)：模型排错时系数接近 β\betaβ，已经排对且差距大时接近 0。β\betaβ 越大越贴近参考模型。

核心追问

梯度怎么落到每个 token

对损失求导（DPO 论文给出的形式）：

∇θLDPO=−β E[σ(r^l−r^w)⏟排错时权重大(∇θlog⁡πθ(yw∣x)−∇θlog⁡πθ(yl∣x))]\nabla_\theta\mathcal{L}_{\text{DPO}}=-\beta\,\mathbb{E}\Big[\underbrace{\sigma(\hat r_l-\hat r_w)}_{\text{排错时权重大}}\Big(\nabla_\theta\log\pi_\theta(y_w\mid x)-\nabla_\theta\log\pi_\theta(y_l\mid x)\Big)\Big]∇θ​LDPO​=−βE[排错时权重大σ(r^l​−r^w​)​​(∇θ​logπθ​(yw​∣x)−∇θ​logπθ​(yl​∣x))]

而序列 log 概率是 token 求和，所以：

∇θlog⁡πθ(y∣x)=∑t=1∣y∣∇θlog⁡πθ(yt∣x,y<t)\nabla_\theta\log\pi_\theta(y\mid x)=\sum_{t=1}^{|y|}\nabla_\theta\log\pi_\theta(y_t\mid x,y_{<t})∇θ​logπθ​(y∣x)=t=1∑∣y∣​∇θ​logπθ​(yt​∣x,y<t​)

每个 token 拿到的信号 token 级

  • ywy_wyw​ 的每个 token：沿 ∇log⁡πθ(yw,t)\nabla\log\pi_\theta(y_{w,t})∇logπθ​(yw,t​) 方向被推高，系数 β σ(r^l−r^w)\beta\,\sigma(\hat r_l-\hat r_w)βσ(r^l​−r^w​)。
  • yly_lyl​ 的每个 token：被压低，系数相同。
  • 同一个回答里每个 token 的系数完全一样，和 GRPO 把优势复制给每个 token 是一个思路；但 DPO 是求和，不除以长度。
  • prompt 部分不算进去，只对回答 token 求和。

两个容易忽略的结论 加分项

公共前缀互相抵消：如果 ywy_wyw​ 和 yly_lyl​ 前面若干 token 完全相同，这些 token 在两边的条件和取值都一样，梯度一正一负正好抵消。真正起作用的是两者开始不同之后的部分。

权重自动“难例挖掘”：已经排对且差距大的样本，σ(r^l−r^w)→0\sigma(\hat r_l-\hat r_w)\to0σ(r^l​−r^w​)→0，几乎不再贡献梯度；排反的样本权重接近 1。没有这个权重（直接最大化 log⁡π(yw)−log⁡π(yl)\log\pi(y_w)-\log\pi(y_l)logπ(yw​)−logπ(yl​)）会训崩，DPO 论文专门做过这个对比。

代码

# logits: [B, T, V]，已和 labels 错开一位；mask: [B, T]，回答部分为 1，prompt 和 padding 为 0
def seq_logp(logits, labels, mask):
    logp = torch.gather(logits.log_softmax(-1), 2, labels.unsqueeze(-1)).squeeze(-1)   # [B, T]
    return (logp * mask).sum(-1)                       # [B]，求和，不是平均

# chosen 和 rejected 拼成一个 batch 一起前向，省一次 kernel 启动
pi_w, pi_l = seq_logp(policy(x_w), y_w, m_w), seq_logp(policy(x_l), y_l, m_l)
with torch.no_grad():                                  # 参考模型冻结，也可以离线预先算好存下来
    ref_w, ref_l = seq_logp(ref(x_w), y_w, m_w), seq_logp(ref(x_l), y_l, m_l)

r_w = beta * (pi_w - ref_w)                            # chosen 隐式奖励
r_l = beta * (pi_l - ref_l)                            # rejected 隐式奖励
loss = -F.logsigmoid(r_w - r_l).mean()

# 监控指标（TRL 里叫 rewards/chosen、rewards/rejected、rewards/margins、rewards/accuracies）
margin = (r_w - r_l).detach()
acc = (margin > 0).float().mean()

用 F.logsigmoid 而不是 torch.log(torch.sigmoid(...))，后者在 margin 很负时 sigmoid 下溢成 0，log 得到负无穷。除了奖励类指标，还要看 logps/chosen：如果它一路下降，就是下面说的似然位移。

进阶

常见问题与变体

chosen 的概率也在下降 似然位移

DPO 只约束 margin r^w−r^l\hat r_w-\hat r_lr^w​−r^l​ 变大，不约束 r^w\hat r_wr^w​ 本身变大。实际训练中常见两个对数比一起下降，只是 rejected 降得更快，概率质量流向了数据里没有的回答。表现为 logps/chosen 持续下降，生成变长、变怪。常见做法是在 chosen 上加一项 SFT 的 NLL 损失（RPO；Llama 3 的 DPO 也加了这一项）。

离线数据和策略分布不匹配 off-policy

偏好对通常由别的模型生成，和当前策略的分布差得远时，DPO 是在优化策略几乎不会生成的回答。缓解：先在 chosen 上做 SFT 再 DPO；或者用当前策略采样、再打分构造偏好对，迭代地做（online / iterative DPO）。

偏向长回答 长度偏差

序列 log 概率是求和，长回答的对数比绝对值更容易做大；而偏好数据里 chosen 往往又更长。结果是模型越训越啰嗦。SimPO 用长度归一化的平均 log 概率，R-DPO 显式加长度正则。

过拟合偏好 IPO、cDPO

偏好是确定性的（标注总说 ywy_wyw​ 更好）时，最优解会把 margin 推到无穷，KL 约束失效。IPO 把损失换成平方形式，让 margin 回归到一个有限目标；cDPO 用标签平滑应对噪声标签。

高频追问

DPO 是怎么从 RLHF 推出来的？Z(x)Z(x)Z(x) 为什么能消掉？

RLHF 目标是最大化 E[r]−β DKL(π ∥ πref)\mathbb{E}[r]-\beta\,\mathbb{D}_{\text{KL}}(\pi\,\|\,\pi_{\text{ref}})E[r]−βDKL​(π∥πref​)，它的最优解是 π∗∝πrefexp⁡(r/β)\pi^*\propto\pi_{\text{ref}}\exp(r/\beta)π∗∝πref​exp(r/β)。反解得到 r=βlog⁡π∗πref+βlog⁡Z(x)r=\beta\log\frac{\pi^*}{\pi_{\text{ref}}}+\beta\log Z(x)r=βlogπref​π∗​+βlogZ(x)。

偏好用 Bradley-Terry 建模，只依赖两个回答的奖励差。Z(x)Z(x)Z(x) 只和 prompt 有关，两个回答相减时正好抵消。用 πθ\pi_\thetaπθ​ 代替 π∗\pi^*π∗，对偏好数据做最大似然，就是 −log⁡σ(r^w−r^l)-\log\sigma(\hat r_w-\hat r_l)−logσ(r^w​−r^l​)。

β\betaβ 有什么作用？调大调小会怎样？

β\betaβ 来自 RLHF 目标里的 KL 系数，表示多大程度上要贴近参考模型。在损失里它是隐式奖励的温度。

β\betaβ 大：要达到同样的 margin，对数比只需要变一点点，策略离参考模型近，更保守。β\betaβ 小：对数比要变很多才能把损失降下来，策略偏离更大，更激进，也更容易过拟合和似然位移。常用 0.1 左右，常见范围 0.01 到 0.5。

为什么需要参考模型？去掉会怎样？

推导里奖励就是相对参考模型定义的，参考模型同时承担 KL 约束的作用。去掉后，损失只看 log⁡πθ(yw)−log⁡πθ(yl)\log\pi_\theta(y_w)-\log\pi_\theta(y_l)logπθ​(yw​)−logπθ​(yl​)，没有任何东西把策略拉住，模型会不断把 rejected 的概率压向 0，语言能力退化。

SimPO 能去掉参考模型，是因为它改用长度归一化的平均 log 概率，并加了目标间隔 γ\gammaγ，相当于换了一个奖励定义，不再是 DPO 推导出来的那个。

序列 log 概率为什么是求和不是平均？

推导里的 π(y∣x)\pi(y\mid x)π(y∣x) 是整句的概率，自回归模型下等于各 token 条件概率的乘积，取对数就是求和。所以原版 DPO 必须求和。

代价是长度偏差：长回答的对数比更容易做大，模型会越训越长。SimPO 改成平均是为了消除这个偏差，但那已经偏离了原始推导。

训练中 chosen 的 log 概率也在下降，正常吗？

很常见，叫似然位移（likelihood displacement）。DPO 只要求 r^w−r^l\hat r_w-\hat r_lr^w​−r^l​ 变大，两边一起下降、rejected 降得更快，损失也会下降。chosen 和 rejected 往往很相似，压低 rejected 的梯度也会连带压低 chosen。

少量下降问题不大，持续大幅下降说明概率质量流向了数据外的回答，生成质量会变差。解决：在 chosen 上加 SFT 损失（RPO），增大 β\betaβ，或者用 DPOP 这类显式惩罚 chosen 概率下降的变体。

DPO 是 on-policy 还是 off-policy？有什么影响？

原版是离线、off-policy 的：偏好对是事先收集好的，训练时不从当前策略采样。好处是简单、便宜、稳定；坏处是不能探索，数据分布和策略分布差得远时效果打折扣。

改进方向是 online / iterative DPO：每轮用当前策略生成多个回答，用奖励模型或规则打分，选出最好和最差组成新的偏好对，再训一轮。

DPO 的梯度有什么直觉？

梯度是 −β σ(r^l−r^w)(∇log⁡πθ(yw)−∇log⁡πθ(yl))-\beta\,\sigma(\hat r_l-\hat r_w)\big(\nabla\log\pi_\theta(y_w)-\nabla\log\pi_\theta(y_l)\big)−βσ(r^l​−r^w​)(∇logπθ​(yw​)−∇logπθ​(yl​))：推高 chosen、压低 rejected，权重 σ(r^l−r^w)\sigma(\hat r_l-\hat r_w)σ(r^l​−r^w​) 由隐式奖励模型判断“我排错了多少”决定。

排错时权重接近 1，排对且差距大时接近 0，相当于自动聚焦难例。把这个权重去掉，模型会无限制地压低 rejected，很快退化。

训练时要看哪些指标？

损失、r^w\hat r_wr^w​ 和 r^l\hat r_lr^l​ 的均值、margin、准确率（r^w>r^l\hat r_w>\hat r_lr^w​>r^l​ 的比例），以及 chosen 和 rejected 的 log 概率。

准确率很快接近 1、margin 一路暴涨，通常是过拟合或数据太简单；r^w\hat r_wr^w​ 变负、chosen 的 log 概率持续下降，是似然位移。最终还是要看生成质量和下游评测，损失低不代表模型更好。

偏好标签有噪声怎么办？

cDPO 假设每个标签以概率 ε\varepsilonε 标反，损失变成 −(1−ε)log⁡σ(z)−εlog⁡σ(−z)-(1-\varepsilon)\log\sigma(z)-\varepsilon\log\sigma(-z)−(1−ε)logσ(z)−εlogσ(−z)，即标签平滑，margin 不会被推到无穷。IPO 用平方损失给 margin 一个有限目标，也有类似效果。数据层面可以多人标注取一致、过滤低置信度的对。

DPO 能用来训练数学推理吗？和 GRPO 比呢？

能：对同一道题采样多个解答，用规则判对错，正确的当 chosen、错误的当 rejected，迭代地做 DPO。但它只看成对的相对好坏，不在线探索，效果通常不如 GRPO 这类在线 RL。推理任务的奖励可验证，在线采样的收益更大，所以 R1 之后主流用 GRPO 一类方法；DPO 更多用在风格、安全、对话偏好这类难以写成规则的对齐上。

2 分钟口述

答题模板

  1. 一句话定位。DPO 不训奖励模型、不做 RL 采样，直接用偏好对做监督学习，等价于优化带 KL 约束的 RLHF 目标。
  2. 讲推导。RLHF 目标的最优策略 π∗∝πrefexp⁡(r/β)\pi^*\propto\pi_{\text{ref}}\exp(r/\beta)π∗∝πref​exp(r/β)，反解出 r=βlog⁡π∗πref+βlog⁡Zr=\beta\log\frac{\pi^*}{\pi_{\text{ref}}}+\beta\log Zr=βlogπref​π∗​+βlogZ，代入 Bradley-Terry 后 ZZZ 消掉，得到 −log⁡σ(r^w−r^l)-\log\sigma(\hat r_w-\hat r_l)−logσ(r^w​−r^l​)。
  3. 讲怎么算。序列 log 概率 = 回答 token 的 log 概率求和；策略和冻结的参考模型各前向两次；隐式奖励 r^=βlog⁡πθπref\hat r=\beta\log\frac{\pi_\theta}{\pi_{\text{ref}}}r^=βlogπref​πθ​​。
  4. 讲梯度。chosen 每个 token 推高、rejected 每个 token 压低，系数 β σ(r^l−r^w)\beta\,\sigma(\hat r_l-\hat r_w)βσ(r^l​−r^w​)，排错时大、排对时小；公共前缀抵消。
  5. 讲问题和改进。似然位移（加 NLL）、off-policy（先 SFT、迭代 DPO）、长度偏差（SimPO）、过拟合（IPO、cDPO）。最后和 PPO、GRPO 对比适用场景。

常见失分点：说 DPO 不需要参考模型（原版需要）；把序列 log 概率说成 token 平均（原版是求和）；说损失下降就代表 chosen 概率上升（可能两个都在降）；说 β\betaβ 越大越激进（反了，越大越保守）；说 DPO 没有 KL 约束（隐含在推导里）。
