  • 方向：由 A^i\hat{A}_iA^i​ 的符号决定，整个回答一致，好回答的每个 token 都被推高，坏回答的都被压低。

  • 开关：比值越过裁剪边界、且在“占便宜”的方向上，这个 token 的梯度直接为 0。

信用分配靠什么 常被追问

结果监督下，GRPO 本身不区分哪个 token 立了功：一道题做对了，连同废话 token 一起被奖励。区分来自统计：同一个问题采样 GGG 次，关键步骤在对的回答里反复出现、在错的回答里少出现，平均下来它被推高得更多。这也是 GGG 要取得比较大的原因。

想要真正逐 token 不同的优势，需要过程奖励（PRM），或者 PPO 的价值模型。

一个容易答错的点：如果每批数据只做一次梯度更新（完全 on-policy），那么 πθ\pi_\thetaπθ​ 数值上就等于 πθold\pi_{\theta_{\text{old}}}πθold​​，比值恒为 1，裁剪永远不会触发。但梯度不为 0，因为 ∇θri,t=∇θlog⁡πθ(oi,t)\nabla_\theta r_{i,t}=\nabla_\theta\log\pi_\theta(o_{i,t})∇θ​ri,t​=∇θ​logπθ​(oi,t​)，此时 GRPO 退化成带组内 baseline 的 REINFORCE。裁剪只有在同一批数据上做多步更新（μ>1\mu>1μ>1）时才起作用。

手撕

代码：张量形状一步步对上

# B 个问题 × G 个回答，展平成 N = B*G 条；T = 回答的最大长度
# logits: [N, T, V]（只取回答部分，已错位对齐：位置 t 的 logits 预测第 t 个回答 token）
# ids:    [N, T]   回答 token；mask: [N, T]，回答内为 1，padding 为 0
# rewards:[N]      每个回答一个标量

# ① 序列级：组内标准化得到优势
r = rewards.view(B, G)
adv = (r - r.mean(dim=1, keepdim=True)) / (r.std(dim=1, keepdim=True) + 1e-4)
adv = adv.view(N, 1)                                  # [N, 1]，下面广播到 T 个 token

# ② token 级：取出每个位置上“实际生成的那个 token”的 log 概率
logp = torch.gather(logits.log_softmax(-1), 2, ids.unsqueeze(-1)).squeeze(-1)   # [N, T]
ratio = torch.exp(logp - old_logp)                    # old_logp 采样时就存好，不带梯度

# ③ 裁剪 + 取 min，逐 token
surr1 = ratio * adv
surr2 = torch.clamp(ratio, 1 - eps, 1 + eps) * adv
obj = torch.min(surr1, surr2)                         # [N, T]

# ④ KL（k3），逐 token
d = ref_logp - logp
kl = torch.exp(d) - d - 1                             # [N, T]，恒 ≥ 0

per_tok = -(obj - beta * kl)                          # 取负号变成 loss

# ⑤ 聚合：GRPO 原版 = 先句内平均，再对所有回答平均
loss = ((per_tok * mask).sum(1) / mask.sum(1)).mean()
# DAPO（token 级平均）：loss = (per_tok * mask).sum() / mask.sum()
# Dr. GRPO：adv 不除 std；loss = (per_tok * mask).sum() / (N * L_max)

mask 很关键：prompt 部分和 padding 部分都不能算进 loss；logits 和 ids 要错开一位（第 ttt 个位置的输出预测第 t+1t+1t+1 个 token）。old_logp 和 ref_logp 都是在采样之后、更新之前用 no_grad 算好的。

同一个问题采样 GGG 个回答，各自得到奖励 rir_iri​，A^i=ri−mean(r)std(r)\hat{A}_i=\dfrac{r_i-\mathrm{mean}(r)}{\mathrm{std}(r)}A^i​=std(r)ri​−mean(r)​，一个回答一个数，复制给这个回答的所有 token。

critic 的作用是提供 baseline 来降低方差。GRPO 用同一问题的组平均奖励当 baseline，这本身就是对“这道题期望得多少分”的蒙特卡洛估计，所以不需要另外训练一个和策略差不多大的价值模型，省掉一份显存和训练。LLM 的奖励通常只在句末给一次，价值模型逐 token 估计 V(st)V(s_t)V(st​) 本来就很难训准，这也是 GRPO 在推理任务上好用的原因。

一个回答只有一个奖励，怎么作用到每个 token？

优势是序列级的，原样复制到每个 token。之后每个 token 独立计算：自己的概率比 πθ/πθold\pi_\theta/\pi_{\theta_{\text{old}}}πθ​/πθold​​、自己的裁剪、自己的 KL，然后对 log⁡πθ(oi,t)\log\pi_\theta(o_{i,t})logπθ​(oi,t​) 求梯度。所以方向全句一致，但大小和是否被截断是逐 token 不同的。

最后先乘 1∣oi∣\frac{1}{|o_i|}∣oi​∣1​ 做句内平均，再对 GGG 个回答平均。梯度可以写成 ∑tA^i∣oi∣ ri,t ∇θlog⁡πθ(oi,t)\sum_t \frac{\hat{A}_i}{|o_i|}\, r_{i,t}\,\nabla_\theta\log\pi_\theta(o_{i,t})∑t​∣oi​∣A^i​​ri,t​∇θ​logπθ​(oi,t​)。

裁剪是按句子还是按 token？取 min 是什么意思？

按 token。每个 token 的比值单独和 [1−ϵ, 1+ϵ][1-\epsilon,\ 1+\epsilon][1−ϵ, 1+ϵ] 比较。

取 min 是悲观下界：A^>0\hat{A}>0A^>0 时只在 ri,t>1+ϵr_{i,t}>1+\epsilonri,t​>1+ϵ 时截断（已经涨够了），ri,t<1−ϵr_{i,t}<1-\epsilonri,t​<1−ϵ 时不管（往回拉是应该的）；A^<0\hat{A}<0A^<0 时反过来，只在 ri,t<1−ϵr_{i,t}<1-\epsilonri,t​<1−ϵ 时截断。截断的效果是这个 token 的梯度为 0，不是把梯度缩小。

KL 为什么放在 loss 里而不是奖励里？为什么用 k3？

PPO 把每个 token 的 KL 惩罚扣进奖励，再通过 GAE 混进优势。GRPO 的优势是组内标准化的，如果把 KL 混进奖励，会干扰标准化，也让优势不再是单纯的“这个回答好不好”。所以 GRPO 直接把 KL 作为正则项加在 loss 上。

k3 是 πrefπθ−log⁡πrefπθ−1\dfrac{\pi_{\text{ref}}}{\pi_\theta}-\log\dfrac{\pi_{\text{ref}}}{\pi_\theta}-1πθ​πref​​−logπθ​πref​​−1，只用采样 token 的两个 log 概率就能算，是 KL 的无偏估计，而且恒 ≥0\ge 0≥0，方差也比直接用 log 比值（k1）小。

一组回答全对或全错会怎样？

奖励全相同，ri−meanr_i-\mathrm{mean}ri​−mean 全为 0，优势全为 0，这一组除了 KL 之外没有任何梯度（std=0\mathrm{std}=0std=0，靠分母里的 eps 防止除零）。这些样本白白浪费了算力。

DAPO 的动态采样就是持续采样，把这种组过滤掉，直到 batch 里填满有区分度的组。也可以在数据层面剔除太简单或太难的题。

GGG 取多大？太小或太大有什么问题？

GGG 太小，组均值和 std\mathrm{std}std 估计不准，优势噪声大，也更容易出现全对或全错的组。GGG 太大，每个问题的采样成本线性增加。DeepSeekMath 用 G=64G=64G=64，开源复现里常见 8 到 16。

GRPO 的长度偏差是什么？怎么解决？

原版先乘 1∣oi∣\frac{1}{|o_i|}∣oi​∣1​，每个回答的总推力相同。分摊到 token 上，长的错误回答每个 token 罚得少，短的正确回答每个 token 奖得多，于是错误回答越写越长。

DAPO 改成所有 token 一起平均，每个 token 权重一样；Dr. GRPO 改成除以固定常数，并去掉除以 std\mathrm{std}std 带来的难度偏差。

奖励怎么设计？会不会被 hack？

推理类任务一般用规则奖励：答案是否正确（数学比对最终答案，代码跑单元测试），加上格式奖励（比如思考过程必须放在指定标签里）。DeepSeek-R1-Zero 就是这样，没有用神经网络奖励模型，就是为了避免 reward hacking。

开放式任务只能用奖励模型，这时容易被 hack，需要 KL 约束、奖励模型集成、定期更新奖励模型等手段。

2 分钟口述

答题模板

  1. 一句话定位。GRPO 是 PPO 的简化版：去掉 critic，用同一问题多个回答的组内平均奖励当 baseline。
  2. 讲序列级。每个问题采样 GGG 个回答，规则或奖励模型打分，A^i=ri−meanstd\hat{A}_i=\dfrac{r_i-\mathrm{mean}}{\mathrm{std}}A^i​=stdri​−mean​，一个回答一个优势。
  3. 讲逐 token。A^i\hat{A}_iA^i​ 复制给回答的每个 token；每个 token 单独算 πθ/πθold\pi_\theta/\pi_{\theta_{\text{old}}}πθ​/πθold​​ 的比值、做 clip 取 min、减 β DKL\beta\,\mathbb{D}_{\text{KL}}βDKL​（k3，对参考模型）。同一回答方向一致，是否被截断逐 token 不同。
  4. 讲聚合和梯度。先句内平均再组平均，梯度是 ∑tA^i∣oi∣ ri,t ∇θlog⁡πθ(oi,t)\sum_t \frac{\hat{A}_i}{|o_i|}\, r_{i,t}\,\nabla_\theta\log\pi_\theta(o_{i,t})∑t​∣oi​∣A^i​​ri,t​∇θ​logπθ​(oi,t​)。单步 on-policy 时退化为带 baseline 的 REINFORCE。
  5. 讲问题和改进。信用分配靠多次采样的统计；全对全错的组没有梯度；1∣oi∣\frac{1}{|o_i|}∣oi​∣1​ 带来长度偏差。DAPO 用 token 级平均、Clip-Higher、动态采样；Dr. GRPO 去掉 1∣oi∣\frac{1}{|o_i|}∣oi​∣1​ 和除以 std\mathrm{std}std。

常见失分点：说 GRPO 的优势是逐 token 不同的（结果监督下全句相同）；说裁剪按句子做（按 token）；说比值为 1 时没有梯度（有，就是 ∇θlog⁡πθ\nabla_\theta\log\pi_\theta∇θ​logπθ​）；把 KL 说成扣在奖励里（GRPO 放在 loss 里）；说截断是把梯度缩小（是直接为 0）。
