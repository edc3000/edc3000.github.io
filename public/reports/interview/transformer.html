先给结论

30 秒背诵版

每层 = 注意力（token 之间交换信息）+ FFN（每个 token 自己加工），外面包残差和 Norm

注意力：Attention(Q,K,V)=softmax(QK⊤dk+M)V\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\big(\frac{QK^\top}{\sqrt{d_k}}+M\big)VAttention(Q,K,V)=softmax(dk​​QK⊤​+M)V。每个 token 用自己的 query 和所有 key 算相似度，softmax 成权重，对 value 加权求和。除以 dk\sqrt{d_k}dk​​ 是因为点积的方差随维度线性增长，不缩放 softmax 会饱和、梯度消失。MMM 是 mask，屏蔽的位置加 −∞-\infty−∞。

多头：把 ddd 维切成 hhh 个头，各自做注意力再拼接，不同的头关注不同的关系，总计算量和单头一样。MQA、GQA 让多个 query 头共享 K、V，用来缩小 KV cache。

其余部分：FFN 先升维再降维（标准 4 倍，SwiGLU 约 83\frac{8}{3}38​ 倍），参数量占大头；残差 + LayerNorm 保证深层能训。原版是 encoder-decoder + Post-Norm，现在的大模型是 decoder-only + Pre-RMSNorm + RoPE + SwiGLU + GQA。

数量级：每层参数约 12d212d^212d2，总参数约 12Ld2+Vd12Ld^2+Vd12Ld2+Vd；注意力计算 O(n2d)O(n^2d)O(n2d)，FFN O(nd2)O(nd^2)O(nd2)；训练每个 token 约 6N6N6N FLOPs，推理约 2N2N2N。

mask：注意力 mask 在 softmax 前加 −∞-\infty−∞，决定谁能看谁（padding、causal、prefix LM、序列打包的 document mask、滑动窗口）；loss mask 是另一回事，决定哪些位置算损失，比如 SFT 只训回答部分。批量生成用左填充，屏蔽值用该精度的最小值防止整行 NaN。

核心

缩放点积注意力

输入 X∈Rn×dX\in\mathbb{R}^{n\times d}X∈Rn×d（nnn 个 token），先投影出三组向量：

Q=XWQ,K=XWK,V=XWV,Attention(Q,K,V)=softmax(QK⊤dk+M)VQ=XW^Q,\quad K=XW^K,\quad V=XW^V,\qquad \mathrm{Attention}(Q,K,V)=\mathrm{softmax}\Big(\frac{QK^\top}{\sqrt{d_k}}+M\Big)VQ=XWQ,K=XWK,V=XWV,Attention(Q,K,V)=softmax(dk​​QK⊤​+M)V
① 打分

QK⊤QK^\topQK⊤ 是 n×nn\times nn×n 的矩阵，第 iii 行第 jjj 列是第 iii 个 token 的 query 和第 jjj 个 token 的 key 的点积，表示“iii 有多想看 jjj”。

② 缩放 + mask

除以 dk\sqrt{d_k}dk​​，再加 mask MMM：允许看的位置加 0，不允许的加 −∞-\infty−∞，softmax 后这些位置的权重正好是 0。

③ 归一化

对每一行（也就是 key 的维度）做 softmax，得到第 iii 个 token 分给各个位置的注意力权重，和为 1。

④ 加权求和

权重矩阵乘 VVV，第 iii 个 token 的输出是所有 value 的加权平均。Q、K 决定“看谁”，V 决定“拿到什么”。

为什么除以 dk\sqrt{d_k}dk​​ 必考

设 qqq、kkk 的各分量独立、均值 0、方差 1，则：

Var(q⋅k)=∑i=1dkVar(qiki)=dk\mathrm{Var}(q\cdot k)=\sum_{i=1}^{d_k}\mathrm{Var}(q_ik_i)=d_kVar(q⋅k)=i=1∑dk​​Var(qi​ki​)=dk​

点积的标准差是 dk\sqrt{d_k}dk​​，dk=128d_k=128dk​=128 时约 11。分数差距这么大，softmax 几乎变成 one-hot，雅可比矩阵 diag(p)−pp⊤\mathrm{diag}(p)-pp^\topdiag(p)−pp⊤ 接近 0，梯度消失。除以 dk\sqrt{d_k}dk​​ 把方差拉回 1。

两种 mask 常考

  • padding mask：batch 里句子长短不一，补齐的 padding 位置不能被别人看到，按 key 的位置屏蔽。
  • causal mask：decoder 里第 iii 个 token 只能看 j≤ij\le ij≤i，屏蔽上三角。这样训练时整句可以并行算，又不会偷看答案。
  • 用 −∞-\infty−∞ 而不是乘 0：mask 要在 softmax 之前加，乘 0 会让分数变成 0，e0=1e^0=1e0=1 仍然分到权重。实现里常用一个很大的负数，并注意半精度下别溢出。
  • 更多形状（prefix LM、序列打包、滑动窗口）、loss mask 和工程上的坑，见下面的 Mask 全解。

左填充还是右填充 高频

训练用右填充即可，padding 在末尾，配合 loss mask 不影响结果。

decoder-only 批量生成必须左填充：生成是在每条序列的最后一个 token 后面接着写，右填充时短句的“最后一个”是 padding，新 token 会接在 padding 后面。左填充让所有序列的真实末尾对齐在最右边。

左填充时位置编号要从第一个真实 token 开始算，常用 position_ids=cumsum(mask)−1\text{position\_ids}=\mathrm{cumsum}(\text{mask})-1position_ids=cumsum(mask)−1，否则 RoPE 的位置会整体偏移。

整行被屏蔽会出 NaN 工程坑

causal + 左填充时，最前面的 padding query 能看的位置全被屏蔽，一整行都是 −∞-\infty−∞，softmax 变成 0/0=NaN0/0=\text{NaN}0/0=NaN。这些位置的输出虽然用不到，NaN 却可能经过后续计算或梯度扩散开。

做法：用该精度的最小值（如 torch.finfo(dtype).min）代替 −∞-\infty−∞，整行屏蔽时 softmax 退化成均匀分布，不会 NaN；或者让 padding 位置至少能看到自己。HuggingFace 就是用最小值。

decode 阶段还要 causal mask 吗

prefill 一次处理整段 prompt，需要 causal mask。decode 每步只有 1 个新 query，它要看的缓存全是它之前的 token，天然满足 j≤ij\le ij≤i，不需要 causal mask，只需保留 padding mask（左填充的部分）。

投机解码一次验证多个草稿 token 时，又要在这几个 token 之间加 causal mask；Medusa、EAGLE 这类树形草稿要用树形 mask，每个候选只能看到自己那条路径。

序列打包要加 document mask

为了不浪费 padding，训练时常把多条短样本拼成一条长序列。只用普通 causal mask 的话，后一条样本能看到前一条的内容，相互污染。LLaMA 3 预训练就用了 document mask 防止跨文档注意力。

实现上一般不建 n×nn\times nn×n 矩阵，而是用 FlashAttention 的变长接口，传入每条样本的起止位置（cu_seqlens），每条样本的位置编号也要从 0 重新开始。

SFT 的 loss mask

对话数据里 system、user 的部分只是条件，不应该训练模型去生成它们。把这些位置的 label 设成 −100-100−100，交叉熵会忽略它们，只在 assistant 回答上算损失；多轮对话要把每一轮的 user 部分都屏蔽掉。注意力 mask 仍然是普通的 causal，回答部分照常能看到前面的 prompt。

损失按有效 token 数平均。GRPO、DPO 代码里的 mask 也是这个意思，只统计回答部分。

不同 API 的约定相反 手撕易错

  • HuggingFace 的 attention_mask：1 表示真实 token，0 表示 padding。
  • PyTorch F.scaled_dot_product_attention 的布尔 attn_mask：True 表示可以看。
  • PyTorch nn.MultiheadAttention 的布尔 key_padding_mask、attn_mask：True 表示屏蔽。

同一个框架里两种语义都有，传错方向模型照样能跑，只是结果全错，排查时要先确认这一点。

def build_mask(attention_mask, causal=True, dtype=torch.float32):
    # attention_mask: [B, n]，HF 约定 1 = 真实 token，0 = padding
    B, n = attention_mask.shape
    keep = attention_mask[:, None, None, :].bool()                 # [B, 1, 1, n]：按 key 屏蔽 padding
    if causal:
        tril = torch.ones(n, n, dtype=torch.bool, device=attention_mask.device).tril()
        keep = keep & tril                                         # [B, 1, n, n]
    bias = torch.zeros(keep.shape, dtype=dtype, device=attention_mask.device)
    return bias.masked_fill(~keep, torch.finfo(dtype).min)        # 用最小值而不是 -inf，避免整行 NaN

position_ids = attention_mask.long().cumsum(-1) - 1

为什么要多头

一个头只能产生一种注意力分布。多头让不同的头在不同的子空间里关注不同的关系，比如有的头看前一个词，有的看句法上的主语，有的看相同的实体。每个头维度变小，总计算量和一个 ddd 维的单头基本相同。

MHA、MQA、GQA 推理优化

推理时 K、V 要缓存，大小和 KV 头数成正比。MQA：所有 query 头共享一组 K、V，KV cache 缩小 hhh 倍，但效果有损。GQA：query 头分成 ggg 组，每组共享一组 K、V，KV cache 缩小 h/gh/gh/g 倍，效果接近 MHA。LLaMA 2 70B、LLaMA 3、Qwen 系列都用 GQA。

FFN、残差与 Norm

FFN：每个 token 自己加工 参数大头

残差和 Norm：让深层能训 稳定性

残差 x+F(x)x+F(x)x+F(x) 给梯度一条恒等的通路，几十上百层也不会梯度消失；同时每层只需要学“增量”。

Norm 控制每层输入的尺度。原版是 Post-LN（先加残差再归一化），深了需要 warmup；现在用 Pre-Norm（子层前归一化），并把 LayerNorm 换成 RMSNorm。细节见 Norm：从 BatchNorm 到 RMSNorm。

分类

三种架构：encoder-only、decoder-only、encoder-decoder

架构注意力训练目标擅长代表
encoder-only双向，每个 token 看整句MLM：遮住 15% 的词让模型猜理解：分类、抽取、向量检索BERT、RoBERTa
decoder-only单向，causal mask下一个 token 预测生成，也能通过提示做理解GPT 系列、LLaMA、Qwen、DeepSeek
encoder-decoder编码器双向；解码器单向 + 交叉注意力输入到输出的条件生成（如 span corruption）翻译、摘要这类输入输出分明的任务原版 Transformer、T5、BART

交叉注意力里，QQQ 来自解码器当前层，KKK、VVV 来自编码器最后一层的输出，解码器借此“查”源句子。

为什么现在的大模型几乎都是 decoder-only 高频

  • 训练效率：每个 token 都是一个预测目标，数据利用率高；MLM 只有被遮住的 15% 有监督。
  • 天然会生成：预训练目标和推理时的使用方式一致，零样本、少样本只要写提示词就行。
  • 推理友好：只有一个栈，KV cache 可以一路复用；多轮对话直接接在后面。
  • 规模化验证最充分：GPT-3 之后的 scaling 经验、工程生态都围绕 decoder-only 建立。
  • 一个常见的理论解释：双向注意力矩阵容易退化成低秩，causal 注意力矩阵是下三角、对角线为正，一定满秩，表达能力更强。这是一种观点，不是定论。

计算量

  • 前向每个 token 约 2N2N2N FLOPs（每个参数一次乘一次加）；训练加上反向约 6N6N6N，所以训练总量 ≈6ND\approx6ND≈6ND，DDD 是 token 数。
  • 注意力额外有 QK⊤QK^\topQK⊤ 和乘 VVV 两项，每层每 token 约 4nd4nd4nd，序列很长时才显著。
  • 复杂度：注意力 O(n2d)O(n^2d)O(n2d)，FFN 和投影 O(nd2)O(nd^2)O(nd2)。n<dn<dn<d 时 FFN 和投影占大头，长上下文时注意力占大头。

训练 vs 推理

decoder 在训练和推理时有什么不同

训练：teacher forcing，整句并行

整句一次送进去，causal mask 保证每个位置只看前文，所有位置的“下一个 token”损失一次算完。输入是真实文本右移一位，不依赖模型自己的输出。

推理：自回归，一次一个 token

prefill：把 prompt 一次算完，存下每层的 K、V。decode：每步只算新 token 的 qqq、kkk、vvv，新的 kkk、vvv 追加进缓存，qqq 和全部缓存的 K 做注意力。Q 不需要缓存，因为以前的 query 以后不会再用。decode 阶段受显存带宽限制，这也是投机解码能加速的原因。

手撕

代码：缩放点积注意力和多头注意力

import math, torch, torch.nn as nn, torch.nn.functional as F

def attention(q, k, v, mask=None):                      # q,k,v: [B, h, n, d_h]
    scores = q @ k.transpose(-2, -1) / math.sqrt(q.size(-1))   # [B, h, n, n]
    if mask is not None:
        scores = scores.masked_fill(mask == 0, float("-inf"))  # mask 为 0 的位置屏蔽
    w = F.softmax(scores, dim=-1)                       # 对 key 维度归一化
    return w @ v                                        # [B, h, n, d_h]

class MultiHeadAttention(nn.Module):
    def __init__(self, d, h):
        super().__init__()
        assert d % h == 0
        self.h, self.dh = h, d // h
        self.qkv = nn.Linear(d, 3 * d, bias=False)      # 一次投影出 Q、K、V
        self.o = nn.Linear(d, d, bias=False)

    def forward(self, x, causal=True):                  # x: [B, n, d]
        B, n, d = x.shape
        q, k, v = self.qkv(x).split(d, dim=-1)
        q, k, v = (t.view(B, n, self.h, self.dh).transpose(1, 2) for t in (q, k, v))
        mask = torch.tril(torch.ones(n, n, device=x.device)) if causal else None
        out = attention(q, k, v, mask)                  # [B, h, n, d_h]
        out = out.transpose(1, 2).contiguous().view(B, n, d)
        return self.o(out)

手撕常见追问：transpose 之后要 contiguous() 才能 view；softmax 的维度是最后一维（key）；padding mask 要广播成 [B,1,1,n][B,1,1,n][B,1,1,n]；实际工程直接用 F.scaled_dot_product_attention，会自动走 FlashAttention，不显式存 n×nn\times nn×n 的分数矩阵。

自测

高频追问

注意力为什么要除以 dk\sqrt{d_k}dk​​？

假设 qqq、kkk 各分量独立、均值 0、方差 1，点积 q⋅kq\cdot kq⋅k 的方差是 dkd_kdk​。dkd_kdk​ 大时分数差距很大，softmax 会接近 one-hot，雅可比 diag(p)−pp⊤\mathrm{diag}(p)-pp^\topdiag(p)−pp⊤ 接近 0，梯度消失、训练不稳。除以 dk\sqrt{d_k}dk​​ 让方差回到 1。

追问“为什么不除以 dkd_kdk​”：那样方差变成 1/dk1/d_k1/dk​，分数太平，softmax 接近均匀分布，注意力失去区分度。

为什么用多头？头数越多越好吗？

多头让模型在不同子空间里同时关注不同类型的关系，表达能力更强，总计算量和单头差不多。

不是越多越好：ddd 固定时头越多，每个头的维度 dhd_hdh​ 越小，单个头的表达能力下降，而且研究发现很多头是冗余的，剪掉影响不大。实践中 dhd_hdh​ 一般取 64 或 128。

Q 和 K 为什么要用不同的投影矩阵？

如果 WQ=WKW^Q=W^KWQ=WK，分数矩阵 XWW⊤X⊤XWW^\top X^\topXWW⊤X⊤ 是对称的，“iii 看 jjj”和“jjj 看 iii”一样强，而语言里的关系是不对称的（形容词看名词，不代表名词同样看形容词）。而且每个 token 和自己的点积往往最大，注意力会集中在自己身上。不同的投影让打分可以不对称。

自注意力的复杂度是多少？长序列的瓶颈在哪？

时间 O(n2d)O(n^2d)O(n2d)，显存上要存 n×nn\times nn×n 的分数矩阵，是 O(n2)O(n^2)O(n2)。长序列时这是主要瓶颈。

解决方向：FlashAttention 分块计算，不把 n×nn\times nn×n 矩阵写回显存，显存降到 O(n)O(n)O(n)，但计算量不变；稀疏注意力、滑动窗口只算一部分位置；线性注意力把复杂度降到 O(n)O(n)O(n)；推理时的 KV cache 再用 GQA、MLA 压缩。

attention mask 和 loss mask 有什么区别？SFT 时怎么设？

attention mask 作用在 softmax 之前的分数上，决定每个 token 能看哪些 token；loss mask 作用在每个位置的损失上，决定哪些位置参与训练。两者互不影响。

SFT 时注意力仍用普通 causal mask（回答要能看到 prompt），loss mask 把 system、user 部分的 label 设为 −100-100−100，只在 assistant 回答上算交叉熵，按有效 token 数平均；padding 位置两种 mask 都要屏蔽。

decoder-only 模型批量生成为什么要左填充？

生成是在每条序列最后一个 token 后面接着写。右填充时短句的末尾是 padding，新 token 会接在 padding 后面，而且各条序列的“下一个位置”不一致。左填充让所有真实末尾对齐在最右边，每步统一在最后追加。

左填充还要处理两件事：padding mask 屏蔽左边的 padding；位置编号从第一个真实 token 开始算（cumsum(mask)−1\mathrm{cumsum}(\text{mask})-1cumsum(mask)−1），否则 RoPE 的位置整体偏移。训练时用右填充就行。

推理的 decode 阶段还需要 causal mask 吗？

不需要。decode 每步只有一个新 query，KV cache 里全是它之前的 token，天然满足因果关系，只保留 padding mask。prefill 一次处理整段 prompt 时才需要 causal mask；投机解码一次验证多个草稿 token 时，草稿之间也要加 causal（树形草稿用树形 mask）。

序列打包（packing）时 mask 要注意什么？

多条样本拼成一条长序列时，普通 causal mask 会让后面的样本看到前面样本的内容。要用 document mask：只允许同一条样本内部的因果注意力，形状是若干个对角块的下三角。每条样本的位置编号也要从 0 重新开始，loss 在样本边界处不能跨样本预测。实现上用 FlashAttention 的变长接口传 cu_seqlens，不需要真的构造 n×nn\times nn×n 矩阵。

为什么有时加了 mask 会出现 NaN？

某一行的所有位置都被屏蔽（比如 causal + 左填充时最前面的 padding query），这一行全是 −∞-\infty−∞，softmax 是 0/00/00/0，得到 NaN，还可能通过梯度扩散。解决：屏蔽值用该精度能表示的最小值而不是 −∞-\infty−∞，或者让每个位置至少能看到自己；FP16 下尤其要注意，−109-10^9−109 这类常数会溢出。

mask 是怎么实现的？为什么用 −∞-\infty−∞？

在 softmax 之前给分数加 mask：允许的位置加 0，屏蔽的位置加 −∞-\infty−∞（或一个很大的负数），softmax 后权重为 0。causal mask 是下三角矩阵，padding mask 按 key 的位置屏蔽，两者可以相加组合。

不能在 softmax 后乘 0 再不重新归一化，也不能把分数设成 0：e0=1e^0=1e0=1，屏蔽的位置仍会分到权重。半精度下要用该精度能表示的最小值，避免 −∞-\infty−∞ 和 NaN 问题（整行都被屏蔽时 softmax 会得到 NaN）。

encoder 和 decoder 有什么区别？交叉注意力的 Q、K、V 来自哪？

encoder 用双向注意力，每个 token 看整句，适合理解；decoder 用 causal mask，只看前文，适合生成。原版 decoder 每层多一个交叉注意力：QQQ 来自 decoder 当前层的输出，KKK、VVV 来自 encoder 最后一层的输出。

为什么现在的大模型几乎都是 decoder-only？

训练时每个 token 都有监督，数据效率高；预训练目标和生成方式一致，零样本、少样本只需要提示；只有一个栈，KV cache 复用简单，工程实现和推理优化最成熟；scaling 的经验也都建立在它上面。

还有一种理论解释：causal 注意力矩阵是下三角、对角线为正，必然满秩；双向注意力矩阵更容易低秩，表达能力受限。这是一个观点，回答时说明即可。

FFN 有什么作用？SwiGLU 的 dffd_{ff}dff​ 为什么是 83d\frac{8}{3}d38​d？

注意力负责 token 之间交换信息，FFN 对每个 token 独立做非线性变换，参数量约占每层的 2/3，常被认为存储了大量知识。先升维再降维，提供足够的非线性容量。

SwiGLU 有 gate、up、down 三个矩阵，标准 FFN 只有两个。要让参数量相同：3 d dff=2 d⋅4d3\,d\,d_{ff}=2\,d\cdot4d3ddff​=2d⋅4d，得到 dff=83dd_{ff}=\frac{8}{3}ddff​=38​d，再取整到方便计算的倍数（LLaMA-7B 是 11008）。

一个 Transformer 的参数量怎么算？

每层：注意力 4d24d^24d2（MHA），标准 FFN 8d28d^28d2，合计约 12d212d^212d2；再乘层数 LLL，加上 embedding VdVdVd（不共享时 LM head 再加 VdVdVd）。用 GQA 时 K、V 投影变成 2 d g dh2\,d\,g\,d_h2dgdh​；SwiGLU 是 3 d dff3\,d\,d_{ff}3ddff​。LLaMA-7B 代入就是 6.74B。

KV cache 是什么？为什么只缓存 K、V 不缓存 Q？

自回归生成时，新 token 要和所有历史 token 做注意力，历史 token 的 K、V 不会变，缓存起来就不用每步重算。每步只算新 token 的 qqq、kkk、vvv，把 kkk、vvv 追加进缓存。

Q 只在当前步用一次：历史 token 的 query 已经完成了它们的注意力计算，后面不会再用到，所以不需要缓存。

MHA、MQA、GQA 有什么区别？

MHA：每个 query 头有自己的 K、V。MQA：所有 query 头共享一组 K、V，KV cache 缩小 hhh 倍，但效果有损、训练不稳。GQA：把 query 头分成 ggg 组，组内共享 K、V，是两者的折中，KV cache 缩小 h/gh/gh/g 倍，效果接近 MHA。还可以把训好的 MHA 模型的 KV 头做平均池化，转成 GQA 后再少量训练。

残差连接和 LayerNorm 起什么作用？

残差提供恒等的梯度通路，让深层网络能训，同时每层只学增量。LayerNorm 把每个 token 的激活拉回稳定的尺度。原版是 Post-LN，现在是 Pre-Norm + RMSNorm，详见 Norm 一文。

2 分钟口述

答题模板

  1. 整体。每层由注意力和 FFN 组成，外面包残差和 Norm；原版是 encoder-decoder，现在的大模型是 decoder-only。
  2. 注意力。softmax(QK⊤/dk+M)V\mathrm{softmax}(QK^\top/\sqrt{d_k}+M)Vsoftmax(QK⊤/dk​​+M)V：打分、缩放、mask、按行 softmax、加权求和；除以 dk\sqrt{d_k}dk​​ 是因为点积方差为 dkd_kdk​，防止 softmax 饱和。
  3. 多头。切成 hhh 个头，各自注意力后拼接再乘 WOW^OWO；GQA 让多个 query 头共享 K、V，缩小 KV cache。
  4. FFN 与稳定性。FFN 升维再降维，参数大头，现在用 SwiGLU；残差 + Pre-RMSNorm 保证深层可训；位置用 RoPE。
  5. 数量级。每层约 12d212d^212d2 参数，LLaMA-7B 可以当场算出 6.74B；注意力 O(n2d)O(n^2d)O(n2d)；训练 6N6N6N、推理 2N2N2N FLOPs/token；KV cache 每 token 2Lgdh2Lgd_h2Lgdh​ 个数。

常见失分点：说除以 dk\sqrt{d_k}dk​​ 是为了“归一化到 0–1”（是控制方差）；softmax 做在 query 维度（是 key 维度）；mask 用乘 0（要在 softmax 前加 −∞-\infty−∞）；说 KV cache 也缓存 Q（不缓存）；说多头增加了很多计算量（总量基本不变）；把 attention mask 和 loss mask 混为一谈；说批量生成用右填充（要左填充）。
