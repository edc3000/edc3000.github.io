从策略梯度推到 PPO

PPO 要解决的问题是：怎样用一批采样数据安全地多更新几步。按下面四步推过来，每一步都在补上一步的缺点。

① 策略梯度：只能用一次

③ TRPO：加一个硬约束

把每次更新限制在信赖域里，理论上能保证策略单调改进。代价是要用共轭梯度和 Fisher 向量积求解，再做线搜索，实现复杂，PPO 论文还指出它和 dropout、策略与价值共享参数这类结构不兼容。

④ PPO：用一阶方法近似信赖域
LCLIP(θ)=Et[min⁡(ρtA^t, clip(ρt,1−ϵ,1+ϵ) A^t)]L^{\text{CLIP}}(\theta)=\mathbb{E}_t\Big[\min\big(\rho_t\hat{A}_t,\ \mathrm{clip}(\rho_t,1-\epsilon,1+\epsilon)\,\hat{A}_t\big)\Big]LCLIP(θ)=Et​[min(ρt​A^t​, clip(ρt​,1−ϵ,1+ϵ)A^t​)]

裁剪不是硬约束 常被追问

裁剪只是让越界的样本不再贡献梯度，不会把比值拉回区间。参数是所有样本共享的，别的样本的梯度照样可能把这个样本的比值推得更远。所以训练时要监控 clipfrac（被裁剪的 token 比例）和近似 KL；多数实现在近似 KL 超过阈值时提前结束这批数据的更新。

结构和初始化

critic 和 actor 结构相同，把输出词表的头换成输出一个标量的线性层，每个位置输出一个 V(st)V(s_t)V(st​)。InstructGPT 和更早的 Learning to Summarize 都用 reward model 初始化 critic：RM 已经会对整条回答打分，离“估计后续能拿多少奖励”最近。InstructGPT 对所有尺寸的策略都用 6B 的 RM 和 6B 的 critic，所以 critic 不一定要和 actor 一样大。

为什么难训 常被追问

  • 奖励只在句末给一次，前面的 token 要靠 critic 自己猜后面能拿多少分，回答越长越难。
  • 状态是任意长度的文本，空间极大；而 critic 每轮只能看到当前策略采样出的少量轨迹。
  • 策略在变，critic 的回归目标也跟着变。critic 不准，GAE 的优势就有偏，策略会朝错误的方向更新。

常见的缓解办法是先只训 critic 若干步（critic warmup），等它稳定了再放开 actor。

手撕

代码：一次 PPO 更新

# B 条回答，T = 回答的最大长度；以下张量都只取回答部分，已错位对齐
# 采样后用 no_grad 算好：old_logp, ref_logp, values: [B, T]；scores: [B]（RM 对整条回答的打分）
# mask: [B, T]，回答内为 1，padding 为 0；last: [B]，每条回答最后一个 token 的下标

# ① 逐 token 奖励：每个 token 扣 KL，最后一个 token 再加 RM 分数
kl = old_logp - ref_logp                              # k1 估计，可正可负
rewards = -beta * kl
rewards[torch.arange(B), last] += scores
rewards, values = rewards * mask, values * mask      # padding 处清零，最后一个 token 的 V(s_{T+1}) 就是 0

# ② GAE：从后往前递推（gamma=1, lam=0.95）
adv = torch.zeros_like(rewards)
gae = 0.0
for t in reversed(range(T)):
    next_v = values[:, t + 1] if t + 1 < T else 0.0
    delta = rewards[:, t] + gamma * next_v - values[:, t]
    gae = delta + gamma * lam * gae
    adv[:, t] = gae
returns = adv + values                                # critic 的回归目标，之后不再变
adv = masked_whiten(adv, mask)                        # 在整个 batch 的有效 token 上标准化

# ③ 同一批数据跑 K 轮，每轮切成小批量
for epoch in range(K):
    for mb in minibatches(B):
        logp = actor_logp(mb)                         # [b, T]，带梯度
        v = critic(mb)                                # [b, T]，带梯度
        ratio = torch.exp(logp - old_logp[mb])
        pg = torch.max(-adv[mb] * ratio,              # max 两个负数 = 对目标取 min 再取负
                       -adv[mb] * torch.clamp(ratio, 1 - eps, 1 + eps))
        v_clip = values[mb] + torch.clamp(v - values[mb], -eps_v, eps_v)
        vf = 0.5 * torch.max((v - returns[mb]) ** 2, (v_clip - returns[mb]) ** 2)
        loss = masked_mean(pg, mask[mb]) + vf_coef * masked_mean(vf, mask[mb])
        loss.backward(); opt.step(); opt.zero_grad() # opt 同时管 actor 和 critic 的参数

容易写错的地方：GAE 必须倒着扫；padding 位置的奖励和价值要清零，否则最后一个 token 会读到 padding 处的 VVV；returns 要在优势标准化之前算；old_logp、values、returns、adv 都是采样后固定的，KKK 轮更新里不能变。

自测

高频追问

PPO 为什么要裁剪？不裁剪会怎样？

为了在同一批数据上安全地多更新几步。重要性采样的替代目标 E[ρtA^t]\mathbb{E}[\rho_t\hat{A}_t]E[ρt​A^t​] 只在新旧策略接近时才可靠（它没修正状态分布）。不加限制地优化它，比值可以无限变大，目标也跟着无限变大，策略会被推到一个替代目标看起来很好、实际很差的地方，训练崩掉。

裁剪把越界部分的收益截掉，相当于用一阶方法近似 TRPO 的信赖域，不用解约束优化。

取 min 是什么意思？哪几种情况梯度为 0？

取 min 得到的是不裁剪目标的下界，是一个悲观估计：只截掉“继续往有利方向走”能多拿的部分，不截“往不利方向走”的部分。

梯度为 0 只有两种情况：A^>0\hat{A}>0A^>0 且 ρt>1+ϵ\rho_t>1+\epsilonρt​>1+ϵ（好动作的概率已经涨够了）；A^<0\hat{A}<0A^<0 且 ρt<1−ϵ\rho_t<1-\epsilonρt​<1−ϵ（坏动作的概率已经降够了）。反方向越界时不裁剪，梯度照常把它拉回来。

PPO 是 on-policy 还是 off-policy？

on-policy。每轮都用当前策略重新采样，数据用完就扔，不像 DQN 那样有经验回放。

但它在一批数据上会做 KKK 轮小批量更新，从第二个小批量开始，数据其实已经是稍微 off-policy 的了。重要性采样比值修正这一点偏差，裁剪保证偏差不会太大。

PPO 和 TRPO 有什么区别？

目标相同：每次更新不要离旧策略太远。TRPO 把 KL 作为硬约束，用共轭梯度、Fisher 向量积和线搜索求解，有单调改进的理论保证，但实现复杂、计算贵。

PPO 用裁剪（或 KL 惩罚）把约束变成目标的一部分，直接用 SGD 或 Adam 优化，能做小批量多轮更新，实现简单、效果相当，所以成了默认选择。代价是没有严格保证，比值仍可能越界。

GAE 里的 γ\gammaγ 和 λ\lambdaλ 分别控制什么？RLHF 里怎么取？

γ\gammaγ 是折扣因子，定义了要优化的目标本身：未来的奖励打多少折。λ\lambdaλ 只影响优势的估计方式：λ=0\lambda=0λ=0 只用一步 TD，方差小、偏差大；λ=1\lambda=1λ=1 用完整回报，偏差小、方差大。

RLHF 里常用 γ=1\gamma=1γ=1、λ=0.95\lambda=0.95λ=0.95。γ=1\gamma=1γ=1 是因为回答长度有限，RM 分数只在末尾给一次，打折会让前面的 token 几乎收不到这个信号。

RLHF 里的奖励是怎么构造的？KL 为什么要逐 token 扣？

每个 token 的奖励是 −β (log⁡πθold(yt)−log⁡πref(yt))-\beta\,(\log\pi_{\theta_{\text{old}}}(y_t)-\log\pi_{\text{ref}}(y_t))−β(logπθold​​(yt​)−logπref​(yt​))，最后一个 token 再加上 RM 对整条回答的分数。

KL 是为了防止策略为了骗 RM 的高分跑得离 SFT 模型太远（reward hacking），同时保持语言流畅。整句的 log 比值本来就是逐 token log 比值之和，拆开扣，每个 token 都有即时信号，GAE 能更准地把“哪个 token 偏离了参考模型”归到具体位置上。

critic 为什么难训？为什么用 RM 初始化？

奖励极其稀疏，只在句末一次；状态是任意长度的文本；策略在变，回归目标也在变。critic 不准，优势就有偏，会直接把策略带偏。

RM 已经学会了给整条回答打分，和“从这里往后能拿多少奖励”最接近，用它初始化比从 SFT 模型初始化收敛快得多。InstructGPT 和 Learning to Summarize 都是这么做的，很多框架还会先单独训 critic 一段时间再放开 actor。

RLHF-PPO 显存里有几个模型？怎么省？

四个：actor 和 critic 要训练，各有梯度和优化器状态；ref 和 RM 只做前向。actor 是 7B 时，光两份 Adam 状态和参数就是一大笔。

省法：critic 和 RM 用比 actor 小的模型（InstructGPT 用 6B 的 critic 配 175B 的策略）；ref 和 RM 卸载到 CPU，或者放到单独的卡上只做推理；用 LoRA 训练时，ref 就是不挂 adapter 的同一个 base 模型；或者干脆换成不需要 critic 的 GRPO、RLOO。

为什么同一批数据要跑多轮？轮数太多会怎样？

采样（生成）是最贵的环节，多跑几轮能提高样本利用率。TRL 默认 4 轮。

轮数太多，策略离采样时的策略越来越远，比值大量越界，clipfrac 和近似 KL 上升，裁剪掉的样本越来越多，有效梯度越来越少，还容易不稳定。所以一般配合近似 KL 阈值提前停止。

每批只更新一步时，比值恒为 1，还有梯度吗？

有。比值数值上是 1，但 ∇θρt=∇θlog⁡πθ(at∣st)\nabla_\theta\rho_t=\nabla_\theta\log\pi_\theta(a_t\mid s_t)∇θ​ρt​=∇θ​logπθ​(at​∣st​)，梯度就是 A^t∇θlog⁡πθ\hat{A}_t\nabla_\theta\log\pi_\thetaA^t​∇θ​logπθ​，等价于 actor-critic 的策略梯度。只是裁剪永远不会触发，PPO 的作用要在多步更新时才体现出来。

优势为什么要标准化？

奖励的尺度会随训练变化，优势的尺度也跟着变，同一个学习率在不同阶段效果差很多。在 batch 内减均值、除标准差，让梯度尺度稳定。减均值还让大约一半的 token 优势为负，起到 baseline 的作用。

注意顺序：critic 的回归目标 R^t\hat{R}_tR^t​ 要用标准化之前的优势算。

PPO 和 GRPO 的本质区别是什么？

都用裁剪目标，区别在 baseline 从哪来。PPO 训练一个 critic 逐 token 估计 V(st)V(s_t)V(st​)，用 GAE 得到逐 token 不同的优势；GRPO 对同一问题采样一组回答，用组内平均奖励当 baseline，全句共享一个优势。

GRPO 省掉了 critic 的显存和训练，也避开了“稀疏奖励下 critic 难训”的问题，代价是每个问题要采样多次，而且没有逐 token 的信用分配。另一个区别是 KL：PPO 扣在奖励里，GRPO 加在 loss 里。

2 分钟口述

答题模板

  1. 一句话定位。PPO 是带信赖域思想的策略梯度方法：用重要性采样复用一批数据做多轮更新，用裁剪限制每次更新离旧策略不要太远，是 TRPO 的一阶近似。
  2. 讲目标函数。LCLIP=E[min⁡(ρtA^t,clip(ρt,1−ϵ,1+ϵ)A^t)]L^{\text{CLIP}}=\mathbb{E}[\min(\rho_t\hat{A}_t,\mathrm{clip}(\rho_t,1-\epsilon,1+\epsilon)\hat{A}_t)]LCLIP=E[min(ρt​A^t​,clip(ρt​,1−ϵ,1+ϵ)A^t​)]，取 min 是悲观下界；A^>0\hat{A}>0A^>0 时比值超过 1+ϵ1+\epsilon1+ϵ、A^<0\hat{A}<0A^<0 时比值低于 1−ϵ1-\epsilon1−ϵ，梯度为 0。

  4. 讲 RLHF 落地。四个模型；token 是动作；每个 token 扣 β KLt\beta\,\mathrm{KL}_tβKLt​，最后一个 token 加 RM 分数；γ=1\gamma=1γ=1、λ=0.95\lambda=0.95λ=0.95；critic 从 RM 初始化；优势 batch 内标准化；一批数据跑几轮小批量。
  5. 讲问题和演进。四个模型显存大、critic 在稀疏奖励下难训、对实现细节敏感、容易 reward hacking。GRPO 去掉 critic 用组内 baseline，DPO 直接把 RLHF 目标变成离线的分类损失。

常见失分点：说裁剪能保证比值不越界（只是越界后不给梯度）；说两侧都裁（只裁有利方向的一侧）；把 λ\lambdaλ 和 γ\gammaγ 混为一谈（γ\gammaγ 改目标，λ\lambdaλ 只改估计）；说 PPO 是 off-policy（是 on-policy，多轮更新只是轻微复用）；说 RM 分数加在每个 token 上（只加在最后一个 token，每个 token 上的是 KL 惩罚）；用标准化之后的优势去算 critic 的目标。
