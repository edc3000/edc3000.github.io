多模态大模型基础：视觉编码、模态对齐、动态分辨率与原生多模态

纯文本 LLM 只认离散词表里的 token ID，而图像、视频、音频都是连续的高维信号。多模态大模型面试几乎所有追问都围绕五件事：视觉信号怎么编码成 token（ViT、CLIP、SigLIP）、怎么对齐进语言主干（MLP、Q-Former、Pixel Shuffle、Cross-Attention）、高清图和长视频怎么不爆显存（AnyRes、NaViT、MRoPE）、多阶段怎么训不丢文本能力，以及理解与生成怎么统一。本文把这条链路从头拆清楚。

先给结论

30 秒背诵版

主线：连续多模态信号 → 编码 / 切块 → 模态对齐压缩 → 与文本共用 Transformer 主干

主流架构：当前视觉语言模型（VLM）的事实标准是 Vision Encoder (ViT) + Patch Merger / MLP + Decoder-only LLM（输入级早期拼接，代表 LLaVA、Qwen-VL、InternVL）。另一条路是中间层 Cross-Attention 注入（Flamingo、Llama 3.2 Vision），冻结 LLM 时纯文本零退化，但深层跨模态推理弱于全自注意力；更新的趋势是跳过后接视觉的拼接期，从预训练早期就图文音视混训的原生多模态（Gemini、Qwen3.5）。

视觉编码器：ViT 用步长 PPP 的卷积把 H×WH\times WH×W 图像切成 (H/P)×(W/P)(H/P)\times(W/P)(H/P)×(W/P) 个 patch。对比学习预训练里，CLIP 用 InfoNCE（对称 Softmax），分母耦合全局负样本，依赖超大 batch；SigLIP 改成逐对 Sigmoid 二分类损失，解耦 batch 大小、初始偏置 b≈−10b\approx -10b≈−10 抵消负样本压倒正样本的问题，OCR 与细粒度定位普遍优于 CLIP。

连接器与高分辨率：纯 Linear/MLP 保留全部空间信息但 token 太长；Q-Former / Resampler 压成定长（如 32/64 个 token）但丢细节、OCR 差；现代主流是 Pixel Shuffle / 2×2 Patch Merger + 2 层 MLP，把 token 砍到 1/41/41/4 同时保住局部结构。高清图处理分两条路：AnyRes 动态切图（InternVL、LLaVA-NeXT，切 tile + 全局缩略图）vs NaViT 原生动态分辨率（Qwen2/2.5/3-VL，不切图直接按原比例打包进变长序列，配合 2D-RoPE 与局部窗口注意力）。

位置编码、Mask 与训练：展平 2D 图像会让上下相邻 patch 在 1D 序列里距离失真，现代方案把 1D RoPE 拆成时间、高、宽三组频率（MRoPE / Interleaved-MRoPE），文本位置三坐标相同、严格退化回 1D RoPE。视觉理解任务的 loss mask 只算模型回答文本，不算图像占位符和提问。训练分四步：① 冻结主干只训 Connector 对齐；② 解冻联合持续预训练（必须混 15%–30% 纯文本防遗忘）；③ 多模态 SFT；④ DPO / GRPO 抑幻觉、提推理。

多下游任务统一：不再像传统 CV 给每个任务挂专用头，而是把 VQA、OCR（Markdown/LaTeX）、目标检测 Grounding（归一化 [0,1000) 或绝对像素坐标 JSON）、GUI 点击动作、视频时间戳定位全部统一成 Prompt 路由 + 结构化文本 Next-Token Prediction；只有像素级分割（Segmentation）等超密输出才通过特殊 <SEG> token 接轻量 SAM Decoder 或调用外部工具完成。多任务混训靠温度采样和样本级/加权 Loss 防止长回复（OCR）淹没短输出（坐标/点选）。

统一理解与生成：理解要抽象语义、生成要保真像素，存在表征冲突。早期 VQ 离散自回归（Chameleon、Emu3）统一用 Next-Token Prediction 但量化损细节；当前主流转向解耦编码器 + 连续 Diffusion / Flow Matching（Transfusion、Janus-Pro、BAGEL），或用 Mixture-of-Transformers（MoT）按模态分设 FFN、共享注意力。

架构全景

四种多模态架构范式

把图像接入大语言模型，核心分歧在两个问题：视觉特征要不要先过一个独立编码器，以及视觉信息和文本在 LLM 的哪一层汇合。按这两条轴，演进出了四种典型范式。

端到端拆解

从一张原始图片到 ViT 输出：完整链路与张量形状

面试里最容易卡壳的不是宏观概念，而是“一张 JPG/PNG 原始图片传进来，每一步张量到底长什么样、是怎么切块并送进视觉编码器、最后怎么塞进 LLM 的？”下面拿一张具体尺寸 448 × 896 的图片（配 P=14、D_v=1152、2×2 Merger、D_l=3584）把 6 个步骤从头到尾走一遍。

细节 ①：为什么切块 + 线性投影等价于一个 Conv2d？

直觉做法分两步：把 [3, 448, 896] 按 14×14 切成 32×64 = 2048 个互不重叠的小块，每块有 14×14×3=58814\times 14\times 3 = 58814×14×3=588 个像素值，拉直成 588 维向量再乘权重矩阵 W∈R588×1152W \in \mathbb{R}^{588\times 1152}W∈R588×1152 得到 1152 维向量。

把 Conv2d(in_ch=3, out_ch=1152, kernel_size=14, stride=14) 展开看：核大小等于步长意味着滑动窗口互不重叠，每个输出通道的卷积核权重大小正好是 3×14×14 = 588，做一次局部内积和上面的 flatten + Linear 在数学上逐元素完全等价，而且能直接吃到 cuDNN 卷积加速（视频则换成 Conv3d(kernel=(2,14,14), stride=(2,14,14))）。

细节 ②：展平后，不同尺寸的多张图怎么一起进 ViT？

Transformer 只吃 1D 序列，所以要把 [1152, 32, 64] 展平成 [2048, 1152]。如果是 Fixed Resize / AnyRes，每张图（或每个 tile）切出来的 patch 数完全一样（如都是 1024），直接按 batch 维堆成 [B, 1024, 1152] 即可。

如果是 NaViT 原生动态分辨率，一个 batch 里图 A 有 2048 个 patch、图 B 只有 512 个 patch。硬补零到 2048 会白算 75% 废计算，所以现代框架用 Sequence Packing：把图 A 和图 B 首尾拼成一条长度 2560 的一维长序列 [2560, 1152]，再传一个边界数组 cu_seqlens = [0, 2048, 2560] 给 FlashAttention varlen 内核，保证图 A 和图 B 的注意力互不串味、零 padding 浪费。

细节 ③：ViT 内部怎么知道谁在左上、谁在右下？

展平操作本身抹掉了二维邻接关系，必须注入位置信息，分两代做法：

  • 固定位置表（CLIP / 早期 SigLIP）：存一张可学习表 pos_embed [H'×W', D_v] 直接加到 patch 向量上。缺点是一旦输入尺寸变了，必须把位置表 reshape 成 2D 做双三次插值（bicubic interpolation），拉伸幅度大了精度明显掉。
  • 2D-RoPE（NaViT / Qwen2.5-VL）：去掉绝对位置表，在 ViT 每一层算 Q、K 时，把头维度 dhd_hdh​ 对半拆——前一半按行号 yyy 旋转、后一半按列号 xxx 旋转。任意尺寸、任意长宽比原生支持；高清图再配合 Window Attention（把 H'×W' 按 8×8 块分组局部自注意力，隔几层插 1 层全局自注意力），避免单图上万 patch 的 O(N2)O(N^2)O(N2) 爆炸。

细节 ④：ViT 输出取哪一层？怎么和文本拼进 LLM？

  • 取层与去 [CLS]：CLIP 是在顶层 [CLS] 上做图文对比损失训出来的，最后一层高度偏向全局抽象语义、局部细节已被压缩。LLaVA-1.5 实测拿 倒数第二层 hidden_states[-2] 并丢弃 [CLS]，效果明显好于最后一层；SigLIP 没有 [CLS]，直接取全部空间 patch；Qwen3-VL 甚至同时取多层中间特征做 DeepStack。
  • 原位替换（Scatter）进 LLM：文本端构造 prompt 时，已经提前在图像出现的位置塞好了恰好 512 个特殊占位 token <image_pad>，过完文本词表 embed_tokens 得到 [L, 3584]；接着只需一行张量赋值 inputs_embeds[input_ids == IMG_PAD_ID] = vision_embeds，就把这 512 个位置的向量替换成 Merger 输出的视觉向量，直接喂进 LLM 第 0 层！

视觉编码器怎么训：CLIP 与 SigLIP

走完上面这条前向链路后，下一个必考问题是：ViT 里这几亿参数是怎么训出来的？

为什么选 ViT 而不是 CNN（ResNet）？

  • 输出天然是 token 序列：每个 patch 对应一个向量，和 LLM 的 token 接口完全同构。
  • 全局感受野：第一层就能做跨全图的自注意力，方便整合图文里的全局空间关系。
  • Scaling 曲线更好：数据上亿后 CNN 容易饱和，ViT（如 ViT-SO400M、InternViT-6B）能随数据和参数持续涨点。

为什么直接拿 ImageNet 分类 ViT 不够？

ImageNet 只有 1000 个固定类别，学到的是“猫/狗/车”这类粗糙分类边界，缺乏开放词汇、文字（OCR）、属性和细粒度描述能力。因此 VLM 几乎都用海量图文对预训练出的视觉编码器——典型代表就是 CLIP 和 SigLIP。

CLIP（InfoNCE）vs SigLIP（Sigmoid Loss）

给定一个大小为 BBB 的图文 batch，图像编码器输出 ℓ2\ell_2ℓ2​ 归一化向量 u1,…,uB\mathbf{u}_1,\dots,\mathbf{u}_Bu1​,…,uB​，文本编码器输出 v1,…,vB\mathbf{v}_1,\dots,\mathbf{v}_Bv1​,…,vB​，余弦相似度 sij=ui⊤vjs_{ij}=\mathbf{u}_i^\top \mathbf{v}_jsij​=ui⊤​vj​。两者的本质分歧在于如何对这 B×BB\times BB×B 个图文对算损失：

CLIP：对称 InfoNCE 行/列 Softmax

LCLIP=−12B∑i=1B(log⁡etsii∑j=1Betsij+log⁡etsii∑j=1Betsji)\mathcal{L}_{\text{CLIP}} = -\frac{1}{2B}\sum_{i=1}^{B}\left(\log\frac{e^{t s_{ii}}}{\sum_{j=1}^{B} e^{t s_{ij}}} + \log\frac{e^{t s_{ii}}}{\sum_{j=1}^{B} e^{t s_{ji}}}\right)LCLIP​=−2B1​i=1∑B​(log∑j=1B​etsij​etsii​​+log∑j=1B​etsji​etsii​​)

把每张图匹配正确文本看成一次 BBB 分类（反之亦然），t=1/τt = 1/\taut=1/τ 是可学习温度倒数（CLIP 里把 log⁡t\log tlogt 截断在 ln⁡100\ln 100ln100 防过尖）。

痛点：Softmax 分母依赖全局所有负样本，多机训练必须做全局 all_gather 通信；batch size 小时负样本太简单、表征容易退化，因此 CLIP 往往需要 32k 级别的超大 batch。

SigLIP：逐对 Sigmoid 独立二分类

LSigLIP=−1B∑i=1B∑j=1Blog⁡11+exp⁡(−zij(tsij+b))\mathcal{L}_{\text{SigLIP}} = -\frac{1}{B}\sum_{i=1}^{B}\sum_{j=1}^{B}\log\frac{1}{1+\exp\big(-z_{ij}(t s_{ij} + b)\big)}LSigLIP​=−B1​i=1∑B​j=1∑B​log1+exp(−zij​(tsij​+b))1​

正样本对 zii=+1z_{ii}=+1zii​=+1，其余 B2−BB^2-BB2−B 个负样本对 zij=−1z_{ij}=-1zij​=−1，把每个位置变成独立的二分类，引入可学习偏置 bbb。

优势：不再需要跨卡做全局 Softmax 归一化，可以用分块（chunked）通信把显存从 O(B2)O(B^2)O(B2) 压到极低；在中等 batch（如 4k–16k）就能训得很好，且对密集语义、OCR 和小物体更友好。SigLIP-2 进一步加入局部描述（captioning）与自蒸馏目标，已成为 Qwen3-VL、PaliGemma 2、Gemma 3 的标配编码器。

CLIP/SigLIP 的「词袋盲区」与多编码器补救：纯对比学习只要求图像整体向量贴近整句描述，容易忽略空间方位（左/右）、计数、精确几何形状和底层纹理（称为 Vision-Language 的 bag-of-words 缺陷）。常见补救有三种：① 用 SigLIP-2 / EVA-CLIP / InternViT 等加了生成式或掩码建模目标的编码器；② 多层特征融合（如 Qwen3-VL 的 DeepStack，把 ViT 中间层的细粒度空间特征也送进 LLM 前几层）；③ 视觉编码器集成（如 Cambrian-1 拼接 SigLIP + DINOv2 + ConvNeXt，DINOv2 补强空间几何与深度感知）。

模态连接器：MLP、Q-Former 与 Pixel Shuffle

视觉编码器输出的是维度 DvD_vDv​ 的空间特征网格（如 SigLIP-SO400M 为 1152 维），而 LLM 期望维度 DlD_lDl​ 的词向量（如 7B 模型为 3584 或 4096 维）。连接器（Projector / Adapter）干两件事：把视觉特征映射到文本语义空间，以及按需压缩视觉 token 数量。

为什么 Q-Former 逐渐退居二线？

BLIP-2 时代 LLM 上下文只有 2K–4K，必须靠 Q-Former 把 576 个 patch 硬压成 32 个 token。但当任务扩展到整页 PDF、长截图、密集表格、GUI 点击坐标时，32 或 64 个无固定空间对应的 query 根本装不下上百行小字；而且 Q-Former 参数量大、从头训收敛慢，不如简单的 Pixel Shuffle + 2 层 MLP 稳定高效。

DeepStack：不只拿 ViT 最后一层

传统架构只取 ViT 最后一层的输出（偏高层语义，底层笔画和边缘纹理已抽象掉）。像 Qwen3-VL 的 DeepStack 或多层特征拼接，会额外取出 ViT 中间几层的特征，分别过 Merger 后加到 LLM 前几层的 hidden state 上，显著增强细粒度识别与空间定位。

看得清

高分辨率处理：Fixed Resize、AnyRes 与 NaViT

早期 VLM（如 LLaVA-1.5）强行把所有图片缩放到 336×336336\times 336336×336。遇到一张 1920×10801920\times 10801920×1080 的 PPT 或 800×2400800\times 2400800×2400 的手机长截图，缩放后不仅文字糊成一片，还会发生严重的纵横比畸变。工业界先后走出了两条高分辨率路线：

AnyRes 的具体做法（InternVL / LLaVA-NeXT）

预先给一个最大切片数 Mmax⁡M_{\max}Mmax​（如 6 或 12），枚举所有 gh×gw≤Mmax⁡g_h \times g_w \le M_{\max}gh​×gw​≤Mmax​ 的网格，选出长宽比最接近原图、且有效面积覆盖最大的网格，把原图切分成 gh⋅gwg_h \cdot g_wgh​⋅gw​ 个 448×448448\times 448448×448 的 tile，再加上 1 张缩放到 448×448448\times 448448×448 的全局缩略图。若每块经 2×2 Pixel Shuffle 出 256 token，6 块 + 1 缩略图就是 7×256=17927\times 256 = 17927×256=1792 个 token。

NaViT 的工程关键（Qwen2.5-VL）

1）把原图宽高按 factor = P × merge_size（如 14×2=2814\times 2 = 2814×2=28）取整，面积超出 max_pixels 时等比缩小；2）去掉固定绝对位置编码，改用 2D-RoPE；3）因为不切 tile，高清图单图 patch 可能上万，ViT 内部如果全用全局注意力会面临 O(N2)O(N^2)O(N2) 爆炸——Qwen2.5-VL 把大部分 ViT 层改为 Window Attention（如 8×88\times 88×8 局部窗口），只在少数几层保留全局自注意力，把 ViT 耗时压到线性级别。

空间与因果

多模态位置编码（MRoPE）与注意力 / Loss Mask

视觉 token 进到 LLM 之后，立刻面临两个和纯文本完全不同的结构性问题：二维/三维空间位置怎么编码，以及谁能看谁、哪些位置算损失。

为什么 1D RoPE 表达图像会失真？

一张 10×1010\times 1010×10 的视觉网格按行展平后，第 1 行第 1 列与第 2 行第 1 列在空间上紧挨着（距离 1），但在 1D 序列里相隔 10 个位置；而第 1 行末尾和第 2 行开头在空间上隔着整张图，序列距离却只有 1。多图和视频还多出一个时间维 TTT。

MRoPE 与 Interleaved-MRoPE

MRoPE（Qwen2-VL）把每个注意力头的 dh/2d_h/2dh​/2 对旋转频率拆成三份，分别编码时间 ttt、高度 hhh、宽度 www。关键性质：遇到纯文本 token 时，令 (t,h,w)=(p,p,p)(t, h, w) = (p, p, p)(t,h,w)=(p,p,p)，三组旋转角度相同，严格退化为标准 1D RoPE，完全兼容原文本能力。

Interleaved-MRoPE（Qwen3-VL）修复了原版按连续分块（T 全拿高频、W 全拿低频）导致视频长程衰减过快的毛病，把 (t,h,w)(t, h, w)(t,h,w) 交错排布到所有频段，让时间与空间都同时拥有高频局部定位和低频长程建模能力。

不止图像

扩展到视频与音频：从 VLM 到 Omni

视频和音频本质上都是在空间之外引入了时间轴，核心挑战变成如何在有限上下文窗口里装下长时序信息。

视频理解三件套 时空压缩

  • 采样与动态预算：短视频按固定帧率（如 1–2 fps）抽帧；长视频受总视觉 token 上限约束，会自动降低每帧分辨率或抽帧率。
  • 3D Patchify（时间压缩）：Qwen2/2.5-VL 用 3D 卷积 Conv3d(kernel=(2,14,14)) 把相邻 2 帧打包成 1 个时间步（单张静图复制成 2 帧统一走同一卷积核），再叠 2×2 空间合并，时空总压缩率达 2×4=8×2\times 4 = 8\times2×4=8×。
  • 绝对时间对齐：动态抽帧下“帧序号”不等于“真实秒数”。Qwen2.5-VL 把 MRoPE 的时间 ID 绑定到物理时间戳（而非帧索引），让模型能准确回答“第 1 分 23 秒发生了什么”。

音频与全双工 Omni Thinker-Talker

  • 音频输入（听）：原始 16kHz 波形转成 Log-Mel 频谱图，经过 Whisper 风格的 Audio Encoder（1D 卷积下采样 + Transformer），输出约 12.5 Hz–25 Hz 的连续音频特征（1 秒仅 12–25 个 token），经 Adapter 拼进 LLM。
  • 音频输出（说）：早期级联方案是 ASR → LLM → TTS（延迟高、丢语气情绪）。原生 Omni（如 GPT-4o、Qwen2.5-Omni）采用端到端语音建模或 Thinker-Talker 双轨架构：Thinker 负责多模态理解与文本生成，Talker 同步接收 Thinker 的隐状态流式预测离散音频 codec token，再由声码器（Vocoder）实时合成波形，实现低延迟且带情感韵律的语音对话。

多模态训练全流程与防遗忘

把一个训好的 ViT 和一个训好的 LLM 拼在一起，最忌讳一上来就端到端大力微调：刚初始化的 Connector 输出全是噪声，反向传播的大梯度会瞬间冲毁已经收敛好的 ViT 和 LLM 权重。因此主流 VLM 形成了清晰的多阶段训练范式：

为什么 Stage 2 必须解冻 ViT？

如果一直冻结 CLIP/SigLIP ViT，它永远带着对比学习的“全局词袋偏置”——看大物体没问题，一碰密集表格、公式排版、代码截图、精确边界框就卡死。解冻 ViT（配较小的学习率，比如 LLM 的 1/51/51/5 到 1/101/101/10）配合 OCR 与 Grounding 数据，能把视觉特征重塑得真正服务于语言推理。

原生多模态预训练（Early-Fusion）难在哪？

像 Qwen3.5、Gemini 从预训练阶段就把图文和纯文本混训，省去了“先纯文本后硬拼”的模态鸿沟，但带来三个工程难点：① 梯度尺度冲突（视觉与文本的激活方差、梯度范数不同，常需 QK-Norm 和模态独立 LayerNorm 稳住训练）；② 序列打包与负载不均（一张高清图和一段短文本计算特征差异大，PP/TP 流水线容易出气泡）；③ MoE 模态路由坍缩（部分专家只吃图像不吃文本，需做负载均衡控制）。

多模态模型如何统一做多个下游任务

高频考法 ①：坐标怎么文本化？归一化 vs 绝对像素

让纯文本 LM Head 输出目标框 [x1, y1, x2, y2] 有两种主流编码：

  • 归一化相对坐标 [0, 1000)（Qwen2-VL、InternVL、PaliGemma）：把原图宽高统一映射到 0–999 整数（或 1000 个专用位置词 <loc000>~<loc999>）。好处是和图片缩放无关、跨分辨率通用；缺点是细长图（如 1:4 手机长截图）在长边量化步长变粗，损失精度。
  • 绝对像素坐标（Qwen2.5-VL）：直接输出输入图的真实像素坐标。前提是模型用 NaViT 原生动态分辨率，能从 2D-RoPE 网格尺寸直接感知真实物理尺度，省掉换算且大/长图小目标定位更准。

高频考法 ②：纯文本搞不定的像素级任务怎么办？

如果要输出一张 1024×10241024\times 10241024×1024 的像素级分割掩码，靠自回归吐上万个多边形顶点既慢又糊。工程上有两条成熟路径：

  • 特殊 Token + 轻量像素解码器（Embedding-as-Mask，代表 LISA）：词表里加一个 <SEG> token，LLM 做完复杂推理（例如“找出图里维生素 C 含量最高的水果”）后输出 <SEG>，取该 token 最后一层的隐状态经 MLP 投成 prompt embedding，喂给 SAM Mask Decoder 直接生成高清像素掩码。
  • 多模态 Agent 调工具（Thinking with Images）：LLM 只输出检测框或点坐标，把框传给外部 SAM / OCR / Python 裁剪放大工具，实现“先定位 → 再放大/分割 → 再核验”的闭环。

高频考法 ③：多任务混训为什么会“互相打架”？

  • 数据量悬殊（温度采样）：Caption 和 OCR 往往千万级，GUI 点击和复杂 Grounding 只有几十万。按原比例混训会让小任务彻底学不出来，工业界普遍按 pi∝Niαp_i \propto N_i^{\alpha}pi​∝Niα​（α∈[0.3,0.7]\alpha \in [0.3, 0.7]α∈[0.3,0.7]）做温度重采样，并在不同训练阶段动态调整配比。
  • 长短输出 Loss 淹没：一条整页 PDF OCR 回复长达 2000 token，而一条 GUI 点击 click(412,688) 只有不到 10 个 token。如果按全局 Token-level 平均算交叉熵，1 条 OCR 的梯度权重等于 200 条 GUI 数据，定位能力会被严重压制！常见解法是改用 Sample-level 平均或按 1/L1/\sqrt{L}1/L​ 对长回复衰减加权。

高频考法 ④：后训练怎样一套框架同时拉高多任务？

除了传统 SFT 混训，2025–2026 的核心突破是多任务可验证强化学习（Multimodal RLVR / GRPO）。大多数视觉下游任务天然具备无需人工裁判的精确规则奖励：

  • 数学/图表/VQA → 符号/答案等价验证；
  • 目标检测 / Grounding → 预测框与真值框的 IoU / GIoU；
  • GUI 操作 → 预测点击点 (x, y) 是否落入目标控件 BBox 内；
  • OCR / 结构化抽取 → 规范化编辑距离或 JSON Schema 匹配分。

把这些规则奖励塞进同一套 GRPO 训练管线，就能在保留通用对话能力的同时，把定位、点击、视觉推理整体拉上一个台阶。

统一理解与生成：离散 Token vs 连续扩散

前面讲的 VLM 都是“多模态输入、纯文本输出”。如果要让一个模型既能看懂图、又能直接画图/改图（Unified Multimodal Model），马上会撞上一堵根本性的墙——理解与生成的表征冲突：

  • 理解任务需要语义不变性：同一只猫，换个光照、歪个角度、压缩一下画质，语义向量应该几乎不变（丢掉底层像素细节）。
  • 生成任务需要像素保真度：必须精确记住每一根毛发、每一个笔画的局部高频细节，才能无损重建出高清图像。

工程痛点

视觉幻觉、Token 剪枝与多模态推理瓶颈

多模态幻觉（Hallucination）从哪来？

  • 语言先验压过视觉证据：LLM 记住“餐桌旁常有椅子”“斑马线旁有红绿灯”，生成越长，注意力越偏向自己刚生成的文本 token，对视觉 token 的注意力在深层迅速衰减。
  • 看得不够清只能脑补：低分辨率缩放或 Q-Former 强压缩把小字/小物体抹掉了，模型却被 SFT 训成“必须有问必答”。
  • 缓解三板斧：① 架构上用高分辨率原生编码 + DeepStack；② 训练上做多模态 DPO（构造只改动一个物体/属性/计数的细粒度负样本）与可验证 RLVR；③ 推理上可用 VCD（视觉对比解码）——拿原图 logits 减去加噪失真图的 logits 放大视觉依赖，或让模型调用 crop/zoom 工具二次放大看图（Thinking with Images）。

视觉 Token 剪枝与推理服务工程坑

  • 为什么视觉 token 特别冗余？一张风景图里大片天空、白墙占了一半以上 patch。FastV 发现进入 LLM 第 2 层之后，超过一半视觉 token 获得的注意力接近 0，直接按注意力得分剪掉 50% 视觉 token，FLOPs 降 45% 而精度几乎不掉；ToMe 则在 ViT 内按余弦相似度合并相似 patch。
  • EPD 分离调度：高清图 ViT 编码是密集计算，直接和文本 decode 混在同一 batch 会拖慢所有并发请求的 TPOT。现代推理框架（vLLM / SGLang）逐步将 Encode（ViT）— Prefill — Decode 解耦或独立缓存。
  • 多模态 Prefix Caching 坑：输入序列里图像位置只是一串相同的占位符 ID（如 <image_pad>）。做前缀缓存哈希时，必须把图像内容哈希（SHA-256）混入块键，否则不同图片会误命中同一份 KV Cache！
手撕

代码：PatchEmbed + Pixel Shuffle Merger + SigLIP Loss

import torch, torch.nn as nn, torch.nn.functional as F

class PatchEmbed(nn.Module):
    """ViT 切块 + 线性投影：用步长=P 的 Conv2d 一步完成"""
    def __init__(self, patch_size=14, in_ch=3, d_v=1152):
        super().__init__()
        self.proj = nn.Conv2d(in_ch, d_v, kernel_size=patch_size, stride=patch_size)

    def forward(self, x):                               # x: [B, 3, H, W]
        x = self.proj(x)                                # [B, d_v, H/P, W/P]
        return x.permute(0, 2, 3, 1)                    # [B, H', W', d_v]

class PixelShuffleMerger(nn.Module):
    """2×2 空间折叠 + 2 层 MLP（Qwen-VL / InternVL 标配连接器）"""
    def __init__(self, d_v=1152, d_l=3584, scale=2):
        super().__init__()
        self.s = scale
        self.norm = nn.LayerNorm(d_v)
        self.mlp = nn.Sequential(
            nn.Linear(d_v * scale * scale, d_l),
            nn.GELU(),
            nn.Linear(d_l, d_l),
        )

    def forward(self, x):                               # x: [B, H', W', d_v]
        B, H, W, D = x.shape
        assert H % self.s == 0 and W % self.s == 0
        x = self.norm(x)
        x = x.view(B, H // self.s, self.s, W // self.s, self.s, D)
        x = x.permute(0, 1, 3, 2, 4, 5).contiguous()    # 相邻 s×s 块聚到一起
        x = x.view(B, (H // self.s) * (W // self.s), self.s * self.s * D)
        return self.mlp(x)                              # [B, N/s^2, d_l]

def siglip_loss(img_emb, txt_emb, log_t, bias):
    """SigLIP 逐对 Sigmoid 损失（初始 log_t=ln(10), bias=-10）"""
    u = F.normalize(img_emb, dim=-1)                    # [B, D]
    v = F.normalize(txt_emb, dim=-1)                    # [B, D]
    logits = u @ v.T * log_t.exp() + bias               # [B, B]
    B = logits.size(0)
    labels = 2 * torch.eye(B, device=logits.device) - 1 # 对角 +1，其余 -1
    return -F.logsigmoid(labels * logits).sum() / B

手撕常见追问：① PixelShuffleMerger 里为什么先 permute(0, 1, 3, 2, 4, 5) 再 view？直接 view(B, N//4, 4*D) 只会把同一行连续 4 个 patch 拼在一起，破坏了二维 2×2 邻域结构；② 如果原图 H′H'H′ 或 W′W'W′ 不是 2 的倍数怎么办？预处理阶段就按 P × scale（如 28）对齐缩放或补边；③ siglip_loss 里为什么要写 F.logsigmoid(labels * logits) 而不是先算 sigmoid 再取 log？数值稳定，防止大负值下溢成 log(0) = -inf。

自测

高频追问

1. 为什么主流 VLM 普遍用「ViT + MLP 拼接」而不是 Cross-Attention 或 Q-Former？

对比 Q-Former：Q-Former 把任意分辨率图像强压成 32/64 个固定 query，形成了严重的信息瓶颈，一遇密集 OCR、表格、小目标就掉点，而且参数多、难收敛。2×2 Pixel Shuffle + MLP 既降了 75% token 数，又完整保留了二维局部结构。

对比 Cross-Attention：Cross-Attention（如 Flamingo、Llama 3.2 Vision）只把视觉特征作为 K/V 注入到少数几层，冻结 LLM 时纯文本零损失，但视觉 token 之间、视觉与文本之间无法在 LLM 每一层做深层双向/全序列交互，在复杂视觉推理和 OCR 上普遍弱于早期输入级拼接（NVLM 论文做了同数据同底座对照，Decoder-only 拼接综合表现更强）。

2. CLIP 和 SigLIP 的核心区别是什么？为什么 SigLIP 初始偏置 b 要设成负数（如 -10）？

CLIP 用对称 InfoNCE（行/列 Softmax），分母强依赖全局负样本，需要超大 batch 和跨卡 all_gather；SigLIP 把 B×BB\times BB×B 个图文对拆成独立的二分类（Sigmoid 损失），无需全局 Softmax，显存和通信友好得多，中等 batch 就能训出更强的密集语义与 OCR 能力。

偏置 b=−10b=-10b=−10 的原因：batch 为 BBB 时，正负样本比例是 1:(B−1)1:(B-1)1:(B−1)。初始化时相似度接近 0，如果 b=0b=0b=0，每个负样本的 sigmoid 概率都是 0.5，B−1B-1B−1 个负样本的梯度合起来会是正样本的几千上万倍，第一步更新就把所有特征往死里推开、训练直接崩掉。设 b=−10b=-10b=−10 后，负样本初始预测概率降到 σ(−10)≈4.5×10−5\sigma(-10)\approx 4.5\times 10^{-5}σ(−10)≈4.5×10−5，总负梯度与正梯度回到同一量级（上面的实验一可直接验证）。

3. 为什么多模态第一阶段通常要冻结 ViT 和 LLM，只训练 Projector？

ViT 和 LLM 都是各自领域预训练好的强基座，而连接器（Projector / Merger）是随机初始化的。第一阶段如果直接全参放开，随机投影产出的噪声特征会导致极高的初始 loss，大梯度反向传进 LLM 和 ViT，在两者还没对齐之前就破坏掉原有的表征分布（Representation Collapse）。先用高学习率把 Projector 训到能“说 LLM 听得懂的话”，再在 Stage 2 全参解冻联合微调，收敛更稳、最终上限更高。

4. 训练多模态模型时，为什么会损伤原本的纯文本能力（灾难性遗忘）？怎么缓解？

两个原因：① 多模态图文数据集的语言分布普遍偏短、偏描述性（“图里有一只猫在草地上”），远不如纯文本预训练语料包含丰富代码、数学和长逻辑链，全参训练会拉偏 LLM 的语言分布；② 视觉 token 的隐状态分布（均值、方差、离群通道）与文本 token 存在显著差异，更新后的注意力和 FFN 权重会向视觉分布偏移。

缓解手段：Stage 2 和 Stage 3 必须混入 15%–30% 高质量纯文本数据（代码、数学、推理）；对 LLM 用更小的学习率；或者从架构上采用 MoE / MoT 为视觉和文本分担参数容量；若是严格不允许文本掉点的场景，可采用冻结文本主干的 Cross-Attention 或模态专属 LoRA。

5. AnyRes（动态切图）和 NaViT（原生动态分辨率）各有什么优缺点？

AnyRes（LLaVA-NeXT、InternVL）最大优点是开箱兼容所有固定分辨率预训练 ViT（比如直接拿 448×448 的 InternViT 或 336×336 的 CLIP），工程迁移门槛低。缺点是切片边界可能把一行字或一个物体拦腰截断、原图长宽比不匹配网格时会引入无效 padding，且额外加一张全局缩略图增加了重复编码开销。

NaViT（Qwen2/2.5/3-VL）按原图长宽比直接切 patch、打包进变长序列并配 2D-RoPE，彻底消除切缝割裂与无效 padding，token 预算随分辨率平滑伸缩；缺点是需要改造 ViT 位置编码与打包基础设施，并在高清图上配合 Window Attention 控制 ViT 内部 O(N2)O(N^2)O(N2) 计算量。

6. 图像 token 在 LLM 里用因果注意力（Causal）还是双向注意力（Bidirectional）？

两条路线都在用：纯 Causal Mask（LLaVA、Qwen-VL）把视觉 token 当普通前缀 token 处理，优点是与纯文本 LLM 训练/推理内核（FlashAttention、vLLM PagedAttention）100% 兼容，且因为前面 ViT 已经做过全图双向自注意力，每个 patch 向量里其实已经融合了全局上下文，所以 LLM 内用因果掩码损失很小。

Prefix-Bidirectional Mask（PaliGemma、Gemma 3）允许同一张图的所有视觉 token 在 LLM 内部互相可见，理论上图像内推理更充分、尤其适合图生文或浅层 ViT；代价是推理框架必须支持块级双向注意力掩码，且多图交错场景下的前缀缓存边界更复杂。

7. MRoPE 是怎么同时兼容文本、图像和视频的？Interleaved-MRoPE 改了什么？

标准 RoPE 在一个注意力头里有 dh/2d_h/2dh​/2 对旋转频率。MRoPE 把这批频率分成三组，分别乘以每个 token 的三维坐标 (t,h,w)(t, h, w)(t,h,w)：纯文本 token 的三坐标相同，设为连续递增的 (p,p,p)(p, p, p)(p,p,p)，于是退化成完全等价的 1D RoPE；图像 token 共享同一个 ttt，h,wh, wh,w 按二维网格坐标递增；视频则在每帧（或每 2 帧）递增 ttt（Qwen2.5-VL 进一步按物理秒数赋 ttt）。

Interleaved-MRoPE（Qwen3-VL）解决了原版 MRoPE 按连续切片分配频率的问题：原版把最高频全给了 T、最低频全给了 W，导致时间维度缺乏低频长程外推能力；交错排布（T, H, W, T, H, W...）让三个维度均分所有频段，长视频和高分辨率空间定位同步变稳。

8. 多模态模型为什么容易出现「视觉幻觉」？怎么系统缓解？

核心根因有三：① 语言先验过强（文本统计惯性盖过真实图像，尤其生成长段落时视觉注意力衰减）；② 视觉细节丢失（分辨率不够、压缩过猛或 CLIP 词袋偏置导致看不清）；③ 训练数据噪音（合成描述自带幻觉、缺乏“图中没有/看不清”的拒答样本）。

系统缓解分四层：架构层上原生高清分辨率 + DeepStack 多层视觉注入；数据层清洗合成描述、加入否定/不存在物体的对抗 VQA 样本；后训练层做多模态 DPO（构造只改物体/属性/数量的细粒度负样本）和可验证 RLVR；推理层可用 VCD 对比解码，或在 Agent 循环里让模型调用 crop/zoom 工具把小区域放大重看。

9. 一张 1920×1080 的图进 Qwen2.5-VL（patch=14，2×2 merger）大概产生多少视觉 token？瓶颈在哪？

按 factor = 14 × 2 = 28 对齐：宽 1920→1904=68×281920 \to 1904 = 68\times 281920→1904=68×28，高 1080→1092=39×281080 \to 1092 = 39\times 281080→1092=39×28。原始 patch 数是 (68×2)×(39×2)=10,608(68\times 2)\times(39\times 2) = 10{,}608(68×2)×(39×2)=10,608，经 2×2 Merger 后进入 LLM 的视觉 token 数为 68×39=2,65268\times 39 = 2{,}65268×39=2,652 个（如果不超 max_pixels）。

瓶颈：① 若不做 Window Attention，ViT 对 10,608 个 patch 做全注意力的矩阵是 106082≈1.1×10810608^2 \approx 1.1\times 10^8106082≈1.1×108，极度耗时；② 进入 LLM 后，单张图就等价于 2,652 字长文，如果一次传 10 张高清图就是 2.6 万 token，Prefill 延迟和 KV Cache 显存都会飙升，所以线上通常会设 max_pixels（如 1280×28×28 ≈ 1M 像素，上限约 1,280 token）或启用视觉 token 剪枝。

10. 为什么统一理解与生成模型（如 Janus-Pro）往往要把「理解编码器」和「生成编码器」解耦？

因为理解和生成对视觉表征的要求是互相冲突的：理解需要高度抽象的语义表征（忽略无关纹理、光照、像素抖动，SigLIP 擅长），而生成需要极高保真的底层像素/潜空间表征（VAE / VQGAN 擅长）。硬用同一个 VQ 离散 tokenizer 同时做理解与生成，往往两头不讨好——理解打不过 SigLIP+LLM，画质打不过 Diffusion。把理解输入走 SigLIP、生成走独立像素通路（或 MoT 分离 FFN + 扩散头），可以让两边各自吃到最优表征。

11. 视频理解怎么处理长视频（几十分钟甚至几小时）的 token 爆炸问题？

按粗到细有四层办法：① 时空压缩：3D Conv 合并相邻帧 + 2×2 空间合并（单步降 8×）；② SlowFast / 差异帧压缩：静态背景帧极度相似，对变化小的帧只保留少量全局 token（Fast 通路），关键变化帧给高分辨率（Slow 通路），或直接做帧间 token 相似度合并；③ 动态分辨率预算：固定整段视频总 token 上限（如 16K），视频越长单帧分辨率越低；④ 记忆库 / Agent 检索：先低帧率粗扫全片定位时间戳区间，再按需高帧率精看目标片段（类似 RAG 思路）。

12. 多模态推理引擎（如 vLLM）在做 Prefix Caching 和调度时，和纯文本 LLM 有什么区别？

三个关键区别：① 缓存键设计：多模态输入里图像被编码成一串相同的 placeholder token ID，如果只按 token ID 算前缀哈希，不同图片会碰撞误命中！必须把图像内容哈希 + 预处理参数一并写进 KV block 的哈希键；② 异构计算隔离：ViT 编码是 compute-bound 的密集计算，且不同请求图片数量/分辨率方差极大，不能阻塞纯文本 decode，需要图像编码结果缓存和 Encode-Prefill-Decode（EPD）分离调度；③ 分块显存预估：同一条请求的视觉 token 往往长达数千，Chunked Prefill 时需注意是否允许把单张图切跨 chunk（若用 Prefix-Bidirectional Mask 则单图不能跨 chunk 切分，Causal Mask 则可以）。

13. VLM 不改网络头，怎么同时做检测定位（Grounding）、分割和 GUI 点击？多任务混训有什么坑？

任务统一：检测、Grounding、GUI 点击、OCR、视频定位全部通过 Prompt 指定输出 Schema + 坐标/时间戳文本序列化，复用同一个 LM Head 做 Next-Token Prediction（坐标分 [0,1000) 归一化离散坐标与 Qwen2.5-VL 的绝对像素坐标两条路）。只有像素级分割因为纯文本难表达，才通过输出特殊 <SEG> token 把最后一层隐状态送给 SAM Mask Decoder（如 LISA），或通过工具调用交给外部视觉工具。

混训核心坑：① 不同任务数据量差百倍，需要温度重采样 pi∝Niαp_i \propto N_i^{\alpha}pi​∝Niα​；② 整页 OCR（2000 token）和 GUI 点击（10 token）输出长度差百倍，全局 token 平均会让短输出任务梯度被淹没，必须改用样本级平均或长度平方根加权；③ 后训练阶段可用统一 GRPO + 分任务规则奖励（IoU、落框判定、编辑距离）协同拉升。

结构化作答

面试 2 分钟答题模板

面试官问「讲一下主流多模态大模型是怎么设计的，和纯文本 LLM 核心差在哪？」时，按下面 4 步展开，条理最清晰：

  1. 先定主干架构：当前工业界视觉理解的主流是「ViT + 2×2 Pixel Shuffle Merger / MLP + Decoder-only LLM」的输入级早期拼接，保留空间细节且复用 LLM 推理栈；同时对比说明 Cross-Attention（护文本零退化）和原生多模态预训练（早期混训消鸿沟）的权衡。
  2. 拆视觉输入三件套：编码器从 CLIP InfoNCE 演进到解耦 batch 依赖、细节更强的 SigLIP / SigLIP-2；高分辨率从固定缩放演进到 AnyRes 动态切图和 NaViT 原生动态分辨率（配 2D-RoPE 与 Window Attention）；位置编码用 MRoPE / Interleaved-MRoPE 统一 T/H/W 且让纯文本退化回 1D RoPE。
  3. 讲训练与能力演进：标准四阶段——先冻结主干只训 Connector 对齐，再解冻全参做大规模多模态预训练（混 15%–30% 纯文本防遗忘），接着多模态 SFT，最后用 mDPO 抑幻觉、用 GRPO/RLVR 提多模态推理。
  4. 补前沿与工程落地：点出统一理解与生成因“语义 vs 像素表征冲突”正走向双编码器/MoT + Diffusion，以及线上推理要重点防视觉幻觉、做视觉 token 剪枝、带图像哈希的 Prefix Caching 和 EPD 调度隔离。
