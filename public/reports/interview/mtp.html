MTP：多 token 预测怎么训练、怎么加速推理

DeepSeek-V3、Qwen3-Next、Qwen3.5 都用了 MTP（Multi-Token Prediction）。面试常问：它和普通的下一个 token 预测有什么区别？DeepSeek 的 MTP 模块输入是什么、每个位置预测哪个 token？推理时怎么拿它做投机解码、为什么能快 1.8 倍？本文用一个具体句子把对齐关系和加速都算出来。

30 秒背诵版

训练时：每个位置多预测几个未来 token，当辅助损失；推理时：丢掉，或者当草稿模型做投机解码

是什么：普通语言模型每个位置只预测下一个 token ti+1t_{i+1}ti+1​。MTP 让每个位置额外预测 ti+2,…,ti+1+Dt_{i+2},\dots,t_{i+1+D}ti+2​,…,ti+1+D​，额外的预测只作为训练时的辅助损失，信号更密，也逼着隐藏表示提前“规划”后面的内容。

两种结构：Meta（2024）是并行多头，共享主干上接 nnn 个独立的头，各自预测 t+1t+1t+1 到 t+nt+nt+n，彼此看不到对方。DeepSeek-V3 是串行模块：第 kkk 个模块把上一深度的隐藏状态 hik−1h_i^{k-1}hik−1​ 和真实的第 i+ki+ki+k 个 token 的 embedding 拼起来，过一个 Transformer 块，用共享的输出头预测 ti+k+1t_{i+k+1}ti+k+1​，保留了完整的因果链。

损失：L=Lmain+λD∑kLMTPk\mathcal{L}=\mathcal{L}_{\text{main}}+\frac{\lambda}{D}\sum_k\mathcal{L}^k_{\text{MTP}}L=Lmain​+Dλ​∑k​LMTPk​。DeepSeek-V3 取 D=1D=1D=1，λ\lambdaλ 前 10T token 为 0.3、后 4.8T 为 0.1。

推理：MTP 模块可以直接丢掉，主模型照常用；也可以当草稿模型做投机解码：一次前向同时验证草稿 token，DeepSeek-V3 第二个 token 的接受率 85%–90%，生成速度约 1.8 倍。

动机

为什么要多预测几个 token

训练信号更密 训练

下一个 token 预测（NTP）在每个位置只有一个监督信号，而且是 teacher forcing：模型永远拿真实前缀预测一步，容易只学局部模式。MTP 在同一个位置再加 DDD 个更远的目标，同样的数据得到更多监督，数据效率更高。

表示要“提前规划” 训练

要预测两三步之后的 token，隐藏状态 hih_ihi​ 就得编码“接下来大概要说什么”，而不只是下一个字。Meta 的实验发现这对代码这类结构性强的任务提升明显，且模型越大收益越大，小模型反而可能变差。

现成的草稿模型 推理

投机解码需要一个又快又准的草稿模型。MTP 模块本来就和主模型一起训练、共享 embedding 和输出头，猜得准，额外开销只有一个 Transformer 块，不用另外训练、部署一个小模型。

只在训练时加，不改主模型 关键

MTP 是附加在主模型之外的模块，主模型本身仍然是标准的 NTP 模型。推理时不用投机解码，就把 MTP 模块整个丢掉，输出和没有 MTP 时完全一样的接口。

推理

推理：用 MTP 做投机解码

大模型解码一次只出一个 token，而且主要受显存带宽限制：一次前向处理 1 个 token 和处理 2 个 token 耗时差不多。投机解码就是先便宜地猜几个 token，再用一次前向一起验证。以 D=1D=1D=1 为例：

步骤做什么得到
第 1 次前向主模型处理当前 token，得到下一个 token tn+1t_{n+1}tn+1​ 和隐藏状态 hn0h_n^0hn0​；MTP 模块用 hn0+Emb(tn+1)h_n^0+\mathrm{Emb}(t_{n+1})hn0​+Emb(tn+1​) 起草 t~n+2\tilde t_{n+2}t~n+2​确定的 tn+1t_{n+1}tn+1​，草稿 t~n+2\tilde t_{n+2}t~n+2​
第 2 次前向主模型把 tn+1t_{n+1}tn+1​、t~n+2\tilde t_{n+2}t~n+2​ 两个位置一起算：在 tn+1t_{n+1}tn+1​ 的位置得到主模型自己对第 n+2n+2n+2 个 token 的预测，和草稿比较一致：接受 t~n+2\tilde t_{n+2}t~n+2​，而且 t~n+2\tilde t_{n+2}t~n+2​ 位置的输出直接给出 tn+3t_{n+3}tn+3​，这一次前向产出 2 个 token
不一致：丢掉草稿，用主模型的预测，这次只产出 1 个
之后MTP 再用最新的隐藏状态起草下一个，循环平均每次前向产出 1+p1+p1+p 个 token

草稿有 DDD 个、每个被接受的概率都是 ppp（简化假设，且必须前面的都接受才轮到后面），每次前向期望产出：

E[每次前向产出的 token 数]=1+p+p2+⋯+pD=1−pD+11−p\mathbb{E}[\text{每次前向产出的 token 数}]=1+p+p^2+\dots+p^{D}=\frac{1-p^{D+1}}{1-p}E[每次前向产出的 token 数]=1+p+p2+⋯+pD=1−p1−pD+1​

DeepSeek-V3 是 D=1D=1D=1、p≈0.85–0.9p\approx0.85\text{–}0.9p≈0.85–0.9，期望 1.85–1.9 个 token，扣掉 MTP 模块和验证的开销，实测生成速度约 1.8 倍。

验证不改变输出分布：贪心解码时只接受和主模型 argmax 一致的草稿，结果与逐个生成完全相同；采样时用投机采样的拒绝采样规则（按 min⁡(1,pmainpdraft)\min\big(1,\frac{p_{\text{main}}}{p_{\text{draft}}}\big)min(1,pdraft​pmain​​) 接受，拒绝时从修正后的分布重采样），保证样本分布仍是主模型的分布。所以 MTP 加速是无损的。

手撕

代码：串行 MTP 的训练前向

class MTPModule(nn.Module):
    def __init__(self, d, block):
        super().__init__()
        self.norm_h, self.norm_e = RMSNorm(d), RMSNorm(d)
        self.proj = nn.Linear(2 * d, d, bias=False)    # M_k
        self.block = block                             # 一个 Transformer 层（因果注意力）

    def forward(self, h_prev, emb_next):               # 都是 [B, T-k, d]
        x = torch.cat([self.norm_h(h_prev), self.norm_e(emb_next)], dim=-1)
        return self.block(self.proj(x))

# tokens: [B, T]；embed、head 与主模型共享
h = main_model(tokens)                                 # h^0: [B, T, d]
loss = ce(head(h[:, :-1]), tokens[:, 1:])              # 主损失：位置 i 预测 t_{i+1}

mtp_loss = 0
for k, mtp in enumerate(mtp_modules, start=1):
    h = mtp(h[:, :-1], embed(tokens[:, k:]))           # 位置 i 拼上第 i+k 个 token：长度 T-k
    mtp_loss += ce(head(h[:, :-1]), tokens[:, k + 1:]) # 位置 i 预测第 i+k+1 个 token：T-k-1 个目标

loss = loss + lam / len(mtp_modules) * mtp_loss

形状对齐是手撕时最容易错的地方：每多一层深度，序列就少一位。第 kkk 个模块的输入是上一深度去掉最后一位的表示，配上从第 k+1k+1k+1 个 token 开始的 embedding；目标是从第 k+2k+2k+2 个 token 开始。词表很大时，每个深度都要再算一遍 [B,T,V][B,T,V][B,T,V] 的 logits，显存压力主要在这里。DeepSeek-V3 把最浅的层（含 Embedding）和最深的层（含输出头）放在同一个流水线 rank 上，MTP 模块和主模型在物理上共享这两份参数和梯度。

方法结构什么时候训练主要目的
Meta MTP共享主干 + nnn 个并行头预训练，和主模型一起提升模型能力，顺带自投机解码

DeepSeek 的 MTP 模块和 EAGLE 的草稿头结构很像，都是“上一步的隐藏特征 + 下一个 token 的 embedding”；区别在于 MTP 在预训练时就作为辅助损失一起训，梯度会回传到主模型，影响主模型的表示；EAGLE、Medusa 是在训好的模型上外挂，主模型不变。

自测

高频追问

MTP 和普通的下一个 token 预测有什么区别？

NTP 每个位置只预测 ti+1t_{i+1}ti+1​。MTP 在每个位置额外预测 ti+2,…,ti+1+Dt_{i+2},\dots,t_{i+1+D}ti+2​,…,ti+1+D​，额外的预测通过独立的头或模块完成，作为辅助损失加到主损失上。主模型本身不变，推理时仍然可以一个一个地生成。

MTP 为什么能提升模型效果？

一是训练信号更密，同样的 token 量得到更多监督；二是要预测更远的 token，隐藏表示必须编码后续的规划，而不只是下一个字的局部模式；三是 teacher forcing 下 NTP 只学一步，MTP 在一定程度上缓解了训练和生成之间的差距。

注意收益和规模有关：Meta 的实验里小模型用 MTP 反而变差，大模型收益明显，在代码任务上最大。

DeepSeek-V3 的 MTP 模块输入是什么？训练时用真实 token 还是预测的 token？

第 kkk 个模块在位置 iii 的输入是上一深度的隐藏状态 hik−1h_i^{k-1}hik−1​（k=1k=1k=1 时就是主模型最后一层的输出）和第 i+ki+ki+k 个 token 的 embedding，两者各过 RMSNorm、拼接、线性投影，再过一个 Transformer 块。

训练时用真实 token（teacher forcing），所以所有深度能在一次前向里并行算。推理做投机解码时，用主模型实际生成的 token。

为什么 DeepSeek 用串行模块，不用 Meta 的并行头？

并行头预测 t+2t+2t+2 时不知道 t+1t+1t+1 是什么，而同一个前缀后面可能有多种合理的 t+1t+1t+1，预测只能是各种可能的混合，做草稿时接受率低。串行模块把真实的 ti+1t_{i+1}ti+1​ 喂进去，保持了完整的因果链，预测的就是主模型生成时真正需要的条件分布，接受率高（85%–90%）。

推理时 MTP 模块怎么处理？

两种选择：直接丢掉，主模型就是一个普通的 NTP 模型，推理框架不需要任何改动；或者保留，作为投机解码的草稿模型，一次前向验证草稿，平均每次前向产出 1+p1+p1+p 个 token。DeepSeek-V3/R1、Qwen3-Next 的推理框架（vLLM、SGLang）都支持用 MTP 层做投机解码。

投机解码为什么能加速？会不会改变输出？

解码阶段是显存带宽瓶颈：每次前向要把全部权重和 KV cache 读一遍，算 1 个位置和算 2 个位置耗时差不多。草稿猜对时，一次前向就产出 2 个 token。

不会改变输出：贪心解码只接受和主模型 argmax 一致的草稿；采样时用拒绝采样（按 min⁡(1,pmain/pdraft)\min(1,p_{\text{main}}/p_{\text{draft}})min(1,pmain​/pdraft​) 接受，拒绝时从修正分布重采样），输出分布严格等于主模型。

接受率和加速比怎么估算？为什么 DeepSeek 只用 D=1D=1D=1？

每个草稿接受率为 ppp、草稿 DDD 个时，每次前向期望产出 1−pD+11−p\frac{1-p^{D+1}}{1-p}1−p1−pD+1​ 个 token。越往后的草稿要前面全部猜对才有用，概率按 pkp^kpk 衰减，而且越远的预测本身也越不准；每多一个模块，训练和推理都要多算一个 Transformer 块和一次大词表的输出头。D=1D=1D=1 时 ppp 高达 0.85–0.9，性价比最好。

λ\lambdaλ 为什么要从 0.3 降到 0.1？

MTP 是辅助损失，目的是改善主模型的表示，最终评价的还是主模型的下一个 token 预测。训练前期用较大的 λ\lambdaλ 让表示学会“往前看”，后期减小，让优化重心回到主损失，避免辅助任务和主任务争抢容量。

MTP 的额外开销有多大？

参数：每个模块只新增一个投影矩阵和一个 Transformer 块，Embedding 和输出头共享。DeepSeek-V3 发布的权重是 671B 主模型加 14B 的 MTP 模块。

计算：相当于多一层 Transformer，再加一次输出头的大矩阵乘和 softmax。训练时显存的主要压力来自额外一份 [B,T,V][B,T,V][B,T,V] 的 logits。

MTP 和 Medusa、EAGLE 有什么区别？

Medusa、EAGLE 是在训好的模型上外挂草稿头，主模型冻结，只为加速。MTP 在预训练阶段作为辅助损失一起训练，梯度回传到主模型，同时提升能力和提供草稿。结构上，DeepSeek 的串行 MTP 和 EAGLE 很像（隐藏特征 + 下一个 token 的 embedding），Meta 的并行多头和 Medusa 很像。

2 分钟口述

答题模板

  1. 一句话定位。MTP 让每个位置额外预测后面几个 token，训练时作辅助损失提升表示，推理时可以丢掉，也可以当草稿模型做投机解码。
  2. 讲两种结构。Meta 是共享主干 + 并行头，各头独立；DeepSeek-V3 是串行模块，用 hik−1h_i^{k-1}hik−1​ 和真实 ti+kt_{i+k}ti+k​ 的 embedding，保持因果链。
  3. 讲 DeepSeek 的计算。两个输入各自 RMSNorm、拼接、用 MkM_kMk​ 投影，过一个 Transformer 块，用共享输出头预测 ti+k+1t_{i+k+1}ti+k+1​；第 kkk 个模块序列长度 T−kT-kT−k；损失 λD∑kLMTPk\frac{\lambda}{D}\sum_k\mathcal{L}^k_{\text{MTP}}Dλ​∑k​LMTPk​，D=1D=1D=1，λ\lambdaλ 0.3 → 0.1。
  4. 讲推理。投机解码：MTP 起草，主模型一次前向验证，期望每次产出 1+p1+p1+p 个 token；DeepSeek-V3 接受率 85%–90%，约 1.8 倍；贪心或拒绝采样保证无损。
  5. 讲取舍。收益随规模增大，小模型可能变差；越远的草稿接受率按 pkp^kpk 衰减，所以 DDD 取 1；和 Medusa、EAGLE 的区别是 MTP 在预训练时一起训、会影响主模型。

常见失分点：说 MTP 让模型一次输出多个 token、改变了自回归（主模型不变，推理可以完全不用）；说 DeepSeek 的 MTP 模块输入是模型自己预测的 token（训练时是真实 token）；说 MTP 头是并行独立的（那是 Meta 的版本）；说投机解码会降低质量（验证机制保证无损）。
