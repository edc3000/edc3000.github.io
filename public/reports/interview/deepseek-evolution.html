DeepSeek 架构演进：从 V2 到 V4.1

DeepSeek 两年多里的架构改动，几乎都在回答同一个问题：怎么用更少的显存和计算，撑起更大的模型、更长的上下文。V2 用 MLA 和 DeepSeekMoE 定下骨架；V3 解决 MoE 的负载均衡、把 FP8 训练做通；V3.2 加上稀疏注意力；V4 用压缩注意力撑到百万上下文，还改了残差连接和优化器；V4.1 继续压 KV cache 和 prefill。本文按“MoE、注意力、残差与训练、后训练”几条线梳理，每个改动都讲清解决了什么。

30 秒背诵版

两条主线：FFN 越来越稀疏（MoE），注意力越来越省（KV cache 和计算）；再加上一路往低精度走的训练和推理

MoE 线：DeepSeekMoE 把专家切细（更多、更小的专家，多选几个）并隔离出共享专家；V2 用 2 个共享 + 160 个路由专家取 6；V3 改成 1 共享 + 256 路由取 8，用 sigmoid 打分，提出无辅助损失的负载均衡：给每个专家一个偏置，只影响选谁、不影响权重，负载高就调低；V4 前 3 层改用哈希路由，打分函数换成 softplus\sqrt{\mathrm{softplus}}softplus​。

注意力线：V2 的 MLA 只缓存 512 维潜向量加 64 维 RoPE key，KV cache 比 DeepSeek 67B 少 93.3%；V3.2 的 DSA 用一个轻量的索引器给所有历史 token 打分，每个 query 只读 2048 个；V4 用 CSA（每 4 个 token 压成 1 条再选 top-k）和 HCA（每 128 个压成 1 条全读）交替，加滑动窗口，1M 上下文下 KV cache 只有 V3.2 的 10%；V4.1 再做跨层共享 KV 和 FP4 KV cache。

其他：V3 的 MTP、FP8 训练、DualPipe 让 671B 模型只花 278.8 万 H800 GPU 小时；R1 证明纯 RL 能练出长思维链；V4 引入 mHC（4 条残差通道，层间混合矩阵约束为双随机矩阵）和 Muon 优化器；V4.1 加入 Engram 查表记忆、因果编码器-解码器（prefill 计算减半）。

负载均衡：从辅助损失到偏置

V2：三种辅助损失 旧做法

专家级、设备级、通信级三个平衡损失加进总 loss，惩罚“某些专家或某些卡负载过高”。问题是辅助损失的梯度会和语言模型的梯度打架：系数小了均衡不住，系数大了伤模型效果。

V3：无辅助损失的偏置 V3 起

给每个专家一个偏置 bib_ibi​，只在“选哪几个专家”时加上，算权重时不用：

选择: TopK(si,t+bi),gi,t=si,t∑j∈选中sj,t\text{选择}:\ \mathrm{TopK}\big(s_{i,t}+b_i\big),\qquad g_{i,t}=\frac{s_{i,t}}{\sum_{j\in\text{选中}}s_{j,t}}选择: TopK(si,t​+bi​),gi,t​=∑j∈选中​sj,t​si,t​​

每一步训练后，负载过高的专家 bib_ibi​ 减去 γ\gammaγ，过低的加上 γ\gammaγ（γ=0.001\gamma=0.001γ=0.001）。偏置不进梯度，不干扰语言模型的目标。另外保留一个系数很小的序列级平衡损失（0.0001），防止单条序列内部极端不均。

注意力 · V2

MLA：把每个 token 的 KV 压成一个潜向量

MHA 每个 token 每层要存所有头的 K 和 V；GQA、MQA 的思路是让多个 query 头共用 KV 头，省得多但会掉效果。MLA 换了个方向：不减少头，而是把所有头的 K、V 一起做低秩联合压缩，只缓存一个低维潜向量，要用时再上投影回去。

为什么 prefill 不吸收 常被追问

吸收后每个头每对 token 要算 576 维点积和 512 维加权求和，展开后只要 192 维和 128 维，计算量差三倍多。解码是访存瓶颈，多算无所谓，少读才重要；prefill 和训练是计算瓶颈，就展开成 MHA 算。V3.2 论文明确写了：训练和 prefill 用 MHA 模式，解码用 MQA 模式。

效果和常见误解

V2 论文里，MLA 的 KV cache 是 DeepSeek 67B 的 6.7%（少 93.3%），最大生成吞吐是 5.76 倍，消融实验里效果还略好于 MHA。V3 每 token 每层 576 个数，61 层 BF16 约 68.6 KiB。常见误解是把 MLA 说成“减少 KV 头数”，其实头数没减，减的是缓存的维度。更多显存账见 KV Cache 篇。

注意力 · V3.2

DSA：先用便宜的索引器挑，再只读挑中的 2048 条

MLA 把每条变小了，但上下文到 128K 时，每生成一个 token 仍要读 128K 条。V3.2 唯一的架构改动就是加上 DeepSeek Sparse Attention（DSA）：一个很便宜的“闪电索引器”先给所有历史 token 打分，主注意力只和分数最高的 2048 个做。

为什么必须建在 MLA 的 MQA 模式上

稀疏注意力的 kernel 要高效，每条被取出来的 KV 必须给很多 query 头复用，否则每个头各取一遍、各算一遍，访存全是零散的小块。MLA 的 MQA 模式里 128 个头本来就共用一条潜向量，正好满足；DSA 的 top-k 也因此是按 query token 选，而不是按头选。这也是 DSA 能直接在 V3.1-Terminus 上继续训练、不用改其它结构的原因。

索引器到底便宜多少 按 config 估算

每一对 (query, 历史 token)，索引器算 64 个 128 维点积，约 8192 次乘加，用 FP8；MQA 模式的主注意力要算 128 个头的 576 维点积加 512 维求和，约 13.9 万次乘加，用 BF16。乘加次数差约 17 倍，再算上 FP8 的吞吐翻倍，索引器每对的开销大约是主注意力的 1/30 量级。所以虽然索引器仍要扫全部 LLL 个 token，长上下文时整体成本大降。短序列的 prefill 则改用带掩码的 MHA 模式来模拟 DSA，效率更高。

和 NSA 的关系 常被追问

DeepSeek 在 2025 年 2 月的 NSA（Native Sparse Attention）论文里试过另一套：按块压缩、按块挑选、滑动窗口三路注意力，再用门控相加。DSA 简化成只有一路、逐 token 选，方便在已有的 MLA 模型上继续训练。到了 V4，CSA 又把“压缩 + 挑选 + 滑动窗口”的组合拿了回来，但压缩条目直接拿来挑和算，没有三路门控。

残差

残差连接：V4 的 mHC

Hyper-Connections 是什么

把残差流从 1 条加宽到 nnn 条（Xl∈Rn×dX_l\in\mathbb{R}^{n\times d}Xl​∈Rn×d），每层用三个小矩阵：AlA_lAl​ 把 nnn 条合成层的输入，ClC_lCl​ 把层的输出分回 nnn 条，BlB_lBl​ 让 nnn 条通道互相混合。相当于多了一个“残差宽度”的扩展维度，计算开销很小。三个矩阵都由当前输入动态生成，再加一个静态偏置。

为什么要约束成双随机矩阵 常被追问

不加约束的 HC 层数一多就数值不稳定：BlB_lBl​ 连乘几十次，信号可能被放大或缩小到失控。mHC 把 BlB_lBl​ 投影到双随机矩阵（非负、每行每列和为 1）上：它的谱范数不超过 1，不会放大信号；双随机矩阵相乘还是双随机矩阵，堆多少层都成立。投影用 Sinkhorn-Knopp：先取 exp⁡\expexp 保证为正，再交替做行、列归一化 20 次。AlA_lAl​、ClC_lCl​ 用 sigmoid 限制为非负、有界。

V4.1 改成 Single-Pass mHC，调整了混合的计算顺序，让整个残差混合能融合成一个 kernel，残差流只读一次、写一次，激活的显存读写量比 V4 的实现减半。

最新

V4.1-Flash：为 Agent 负载继续压 prefill 和 KV

Agent 场景的特点是输入远多于输出：每次工具调用都带回一大段内容，要重新 prefill，KV cache 也越积越大。V4.1-Flash 的改动都针对这一点。

CSA2：跨层共享 KV 和索引

每层被静态指定为三种模式之一：Full 自己算主 KV 和索引；Reindex 复用前面层的主 KV，但用自己的 query 重新选 top-k；Reuse 连选出的下标也直接复用。共享 KV 省存储，复用下标省索引器计算。解码器里还有分层稀疏索引器：第一个 Full 层从全部位置里挑出 2048 个块（每块 8 个位置）作为候选池，后面的层只在这 16384 个候选里打分，代价不再随上下文增长。

Engram：查表式的条件记忆

MoE 是“按需计算”，Engram 是“按需查表”：用最近 2、3、4 个 token 组成的 N-gram，经多头哈希映射到巨大的嵌入表里取向量，再经门控加入隐状态。论文发现它能把早期层从“拼出固定搭配”的工作里解放出来，推理和长上下文检索也变好。V4.1 用了 196B 参数、放在第 1 和第 14 层；因为地址只由 token 决定，可以提前从主机内存预取，嵌入表不必常驻显存。

FP4 主 KV cache

用 E2M1 的 FP4，每 16 个通道一个 E4M3 缩放因子（类似 NVFP4 但去掉了全局缩放），通过量化感知训练适配。注意力前先反量化，所以不依赖硬件原生支持 FP4 矩阵乘。

DSpark 取代 MTP

预训练时不再带 MTP。主干训完后单独训练一个 3 层的草稿模块，一次前向并行出 5 个草稿位置，再按置信度和系统负载动态决定验证多长，后训练时跟着主干一起更新但不回传梯度。

自测

高频追问

DeepSeekMoE 和传统 MoE（如 GShard、Mixtral）有什么区别？

两点。一是细粒度切分：把每个专家切成 mmm 份、激活的专家数也乘 mmm，总参数和计算量不变，但组合数大幅增加，每个专家学的知识更专一。二是共享专家隔离：留出几个每个 token 都经过的专家，承担通用知识，减少路由专家之间的冗余。V3 是 1 个共享 + 256 个路由取 8。

无辅助损失的负载均衡是怎么做的？为什么比辅助损失好？

给每个路由专家一个偏置 bib_ibi​，选 top-k 时用 si+bis_i+b_isi​+bi​，算门控权重时仍用原始的 sis_isi​。每步统计负载，过载的专家 bib_ibi​ 减小，欠载的增大。偏置不参与反向传播，所以不会像辅助损失那样和语言模型的梯度冲突；论文实验里效果和负载均衡都更好。V3 还留了一个系数 0.0001 的序列级损失，防止单条序列里极端不均。

MLA 的“矩阵吸收”具体是什么？为什么 prefill 不吸收？

score 里 q⊤WUKcq^{\top}W^{UK}cq⊤WUKc 可以先算 q~=WUK⊤q\tilde q=W^{UK\top}qq~​=WUK⊤q，直接和缓存的潜向量点积；输出里 ∑jajWUVcj=WUV∑jajcj\sum_j a_j W^{UV}c_j=W^{UV}\sum_j a_jc_j∑j​aj​WUVcj​=WUV∑j​aj​cj​，WUVW^{UV}WUV 并进输出投影。这样解码时 128 个头共用一条 576 维条目，相当于 MQA，读一次用 128 次。代价是每对 token 的点积维度从 192 变成 576，计算量多三倍多。解码是访存瓶颈，划算；prefill 和训练是计算瓶颈，就展开成 MHA 算。

MLA 怎么减少 KV cache？为什么 RoPE 要单独处理？

K、V 都由一个 512 维的潜向量上投影得到，推理时把上投影矩阵吸收进 query 和输出投影，只需要缓存潜向量和一个 64 维的共享 RoPE key，每 token 每层 576 个数。RoPE 在 qqq 和 kkk 之间插了一个随位置变化的旋转矩阵，上投影矩阵就吸收不进去了，所以把位置信息拆到单独的一小部分维度上。

DSA 的索引器本身还是 O(L2)O(L^2)O(L2)，为什么还能省？

索引器头数少、头维度小、用 FP8（V4 里是 FP4），每个打分只是一次 ReLU 点积，比主注意力便宜得多；主注意力从读全部 LLL 个条目变成只读 k=2048k=2048k=2048 个。长上下文时主注意力的开销占大头，所以总体大幅下降。V3.2 是从 V3.1-Terminus 继续训练得到的：先用 KL 损失让索引器模仿主注意力的分布，再整体做稀疏训练。

DSA 为什么要实现在 MLA 的 MQA 模式上？索引器怎么训练？

稀疏 kernel 要求取出来的每条 KV 能给很多 query 头复用，MQA 模式下 128 个头本来就共用一条潜向量，所以 top-k 按 query token 选、各头共用。训练先稠密预热：冻结主模型，用 KL 让索引器的分布对齐主注意力各头分数之和（2.1B token）；再稀疏训练全部参数，KL 只在选中集合上算（943.7B token）。索引器输入 detach，只吃 KL 的梯度，主模型只吃语言模型损失。

V4 的 CSA 和 HCA 有什么区别？为什么要混合使用？

CSA 每 4 个 token 压成一条，再用索引器选 top-k 条，保留了比较细的粒度，适合精确检索；HCA 每 128 个压成一条，不做稀疏、全部读，条目极少，提供便宜的全局视野。两者隔层交替，再各加一个 128 的滑动窗口补充局部信息。1M 上下文时，V4-Pro 的 KV cache 只有 V3.2 的 10%，单 token 计算量是 27%。

为什么 CSA、HCA 还要加滑动窗口？

为了严格保持因果性，query 只能看到已经完整的压缩块，看不到自己所在那一组里前面的 token；而语言建模里最近的 token 往往最重要。所以额外保留最近 128 个 token 的未压缩 KV，和压缩条目一起做注意力。

V4 为什么要对注意力输出再做一次位置为 −t-t−t 的 RoPE？

V4 的压缩条目既当 key 又当 value，而 RoPE 加在条目的最后 64 维上，value 也就带上了绝对位置 RjR_jRj​，加权求和后的输出混着绝对位置。对输出再乘 R−tR_{-t}R−t​，每一项变成 Rj−tvjR_{j-t}v_jRj−t​vj​，只和 query 与条目之间的相对距离有关，和 RoPE 的初衷一致。MLA 没有这个问题，因为它的 RoPE 走的是单独一路，不进 value。

mHC 为什么要把残差混合矩阵约束成双随机矩阵？

Hyper-Connections 把残差流扩成 nnn 条并用矩阵 BlB_lBl​ 在通道间混合，层数一多，BlB_lBl​ 连乘可能把信号放大或缩小到失控。双随机矩阵（非负、每行每列和为 1）的谱范数不超过 1，不会放大信号；而且它们的乘积仍是双随机矩阵，多深都稳定。用 Sinkhorn-Knopp 迭代 20 次投影过去。

V3 为什么能训得这么便宜？

多个因素叠加：MoE 每个 token 只激活 37B；MLA 降低注意力开销；FP8 混合精度训练，细粒度分块缩放保证精度；DualPipe 让计算和通信重叠，专家并行的 all-to-all 几乎被藏起来；节点受限路由控制跨节点通信；无辅助损失均衡减少对效果的损害。官方的 278.8 万 H800 GPU 小时只算正式训练，不含前期研究。

R1-Zero 和 R1 有什么区别？

R1-Zero 直接在 V3-Base 上做 GRPO，只用规则奖励（答案正确性和格式），证明了不经过 SFT 也能涌现长思维链和自我反思，但输出可读性差、语言混杂。R1 先用少量高质量长思维链数据冷启动，再做推理 RL、拒绝采样 SFT、全场景 RL，既保留推理能力又让输出可读。

V4.1 的因果编码器-解码器怎么减少 prefill？

把 40 层分成下 20 层编码器和上 20 层解码器。上 20 层的全局 KV 不由各层自己的隐状态算，而是由第 20 层的输出乘各层的投影矩阵直接得到。prefill 时长 prompt 只需要过下 20 层，就能得到全部全局 KV，计算量约减半；滑动窗口 KV 仍每层自己算，只对 prompt 最后一个窗口的 token 补算。

Engram 是什么？和 MoE 是什么关系？

Engram 是条件记忆：用最近几个 token 组成的 N-gram 哈希到大嵌入表里查向量，查表是 O(1)O(1)O(1) 的，地址只取决于 token，可以从主机内存预取。MoE 是条件计算，Engram 是条件记忆，论文把它们看成两个互补的稀疏维度，并发现两者之间的参数分配有一个 U 形的最优点。

一句话总结 DeepSeek 每一代压的是什么？

V2 压 KV cache 的条目大小（MLA）和 FFN 的激活参数（MoE）；V3 压训练成本（FP8、DualPipe）和负载均衡的代价；V3.2 压注意力读的条目数（DSA）；V4 连存的条目数一起压（CSA、HCA），把上下文推到 1M；V4.1 压 prefill 计算（CED）和跨层的 KV 冗余（CSA2、FP4）。

2 分钟口述

答题模板

  1. 一句话定位。DeepSeek 的架构演进围绕“降低大模型、长上下文的显存和计算成本”，主线是 MoE 和注意力两条。
  2. 讲 MoE。细粒度专家 + 共享专家；V3 的无辅助损失均衡（偏置只影响选择）、sigmoid 打分、节点受限路由；V4 的哈希路由和 softplus\sqrt{\mathrm{softplus}}softplus​ 打分。
  3. 讲注意力。MLA 缓存潜向量（KV cache 少 93.3%）；DSA 用索引器只读 top-2048；V4 的 CSA（压 4 倍再稀疏）和 HCA（压 128 倍全读）交替加滑动窗口，1M 上下文 KV cache 只有 V3.2 的 10%。
  4. 讲训练。MTP、FP8 细粒度量化、DualPipe 让 V3 很便宜；V4 用 Muon 和 mHC（双随机矩阵约束的多通道残差）提升稳定性；专家权重和 KV 逐步走向 FP4。
  5. 讲后训练和最新进展。R1-Zero 纯 RL、R1 多阶段；V3.1 混合思考；V4 先训专家再 on-policy 蒸馏；V4.1 为 Agent 负载做了 CED、CSA2、Engram 和 FP4 KV。

常见失分点：说 MLA 是减少 KV 头数（是压缩成潜向量）；说无辅助损失均衡完全不用损失（还有一个极小的序列级损失）；说偏置也用来算门控权重（只用于选择）；说 DSA 把整体复杂度降成线性（索引器仍是平方，只是很便宜）；把 V4 的 CSA 和 V3.2 的 DSA 混为一谈（CSA 是先压缩再做 DSA）。
