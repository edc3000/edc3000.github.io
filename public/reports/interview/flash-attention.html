FlashAttention：IO 感知、online softmax 与四代演进

FlashAttention 不改变注意力的结果，也不减少计算量（反向还会多算一些），却能快好几倍、显存从 O(N2)O(N^2)O(N2) 降到 O(N)O(N)O(N)。面试要讲清三件事：为什么标准注意力慢在读写显存；online softmax 怎么让分块计算得到精确结果；FA2、FA3、FA4 分别针对 A100、H100、B200 的哪个新瓶颈。本文用一个 4 个 key 的例子把 online softmax 手算一遍。

先给结论

30 秒背诵版

精确注意力；分块 + online softmax 让平方大小的矩阵不出片上 SRAM；反向重算换显存；每一代追着新硬件的瓶颈走

问题：标准注意力分三个 kernel，把 N×NN\times NN×N 的分数矩阵 SSS 和概率矩阵 PPP 写进 HBM 再读出来。这些操作计算量小、读写量大，是访存瓶颈；显存也是 O(N2)O(N^2)O(N2)。

做法：一个融合 kernel，把 Q、K、V 分块搬进片上 SRAM，算完一块的 SSS 和 PPP 就地用掉。softmax 需要整行的最大值和总和，用 online softmax 解决：每行维护当前最大值 mmm 和分母 ℓ\ellℓ，遇到更大的值就把之前的结果乘 em旧−m新e^{m_{\text{旧}}-m_{\text{新}}}em旧​−m新​ 修正，最后除以 ℓ\ellℓ，结果和标准做法完全一样。只写回 OOO 和每行的 logsumexp L=m+log⁡ℓL=m+\log\ellL=m+logℓ。

反向：不存 PPP，用 Q、K 和 LLL 重新算 P=exp⁡(S−L)P=\exp(S-L)P=exp(S−L)。多了计算，但省了 O(N2)O(N^2)O(N2) 的读写，反而更快。HBM 访问从 Θ(Nd+N2)\Theta(Nd+N^2)Θ(Nd+N2) 降到 Θ(N2d2/M)\Theta(N^2d^2/M)Θ(N2d2/M)（MMM 是 SRAM 大小）。

演进：FA2（A100）调换循环顺序、按序列长度并行、减少非矩阵乘运算，约快 2 倍；FA3（H100）用 warp 专门化和 TMA 做异步流水，让 softmax 和矩阵乘重叠，支持 FP8；FA4（B200）面对“张量核翻倍、指数单元不变”，用多项式在 FMA 单元上模拟一部分 exp，并且只在最大值涨得足够多时才重缩放。

动机

标准注意力为什么慢：读写显存，而不是算

访存瓶颈的直观账

一个头、N=32KN=32\text{K}N=32K 时，SSS 用 FP16 存就是 327682×232768^2\times2327682×2 字节 = 2 GiB，乘上头数和 batch 根本放不下。就算放得下，softmax 对每个元素只做一次减法、一次 exp、一次加法和一次除法，算术强度极低，时间全花在读写上。

论文里的实测 反直觉

GPT-2 medium（序列 1024、头维度 64、16 头、batch 64）在 A100 上前向加反向：标准注意力 66.6 GFLOPs、读写 HBM 40.3 GB、耗时 41.7 ms；FlashAttention 因为反向要重算，计算量反而多了，是 75.2 GFLOPs，但读写只有 4.4 GB，耗时 7.3 ms。

FlashAttention 是精确注意力，结果和标准实现在数值误差范围内一致；它和稀疏注意力、线性注意力那类“近似”方法是两回事。它也不改变 O(N2d)O(N^2d)O(N2d) 的计算量，长上下文时计算本身仍然是平方的。

分块算法、IO 复杂度与反向重算

IO 复杂度 论文结论

FA2：为什么调换循环顺序

  • 并行度：FA1 只在 batch 和头上并行，batch 小、序列长时 SM 占不满。FA2 外层是 Q 块，不同 Q 块互不依赖，可以分给不同的线程块，序列长度也成了并行维度。
  • warp 分工：FA1 把 K、V 切给 4 个 warp（split-K），每个 warp 算出一部分结果后要写共享内存、同步、再相加。FA2 改成把 Q 切给 warp，每个 warp 负责自己那几行的完整结果，不用互相通信。
  • 少做非矩阵乘运算：A100 的 FP16 矩阵乘是 312 TFLOPs/s，非矩阵乘的 FP32 运算只有 19.5，每次非矩阵乘运算相当于 16 次矩阵乘运算。所以只在最后除一次 ℓ\ellℓ，反向只存 LLL 而不是 mmm 和 ℓ\ellℓ 两个数。

FA3：让 softmax 藏到矩阵乘后面

  • exp 太慢：H100 SXM5 有 989 TFLOPS 的 FP16 矩阵乘，特殊函数（exp）只有 3.9 TFLOPS。头维度 128 时矩阵乘运算是 exp 的 512 倍，但 exp 吞吐低 250 倍，softmax 会占掉可观的时间。
  • warp 专门化：生产者 warp 用 TMA 异步搬 K、V，消费者 warpgroup 用 WGMMA 做矩阵乘，数据搬运和计算重叠。
  • 乒乓调度：两个 warpgroup 交替，一个在算 softmax 时，另一个在做矩阵乘；同一个 warpgroup 内部也把下一块的 QK⊤QK^\topQK⊤ 和这一块的 softmax 交错。
  • FP8：按块缩放；用随机正负号对角阵乘 Hadamard 矩阵对 Q、K 做“非相干处理”，把离群值摊平，量化误差变小，而且结果不变（正交变换不改变 QK⊤QK^\topQK⊤）。

FA4：硬件不对称地变快 最新

B200 每个 SM 每个时钟能做 8192 次矩阵乘运算（Hopper 的两倍），而指数单元（MUFU）仍然只有 16 次。论文的应对：

  • 软件模拟 exp：把 2x2^x2x 拆成 2⌊x⌋⋅2x−⌊x⌋2^{\lfloor x\rfloor}\cdot2^{x-\lfloor x\rfloor}2⌊x⌋⋅2x−⌊x⌋，整数部分直接写进浮点数的指数位，小数部分用 3 次多项式在 FMA 单元上算。只对每行 10% 到 25% 的元素这样做，其余仍走硬件，两种单元并行。3 次多项式在 BF16 精度下和硬件结果的差别在 1 个 ULP 以内（99% 的输入）。
  • 条件重缩放：只有新最大值比旧的大超过阈值 τ\tauτ 时才重缩放 O~\tilde{O}O~，τ=log⁡2256=8\tau=\log_2256=8τ=log2​256=8（在以 2 为底的指数下，相当于允许中间值最多放大 256 倍）。最后用同一个参考最大值归一化，结果仍然精确。
  • 反向：中间结果放进张量内存（TMEM），用 2-CTA 的 MMA 模式，减少共享内存流量和 dQdQdQ 的原子加。
  • CuTe-DSL：整个 kernel 用嵌入 Python 的 CuTe-DSL 写，编译比 C++ 模板快 20 到 30 倍。现在的 CuTeDSL 版本也支持 Hopper。
推理

推理时的变体：Flash-Decoding、分页 KV、FlashInfer、FlashMLA

FlashAttention 最初为训练和 prefill 设计：Q 很长，按 Q 块并行就能填满 GPU。decode 时每条请求只有 1 个 query，Q 块只有一行，按 batch、头、Q 块三个维度并行，batch 小的时候只能用上几个 SM，其余全部空闲。

Flash-Decoding：沿 KV 长度切分 2023

把 KV cache 沿序列切成若干段，每段由一个线程块独立算出部分输出 OkO_kOk​ 和它的 logsumexp LkL_kLk​，最后再做一次合并：

L=log⁡∑keLk,O=∑keLk−L OkL=\log\sum_k e^{L_k},\qquad O=\sum_k e^{L_k-L}\,O_kL=logk∑​eLk​,O=k∑​eLk​−LOk​

和 online softmax 是同一个原理，只是把“串行扫”变成“并行算完再合并”。上下文越长、batch 越小，收益越大。

分页 KV 和推理引擎

  • 分页 KV：flash-attn 从 2.5 版起，flash_attn_with_kvcache 可以接收块表，直接读 vLLM 那种按块存放的 KV cache。
  • FlashInfer：面向推理服务的注意力库，支持分页和不规则的 KV 布局、可定制的注意力变体、JIT 编译，被 vLLM、SGLang 等引擎用作后端。
  • FlashMLA：DeepSeek 2025 年 2 月开源，最初是 Hopper 上 MLA 的 decode kernel，之后扩展到 DSA 稀疏注意力；2026 年 9 月的版本转向 DeepSeek-V4.1、Blackwell 和昇腾，并移除了 Hopper 支持。

KV cache 为什么让 decode 变成访存瓶颈，见 KV Cache 篇；vLLM 怎么在不同注意力后端（FlashAttention、FlashInfer、FlashMLA）之间选择、以及 v0.17 接入 FA4、v0.20 把 FA4 设为 MLA prefill 默认后端，见 vLLM 篇。

代码：分块前向（FA2 顺序）

import torch

def flash_attn_fwd(Q, K, V, Br=64, Bc=64, causal=False):
    # Q, K, V: [N, d]，单个头。真实 kernel 里外层每个 Q 块交给一个线程块并行执行
    N, d = Q.shape
    O = torch.empty_like(Q)
    L = torch.empty(N)                                    # 每行的 logsumexp，反向要用
    for i in range(0, N, Br):                             # 外层：Q 块
        q = Q[i:i + Br] * d ** -0.5
        m = torch.full((q.shape[0],), float("-inf"))      # 每行当前最大值
        l = torch.zeros(q.shape[0])                       # 每行当前分母
        acc = torch.zeros(q.shape[0], d)                  # 未归一化的输出
        for j in range(0, N, Bc):                         # 内层：K/V 块
            if causal and j > i + q.shape[0] - 1:
                break                                     # 整块都在未来，跳过
            s = q @ K[j:j + Bc].T                         # [Br, Bc]，真实 kernel 里只在片上
            if causal:
                qi = torch.arange(i, i + q.shape[0])[:, None]
                kj = torch.arange(j, j + s.shape[1])[None, :]
                s = s.masked_fill(kj > qi, float("-inf"))
            m_new = torch.maximum(m, s.max(dim=1).values)
            alpha = torch.exp(m - m_new)                  # 旧结果换算到新最大值
            p = torch.exp(s - m_new[:, None])
            l = alpha * l + p.sum(dim=1)
            acc = alpha[:, None] * acc + p @ V[j:j + Bc]
            m = m_new
        O[i:i + Br] = acc / l[:, None]                    # 最后才除一次
        L[i:i + Br] = m + torch.log(l)
    return O, L

N, d = 256, 64
Q, K, V = torch.randn(3, N, d).unbind(0)
mask = torch.triu(torch.ones(N, N, dtype=torch.bool), 1)
ref = torch.softmax((Q @ K.T / d ** 0.5).masked_fill(mask, float("-inf")), -1) @ V
print(torch.allclose(flash_attn_fwd(Q, K, V, causal=True)[0], ref, atol=1e-5))   # True

要点：第一块时 m=−∞m=-\inftym=−∞，α=e−∞=0\alpha=e^{-\infty}=0α=e−∞=0，旧的累加量自然清零；因果情况下 Q 块和 K 块对齐时，每行在第一个 K 块里至少能看到位置 0，所以 mmm 不会一直是 −∞-\infty−∞，不会出现 NaN。真实 kernel 用 2x2^x2x 而不是 exe^xex（把 log⁡2e\log_2elog2​e 乘进缩放因子），因为硬件的指数指令算的是 2x2^x2x。

自测

高频追问

FlashAttention 减少了计算量吗？为什么能快？

没有减少，前向计算量一样，反向因为要重算 PPP 还多了。快是因为减少了 HBM 读写：标准实现把 N×NN\times NN×N 的 SSS、PPP 写进显存再读出来，而这些操作的算术强度很低，时间都花在读写上。FlashAttention 把它们留在片上 SRAM 里用完，只写回 OOO 和 LLL。论文里 GPT-2 medium 的例子，计算量从 66.6 增加到 75.2 GFLOPs，读写从 40.3 降到 4.4 GB，时间从 41.7 降到 7.3 ms。

分块之后 softmax 怎么还能算对？

online softmax。每行维护当前最大值 mmm、分母 ℓ\ellℓ 和未归一化的输出 o~\tilde{o}o~；来一块新数据，先更新 mmm，把旧的 ℓ\ellℓ 和 o~\tilde{o}o~ 乘 em旧−m新e^{m_{\text{旧}}-m_{\text{新}}}em旧​−m新​ 换算到新的最大值下，再加上这一块的贡献。扫完以后 o=o~/ℓo=\tilde{o}/\ello=o~/ℓ。分子分母用的是同一个参考最大值，所以结果和一次性算完全一致。

为什么反向要重算，而不是把 PPP 存下来？

存 PPP 要 O(N2)O(N^2)O(N2) 显存，而且反向还要把它从 HBM 读回来，又回到了访存瓶颈。只存每行的 L=m+log⁡ℓL=m+\log\ellL=m+logℓ（O(N)O(N)O(N)），反向时用 P=exp⁡(QK⊤−L)P=\exp(QK^\top-L)P=exp(QK⊤−L) 分块重算，多做一次矩阵乘，但 IO 少得多，整体更快。softmax\mathrm{softmax}softmax 反向需要的 ∑kPikdPik\sum_kP_{ik}dP_{ik}∑k​Pik​dPik​ 也换成了 Di=rowsum(dOi∘Oi)D_i=\mathrm{rowsum}(dO_i\circ O_i)Di​=rowsum(dOi​∘Oi​)，不需要整行 PPP。

FA1 和 FA2 有什么区别？

三点：一是循环顺序，FA2 外层 Q 块、内层 K/V 块，不同 Q 块互不依赖，可以沿序列长度并行，输出也不用反复写回 HBM；二是 warp 分工，FA1 把 K/V 切给 warp（split-K），要通过共享内存汇总，FA2 把 Q 切给 warp，各自独立；三是减少非矩阵乘运算，比如最后才除一次 ℓ\ellℓ。结果是大约快 2 倍，在 A100 上达到峰值的 50% 到 73%。

FA3 针对 H100 做了什么？

利用 Hopper 的异步硬件：TMA 异步搬数据、WGMMA 异步矩阵乘。用 warp 专门化让生产者 warp 搬数据、消费者 warpgroup 计算；用乒乓调度让一个 warpgroup 的 softmax 和另一个的矩阵乘重叠，因为 H100 的 exp 吞吐比矩阵乘低两个数量级。还支持 FP8，用分块量化和 Hadamard 非相干处理降低误差。FP16 比 FA2 快 1.5 到 2 倍。

FA4 针对 Blackwell 做了什么？

B200 的张量核吞吐是 Hopper 的两倍，但指数单元和共享内存带宽没变，瓶颈转到了 softmax 和数据搬运。FA4 用 3 次多项式在 FMA 单元上模拟一部分 2x2^x2x（每行 10% 到 25%），和硬件指数单元并行；只在最大值涨幅超过阈值（log⁡2\log_2log2​ 下为 8）时才重缩放；反向用张量内存和 2-CTA MMA 减少共享内存流量。用 CuTe-DSL 编写，BF16 最高 1613 TFLOPs/s。

条件重缩放为什么不影响结果？

online softmax 里，中间用哪个“参考最大值”都可以，只要分子和分母用的是同一个，最后一除就约掉了。不及时更新参考值的代价是中间的 es−me^{s-m}es−m 可能大于 1，阈值 τ\tauτ 保证它最多放大 28=2562^8=25628=256 倍，在 FP32 累加器里不会溢出。省下的是对整个 O~\tilde{O}O~（Br×dB_r\times dBr​×d）的向量乘法。

decode 时为什么还需要 Flash-Decoding？

FlashAttention 按 batch、头、Q 块并行。decode 时每条请求只有一个 query，Q 块只有一行，batch 小时并行度不够，大部分 SM 空闲。Flash-Decoding 沿 KV 的长度切分，各段并行算出部分结果和 logsumexp，最后按 O=∑keLk−LOkO=\sum_ke^{L_k-L}O_kO=∑k​eLk​−LOk​ 合并。

FlashAttention 和 KV cache、PagedAttention 是什么关系？

不同层面的东西。KV cache 是推理时避免重复计算的缓存；PagedAttention 是 KV cache 在显存里怎么分块存放、怎么分配；FlashAttention 是注意力计算的 kernel 怎么组织读写。三者可以组合：现在 vLLM 里的注意力后端（FlashAttention、FlashInfer）直接按块表读取分页的 KV cache 来算注意力。

FlashAttention 对 mask、GQA、变长序列怎么处理？

因果 mask：对角线右上方的块整块跳过，对角块内逐元素加 mask，大约省一半计算。GQA/MQA：多个 query 头读同一份 K、V，不需要复制。变长序列（varlen）：把一个 batch 里的序列首尾相接，传入每条序列的起始位置，kernel 按位置分块，避免 padding 浪费。滑动窗口：窗口外的块也整块跳过。

在 PyTorch 里怎么用上 FlashAttention？

torch.nn.functional.scaled_dot_product_attention 会根据硬件、数据类型和输入形状自动选择后端，满足条件时就走 FlashAttention 的实现。也可以直接装 flash-attn 包调用 flash_attn_func；Hopper 和 Blackwell 上的 FA3、FA4 有单独的接口（FA4 在 flash_attn.cute 里）。

2 分钟口述

答题模板

  1. 一句话定位。FlashAttention 是 IO 感知的精确注意力：不减少计算，减少 HBM 读写，显存从 O(N2)O(N^2)O(N2) 降到 O(N)O(N)O(N)。
  2. 讲瓶颈。标准实现把 N×NN\times NN×N 的 SSS、PPP 写进 HBM 再读出，softmax 算术强度低，是访存瓶颈；SRAM 快一个数量级但很小。
  3. 讲算法。Q、K、V 分块进 SRAM，online softmax 维护 mmm、ℓ\ellℓ 和未归一化输出，最大值变大时乘 em旧−m新e^{m_{\text{旧}}-m_{\text{新}}}em旧​−m新​ 修正，最后除以 ℓ\ellℓ；只写回 OOO 和 LLL；反向用 LLL 重算 PPP。IO 从 Θ(Nd+N2)\Theta(Nd+N^2)Θ(Nd+N2) 降到 Θ(N2d2/M)\Theta(N^2d^2/M)Θ(N2d2/M)。
  4. 讲演进。FA2 调换循环、沿序列并行、Q 切给 warp、减少非矩阵乘运算；FA3 用 warp 专门化、乒乓调度隐藏 softmax，支持 FP8；FA4 在 B200 上用多项式模拟 exp、条件重缩放、TMEM 和 2-CTA。
  5. 讲推理。decode 时 Q 只有一行，用 Flash-Decoding 沿 KV 长度并行再合并；配合分页 KV（块表）、FlashInfer、FlashMLA 在推理引擎里使用。

常见失分点：说 FlashAttention 是近似注意力（是精确的）；说它降低了计算复杂度（计算仍是 O(N2d)O(N^2d)O(N2d)，降的是显存和 IO）；说反向存了 PPP（是重算）；说 online softmax 需要先扫一遍求最大值（不需要，边扫边修正）；把 FA 和 PagedAttention 混为一谈。
