Norm：从 BatchNorm 到 RMSNorm

面试最常问的是“LayerNorm 和 RMSNorm 有什么区别”。本文先把这一题讲透：公式、计算量、RMSNorm 为什么好。然后简要讲 BN、IN、GN 的统计范围，以及 Norm 放在残差的哪个位置、QK-Norm 这类新用法。

先给结论

30 秒背诵版

RMSNorm = LayerNorm 去掉减均值和 β；大模型 = Pre-Norm + RMSNorm (+ QK-Norm)

LayerNorm 先减均值、再除以标准差，最后乘 γ 加 β；RMSNorm 不减均值，直接除以均方根，只乘 γ。所以 RMSNorm 参数量只有 LN 的一半，至少少三次加法，计算更快；效果和 LN 相当，LLaMA、Qwen 等大模型基本都用它。

RMSNorm 好在：计算简单、开销小；大模型里真正要控制的是向量的尺度，不一定要零均值中心化；不减均值还能保留表示里的均值信息；实践中效果不输 LN。

其他 Norm 的公式一样，区别只在统计量沿哪些维度算：BN 按通道跨 batch，LN 按样本跨特征（Transformer 里是每个 token 的 D 维），IN 是单样本单通道，GN 是单样本一组通道。位置上大模型用 Pre-Norm，新一代模型还会在 Q、K 上加 QK-Norm。

核心考点

LayerNorm 与 RMSNorm 有什么区别

LayerNorm 减均值 + 除标准差

RMSNorm 只除均方根

yi=xi1n∑j=1nxj2+ϵ⋅γy_i = \frac{x_i}{\sqrt{\dfrac{1}{n}\sum_{j=1}^{n} x_j^2 + \epsilon}}\cdot\gammayi​=n1​∑j=1n​xj2​+ϵ​xi​​⋅γ

不减均值，直接除以均方根 RMS(x)\mathrm{RMS}(x)RMS(x)，只有缩放参数 γ\gammaγ。只保证均方根为 1，原来的均值保留下来。

从计算量看（不深入到算子层面），LayerNorm 至少比 RMSNorm 多三次加法操作：求均值 E(x) 时的累加、每个分量减去 E(x)、最后加 β。这就是 LN 计算效率不如 RMSNorm 的原因。

效率更高

RMSNorm 的参数只有 γ，是 LayerNorm（γ、β）的一半；加法少三次。

数值稳定

LayerNorm 的分母是方差，当所有分量都相等时方差为 0，只能靠 ε 兜底，可能导致数值不稳定。RMSNorm 的分母是均方根，只有输入全为 0 时才会这样。

RMSNorm 为什么好

RMSNorm 是很多大模型常用的 Norm，比如 LLaMA 系列。它相对 LayerNorm 的核心特点是：只做 RMS 缩放，不做去均值。

① 计算更简单，开销更小

不需要先算均值再中心化，只需根据平方均值做缩放。更轻量，训练和推理都更高效。

② 数值更稳定，适合大模型

在 Transformer / LLM 里，很多时候真正重要的是控制向量尺度，不一定非要零均值中心化。RMSNorm 直接约束幅值，已经足够有效。

③ 保留表示中的均值信息

LayerNorm 会把均值去掉，RMSNorm 不会。这有时能保留更多原始表征里的信息，在残差结构里也比较自然。

④ 实践中效果不输 LayerNorm

在很多 LLM 里，RMSNorm 能做到和 LayerNorm 相近甚至更好的效果，同时更省算力。

手撕 LayerNorm

class LayerNorm(nn.Module):
    def __init__(self, d_model, eps=1e-5):
        super().__init__()
        self.gamma = nn.Parameter(torch.ones(d_model))
        self.beta = nn.Parameter(torch.zeros(d_model))
        self.eps = eps

    def forward(self, x):
        mean = x.mean(-1, keepdim=True)
        var = x.var(-1, unbiased=False, keepdim=True)
        return self.gamma * (x - mean) / torch.sqrt(var + self.eps) + self.beta

手撕 RMSNorm LLaMA 写法

class RMSNorm(nn.Module):
    def __init__(self, dim, eps=1e-6):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(dim))

    def forward(self, x):
        dtype = x.dtype
        x = x.float()                       # 升到 fp32 再平方
        x = x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)
        return self.weight * x.to(dtype)

手撕时常被追问：① LN 用有偏方差（unbiased=False）；② ε 加在根号里面；③ 为什么升 fp32：fp16 下平方容易溢出，bf16 的尾数精度又太低，均值会算不准。

输入均值很大时（比如连点几次「整体 +2」），RMSNorm 的输出会趋近于全是 +1：均值几乎占满了均方根，各分量之间的差异被压扁了。这就是不做中心化的代价。好在实际网络里 hidden state 各维的均值通常不会远大于它们的波动，所以 RMSNorm 够用。

顺带讲清

BN、LN、IN、GN：在哪些维度上算均值和方差

这四种 Norm 用的是同一个公式：

x^=x−μσ2+ϵ,y=γx^+β\hat{x} = \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}}, \qquad y = \gamma \hat{x} + \betax^=σ2+ϵ​x−μ​,y=γx^+β

区别只有一个：把哪些数放在一起求 μ\muμ 和 σ\sigmaσ。以 CNN 的特征图为例，输入形状是 [N, C, H, W]：N 张图，每张图有 C 个通道，每个通道是一张 H×W 的特征图。

BatchNorm 固定一个通道，跨整批样本

把这一批 N 张图在同一个通道上的 N×H×W 个数放在一起算。直觉：同一种特征（比如某个检测边缘的通道）在整批数据上被拉到同一尺度。

它依赖 batch：训练时用当前 batch 的统计量，并用滑动平均记下 running_mean / running_var；推理时直接用 running 统计量。

LayerNorm 固定一个样本，跨所有通道

把一张图所有通道的 C×H×W 个数放在一起算。每个样本自己归一化，和 batch 里其他样本无关，训练和推理的计算方式一样。

InstanceNorm 固定一个样本的一个通道

只在一张图的一个通道内部、H×W 个数上算。它会抹掉单张图的整体亮度和对比度这类“风格”信息，所以常用在风格迁移里。

GroupNorm 固定一个样本，跨一组通道

把一张图的 C 个通道分成 G 组，每组 (C/G)×H×W 个数一起算。不依赖 batch，适合每张卡只能放一两张大图的检测、分割任务。G = 1 时就是 LN，G = C 时就是 IN。

NLP 为什么不用 BN：BN 要把不同句子、不同位置的 token 放在一起统计。可是序列长度不一，还有 padding；大模型每张卡上的 batch 又小，统计量噪声很大；自回归推理时 batch 常为 1，训练和推理对不上。LN 只看单个 token 自己的 D 维，这些问题都没有。

放在哪

Pre-Norm 还是 Post-Norm

Post-Norm x_(l+1) = Norm(x_l + F(x_l))

  • 每层输出都被重新归一化，残差通路上也有 Norm，梯度要穿过 L 个 Norm 才能回到底层。
  • Xiong 等人（2020）证明：初始化时靠近输出层的梯度很大，必须用 warmup 慢慢升学习率，层一深就难训。
  • 调好了以后效果往往更好，因为每一层都实实在在改变了表示。

Pre-Norm x_(l+1) = x_l + F(Norm(x_l))

  • 残差是一条恒等的直通路径，梯度可以无损传回底层，训练稳定，对 warmup 不敏感，能堆很深。
  • 代价：x_l 的范数随层数累积变大，而每层新加的 F(·) 输入被归一化了，相对贡献越来越小。常见的说法是“深层更像在变宽，而不是在变深”。
  • 最后一层输出要再过一个 final norm 才接 LM head，否则尺度不受控。

折中方案：DeepNorm（DeepNet，2022）保留 Post-Norm，但把残差放大成 Norm(α·x + F(x))（α > 1），并缩小子层的初始化，把 Transformer 训到了 1000 层。Sandwich-Norm 在子层输出端再加一个 Norm，先把 F(x) 的尺度控制住再加回残差，缓解 Pre-Norm 主干上范数越来越大的问题。

大模型里的新用法

QK-Norm 与零中心 RMSNorm

QK-Norm Qwen3、OLMo 2、Gemma 3

在 Q、K 投影之后、加 RoPE 之前，按头各做一次 RMSNorm。

不加的话，Q·K 的数值可能越训越大，softmax 饱和成接近 one-hot，梯度变差，表现为 loss spike。ViT-22B 在大规模训练中观察到 attention logit 增长，用 QK LayerNorm 解决了这个问题。Qwen3 用它替代了 Qwen2 的 QKV bias,Gemma 3 用它替代了 Gemma 2 的 logit soft-capping。

零中心 RMSNorm Qwen3-Next、Gemma

把缩放权重写成 1 + γ,γ 初始化为 0。

普通 RMSNorm 的 γ 初始化为 1，一般不加 weight decay，否则会被往 0 拉。Qwen 团队发现 QK-Norm 里个别 γ 会异常增大。改成零中心后，weight decay 把 γ 拉回 0，也就是把实际缩放拉回 1 附近，正好约束住异常增长。详见 Qwen3 → Qwen3.5 架构演进。

一个现代 LLM 的 decoder 层里通常有 4 个位置会用到 Norm：attention 前和 FFN 前（Pre-Norm）、Q 和 K 上（QK-Norm），以及整个模型最后再加一个 final norm。用了 Sandwich 的模型还要在两个子层的输出端各加一个。

自测

高频追问

为什么 Transformer 用 LayerNorm，不用 BatchNorm？

① 序列长度不一，padding 位置会污染 batch 统计量；② 大模型训练时每张卡上的 batch 往往很小，统计量噪声大；③ 自回归推理时 batch 常常为 1，而且是逐 token 生成，训练和推理的统计量对不上；④ 对文本来说，同一位置不同句子的 token 本来就不可比，跨样本求均值没有意义。

LN 对每个 token 自己的 D 维特征归一化，不依赖 batch，训练和推理完全一致。

BatchNorm 训练和推理有什么区别？momentum 怎么理解？

训练时用当前 batch 的均值方差，同时用滑动平均更新 running_mean / running_var；推理时直接用 running 统计量。PyTorch 的 momentum 是新值的权重：running = (1 − m)·running + m·batch，默认 0.1。另外，running_var 存的是无偏估计。

常见 bug：推理忘了 model.eval()；微调时 batch 太小，running 统计量被带偏，这时可以冻结 BN，或者换成 GN。

RMSNorm 比 LayerNorm 好在哪？为什么效果不掉？

省掉了求均值、减均值和 β，参数少一半，规约少一次，在 GPU 上是 memory-bound 的小算子，能快不少。原论文在多个模型上报告提速 7%–64%。

效果不掉的解释：LN 的作用主要来自缩放不变性，它能稳定前向尺度和梯度；平移不变性的贡献不大。RMSNorm 保留了缩放不变性，还顺带保住了均值信息。

Pre-Norm 和 Post-Norm 的区别？为什么大模型都用 Pre-Norm？

Post-Norm 先加残差再归一化，残差通路上也有 Norm；Pre-Norm 只归一化子层的输入，残差是恒等直通。

Pre-Norm 的梯度能无损传回底层，训练稳定，几十上百层也不需要精调 warmup，大模型最看重的就是这一点。Post-Norm 初始化时靠近输出层的梯度很大，必须 warmup，层一深就容易发散。Pre-Norm 的代价是深层贡献被稀释，同样的层数下，最终效果可能略差于调好的 Post-Norm。

Pre-Norm 为什么要加 final norm？

Pre-Norm 主干上的 x_l 一路累加，从来没被归一化过，范数会随层数增长。如果不在最后加一个 Norm 就直接接 LM head，logits 的尺度没法控制。所以 LLaMA 这类模型在最后一层之后、LM head 之前都有一个 model.norm。

QK-Norm 加在哪？解决什么问题？

加在 Q、K 线性投影之后、RoPE 之前，按头对 head_dim 做 RMSNorm，V 不加。

它把 Q、K 的尺度固定住，Q·K 不会无限增大，softmax 不会饱和，loss spike 少了，也能用更大的学习率。Qwen3 因此去掉了 QKV bias，Gemma 3 因此去掉了 soft-capping。

Norm 的参数要不要加 weight decay？

通常不加。γ 的“自然值”是 1，加了 weight decay 会被往 0 拉，相当于缩小这层的输出；β 也一样，一般连同所有 bias 一起排除在 weight decay 之外。

例外是零中心写法（1 + γ）：这时 γ 的自然值是 0，加 weight decay 反而是在把缩放拉回 1，Qwen3-Next 就是这样防止 Norm 权重异常增大的。

ε 放在哪？为什么 RMSNorm 要升到 fp32 算？

ε 加在根号里面：√(σ² + ε)，防止方差为 0 时除零。常见取值：BN 1e-5，BERT 的 LN 1e-12，LLaMA 的 RMSNorm 1e-6 或 1e-5。

fp16 的最大值只有 65504，平方很容易溢出；bf16 不会溢出，但尾数只有 7 位，几千维求和取均值的误差很大。所以实现上先转 fp32 算出缩放系数，再转回原 dtype。

BN 推理时可以融合进卷积，LN 为什么不行？

推理时 BN 用的是固定的 running 统计量，整体就是一个逐通道的仿射变换 y = a·x + b，可以直接折进前面卷积或线性层的权重和偏置，零开销。

LN / RMSNorm 的统计量依赖当前输入，每个 token 都不一样，没法提前算成常数，只能单独算，或者和前后的算子做 kernel fusion。

GroupNorm 和 InstanceNorm 用在哪？

GN 不依赖 batch，适合检测、分割这类每张卡只能放 1–2 张大图的任务，扩散模型的 UNet 也普遍用 GN。G = 1 时退化为 LN，G = C 时退化为 IN。

IN 对每张图的每个通道单独归一化，会抹掉这张图的整体亮度、对比度这类“风格”统计量，所以风格迁移里常用（AdaIN 就是把 γ、β 换成风格图的统计量）。

Norm 为什么能帮助训练？只是解决 Internal Covariate Shift 吗？

BN 原论文的解释是减少 Internal Covariate Shift（各层输入分布随训练漂移）。后来 Santurkar 等人（2018）的实验发现，人为加入分布漂移后 BN 依然有效，他们认为 BN 主要是让损失曲面更平滑，梯度更可预测，所以能用更大的学习率。

面试时可以两种说法都讲：控制各层激活的尺度，让优化更平滑稳定；ICS 是原始动机，但不是公认的主要原因。

2 分钟口述

答题模板

  1. 先讲 LN 和 RMSNorm 的公式差别。LN 减均值、除标准差、乘 γ 加 β；RMSNorm 不减均值，直接除以均方根，只乘 γ。
  2. 讲效率和稳定性。RMSNorm 参数量减半，至少少三次加法，计算更快；LN 的方差趋近 0 时可能不稳定，RMSNorm 更稳；两者效果相当。
  3. 讲 RMSNorm 为什么好。大模型里要控制的是向量尺度，不一定要零均值；还保留了均值信息；所以 LLaMA 之后基本都用它。
  4. 顺带讲 BN、IN、GN。公式一样，区别在统计范围：BN 按通道跨 batch（训练和推理统计量不同，NLP 不用），IN 单样本单通道，GN 单样本一组通道。
  5. 讲位置。Post-Norm 需要 warmup、深了难训；Pre-Norm 残差直通、训练稳定，代价是深层贡献被稀释，还需要 final norm。再提一下 DeepNorm 和 Sandwich-Norm。
  6. 讲新趋势。QK-Norm 防止 attention logits 过大、减少 loss spike；零中心 RMSNorm 配合 weight decay 约束 Norm 权重，可以举 Qwen3-Next 的例子。

常见失分点：说 Transformer 的 LN 跨序列长度归一化（只跨 D）；说 RMSNorm 也有 β（没有）；把 PyTorch BN 的 momentum 说成旧值的权重（是新值的权重）；手撕 LN 用了无偏方差；说 Pre-Norm 全面优于 Post-Norm（只是更好训）。
