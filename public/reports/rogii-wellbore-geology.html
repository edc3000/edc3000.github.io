核心结论

要预测什么：水平井钻过 Prediction Start 后，每一英尺位置对应的地层 TVT 坐标。

怎么预测：先生成稳定基础轨迹，再用邻井和本井前缀构造 GR(TVT) 参考，通过分段后验搜索修正，并对高不确定井自动减弱修正。

最终结果：Public RMSE 6.100，Private RMSE 8.074。RMSE 越低越好。

这场比赛在解决什么真实问题

石油与天然气水平井不是竖直向下钻，而是进入目标地层后沿水平方向延伸。钻头需要尽量停留在有效储层中，但地下岩层会倾斜、起伏，钻井人员看不到地下，只能依赖井眼轨迹和随钻测井信号判断当前位置。

比赛把这个过程转成序列预测：给模型井的已钻前段和地层参考曲线，让模型推断尚未提供 TVT 的后段位于地层序列的什么位置。

评分方式：RMSE
对每个待预测行比较预测 TVT 与真实 TVT，平方后求平均，再开平方。较大的单点错误会受到更重惩罚。 RMSE = sqrt( (1/N) × Σ(TVT_pred − TVT_true)² )

先认识五个基础概念

MD · 沿井距离

Measured Depth，从井口沿弯曲井眼累计走过的长度，不是垂直深度。数据约每 1 ft 记录一行。

X / Y / Z · 空间位置

X、Y 是平面坐标，Z 是高程。它们描述钻头在三维空间中的位置和井眼形状。

GR · 岩层指纹

Gamma Ray 反映岩石天然放射性。不同地层会形成不同信号模式，但同一模式可能重复，数据也可能缺失或含噪声。

TVT · 地层坐标

True Vertical Thickness 在本数据中作为累计地层坐标，表示钻头位于地层序列的什么位置。它是比赛的预测目标。

Typewell · 垂直参考字典

Typewell 给出 TVT → GR 的参考曲线。模型把水平井观察到的 GR 与这张字典及邻井曲线对齐，从而反推出 TVT。

输入和输出：训练集、测试集要分开理解

训练集给“题目 + 完整答案”，测试集只给“题目 + 前半段提示”，模型要补出后半段答案。每口井都由一份水平井文件和一份垂直参考井文件组成。

银牌方案：六个步骤连起来看

六步构成一条连续流水线：前四步准备可信参考，第五步生成另一条地层轨迹，第六步判断这条轨迹值得采用多少。每一步均包含计算过程、关键参数、代码和失败保护。

步骤一：先生成一条稳定的基础轨迹不从零猜答案，先用成熟的几何与信号模型给后续修正提供可靠锚点。

像导航先给出一条大体可靠的主路线。后面的复杂算法只负责局部纠偏，不允许把整条路线推翻。

输入
测试井的 MD、X/Y/Z、GR、已知 TVT 前缀，以及该井的 typewell 参考曲线。
输出
从 Prediction Start 到井尾逐行连续的 TVT_base，也是最终融合的安全基线。

具体计算：先把井眼几何和前缀 TVT 转成地层面状态，再用 GR/typewell 对齐为候选位置打分；粒子滤波在多条可能路径间保留概率质量，树模型学习其系统性残差，最后叠加投影、接触面和可见前缀校正，形成平滑连续轨迹。

核心状态：U = TVT + Z；因此 TVT = U − Z。
关键设置：GR 噪声系数 1.30；分支修正强度 2.40 ft；单次修正上限 4.50 ft。
关键代码 · 融合锚点并在地层面空间做稳健投影
def build_base_trajectory(t_ridge, t_selector, t_learned, z, md):
    # 两条粒子滤波轨迹先形成稳定锚点
    t_anchor = 0.30 * t_ridge + 0.70 * t_selector

    # 转到 U = TVT + Z 空间，地层面趋势会比原始 TVT 更平滑
    u_anchor = t_anchor + z
    u_trend = robust_poly_projection(md, u_anchor, degree=3)

    # 保留 25% 原锚点，并加入 75% 的物理连续投影
    t_projected = 0.25 * t_anchor + 0.75 * (u_trend - z)

    # 与训练得到的轨迹模型融合，输出后续模块的安全基线
    t_base = 0.60 * t_projected + 0.40 * t_learned
    return t_base
为什么有效
几何提供连续性，GR 提供地层纹理，粒子滤波保留多种解释，树模型补偿固定偏差，几类信息互相约束。
失败保护
GR 缺失时仍可依靠几何与已有轨迹；任何新分支最终都只能对这条基础轨迹做有界修正。
步骤二：把 773 口训练井做成 GR(TVT) 参考库把训练井中已经知道答案的 GR 信号，整理成可以按地层坐标查询的字典。

typewell 像一本通用字典，但邻近水平井更像当地口音。先把每口训练井整理成一本“小字典”，测试时再挑最像的几本参考。

使用的训练列
X, Y, TVT, GR。其中完整 TVT 只来自训练集，不会读取测试井隐藏答案。
每口井保存什么
井号、井的中心 X/Y，以及一条按 TVT 从浅到深排列的 GR 曲线。

具体计算：把每一行真实 TVT 四舍五入到最近的 0.5 ft 网格；同一网格可能落入多行 GR，取这些 GR 的中位数；按 TVT 排序后得到该井的 GR_reference(TVT)。

分箱：bin(TVTᵢ) = round(TVTᵢ / 0.5) × 0.5
聚合：GR_w(b) = median { GRᵢ | bin(TVTᵢ) = b }
关键代码 · 把一口训练井压缩成 0.5 ft 分辨率参考曲线
def build_reference_curve(horizontal, step_ft=0.5):
    # 只允许训练集的完整 TVT 进入参考库
    tvt = pd.to_numeric(horizontal["TVT"], errors="coerce").to_numpy()
    gr = pd.to_numeric(horizontal["GR"], errors="coerce").to_numpy()
    valid = np.isfinite(tvt) & np.isfinite(gr)

    # 将相近 TVT 合并到同一个 0.5 ft 网格
    tvt_bin = np.round(tvt[valid] / step_ft) * step_ft
    curve = pd.DataFrame({"TVT": tvt_bin, "GR": gr[valid]})

    # 中位数能降低 GR 尖峰和重复穿层的影响
    curve = curve.groupby("TVT", as_index=False)["GR"].median()
    if len(curve) < 20:
        raise ValueError("有效 TVT 网格不足")
    return curve.sort_values("TVT")
为什么取中位数
同一地层位置可能被水平井多次穿过，也可能有尖峰噪声；中位数比均值更不容易被极端值拉偏。
失败保护
有效标注不足或聚合后少于 20 个 TVT 网格的训练井直接跳过，避免短曲线污染参考库。
步骤三：从 32 口空间候选里选出最匹配的 3 口“离得近”只是初筛，最终必须在目标井已知前缀上证明自己的 GR 模式确实匹配。

邻近井的地层通常更相似，但最近的井不一定最像。先按地图距离找候选，再拿已经知道答案的前半段检验匹配程度。

具体计算：用目标井 X/Y 中位数作为井中心，按平面距离取最近 32 口训练井；逐井把候选 GR 曲线插值到目标前缀的 TVT_input，稳健拟合 目标GR ≈ a × 候选GR + b，消除仪器增益和偏移差异。

候选分数：score = 前缀归一化 RMSE + 0.02 × log(1 + 距离/500) + 0.5 × (1 − 覆盖率)
融合权重：wⱼ ∝ exp(−(scoreⱼ − 最佳score) / 0.15)
关键代码 · 用可见前缀给邻井打分并软融合
def select_neighbor_reference(query, curves, typewell_gr):
    # 先按目标井中心位置取最近的 32 口候选井
    center = np.nanmedian(query[["X", "Y"]].to_numpy(float), axis=0)
    ranked = rank_by_xy_distance(center, curves, exclude=query.well_id)[:32]

    candidates = []
    for distance, curve in ranked:
        # 只在已知 TVT 前缀上比较候选 GR，不能读取隐藏答案
        expected = interpolate_without_extrapolation(curve, query.prefix_tvt)
        valid = np.isfinite(expected) & np.isfinite(query.prefix_gr)
        if valid.sum() < 80:
            continue

        # 稳健校准不同井之间的 GR 增益和偏移
        slope, offset = robust_affine(expected[valid], query.prefix_gr[valid])
        residual = query.prefix_gr[valid] - (slope * expected[valid] + offset)
        nrmse = rms(residual) / robust_scale(query.prefix_gr[valid])
        coverage = valid.sum() / np.isfinite(query.prefix_gr).sum()
        score = nrmse + 0.02 * np.log1p(distance / 500) + 0.5 * (1 - coverage)
        profile = slope * interpolate_curve(curve, typewell_grid) + offset
        candidates.append((score, profile))

    # 选择分数最低的 3 口，并用温度 0.15 转成软权重
    selected = sorted(candidates, key=lambda item: item[0])[:3]
    neighbor_gr = soft_weighted_curve(selected, temperature=0.15)
    return 0.50 * neighbor_gr + 0.50 * typewell_gr
选完以后
取得分最低的 3 口井做软权重平均，再与目标井自带 typewell 各占 50%，得到回退参考曲线。
为什么不是只选最近一口
距离只代表地理相近；前缀误差检查能识别局部断层、相变和测井尺度不同，多井融合也能降低单井偶然失配。
失败保护：强制排除与查询井同 ID 的训练文件；候选至少需要 80 行有效前缀匹配；没有合格邻井时完全回退到校准后的 typewell。
步骤四：在有证据的范围内叠加本井前缀本井已钻前段最贴近本井地质，但只在真实覆盖到的位置使用，绝不远距离外推。

邻井提供附近区域的经验，目标井前缀提供当前井刚刚观察到的事实。本井前缀更相关，但只覆盖有限地层范围，超出范围后必须回退。

具体计算：只取 Prediction Start 之前同时具有 TVT_input 和 GR 的行，按 0.5 ft TVT 网格聚合为本井前缀曲线。对参考网格中的每个 TVT，检查它是否位于前缀最小值与最大值之间，并计算到最近前缀网格的距离。

有支持时：GR_ref = 0.50 × GR_本井前缀 + 0.50 × GR_邻井/typewell
无支持时：GR_ref = GR_邻井/typewell
支持条件：位于前缀 TVT 范围内 且 最近网格距离 ≤ 2 ft
关键代码 · 仅在本井前缀真正覆盖的位置叠加参考
def overlay_visible_prefix(horizontal, fallback, grid_tvt):
    # TVT_input 非空的位置就是模型允许使用的已知前缀
    known = horizontal["TVT_input"].notna() & horizontal["GR"].notna()
    prefix = pd.DataFrame({
        "TVT": np.round(horizontal.loc[known, "TVT_input"] / 0.5) * 0.5,
        "GR": horizontal.loc[known, "GR"],
    }).groupby("TVT", as_index=False)["GR"].median()

    # 前缀太短时不冒险，直接保留邻井和 typewell 参考
    if len(prefix) < 3:
        return fallback.copy()

    nearest_gap = distance_to_nearest(prefix["TVT"].to_numpy(), grid_tvt)
    supported = (
        (grid_tvt >= prefix["TVT"].min())
        & (grid_tvt <= prefix["TVT"].max())
        & (nearest_gap <= 2.0)
    )

    # 只修改有近距离观测支持的网格，范围外禁止外推
    prefix_gr = np.interp(grid_tvt, prefix["TVT"], prefix["GR"])
    result = fallback.copy()
    result[supported] = 0.50 * prefix_gr[supported] + 0.50 * fallback[supported]
    return result
为什么有效
它自动吸收目标井自己的 GR 尺度、局部沉积特征和相位，比任何外部参考都更贴近当前井。
失败保护
前缀少于 3 个有效 TVT 网格时不叠加；覆盖范围外不做外推，直接使用步骤三的回退参考。
步骤五：用 STRIDE-lite 搜索多条合理地层轨迹沿井分段前进，同时考虑 GR 匹配和地层变化连续性，而不是逐行独立猜 TVT。

单个 GR 数值可能在很多地层重复出现，逐点匹配很容易认错层段。算法保留多条候选路线，走过一段后再综合整段证据淘汰不合理路线。

搜索状态
U = TVT + Z 表示地层面位置；r = dU/dMD 表示沿井前进时地层面的变化率。
搜索起点
从最后一个已知 TVT_input 锚定 U，并根据可见前缀估计初始变化率。

具体计算：每 120 行作为一个段。对 beam 中每条候选轨迹尝试若干变化率增量，推算段末 U；再把段内 U 插值成 TVT，通过步骤四的 GR_ref(TVT) 得到期望 GR，与真实水平井 GR 比较。每轮只保留累计代价最低的 192 条路径。

段末状态：U_end = U_start + r × ΔMD
总代价：Cauchy 型 GR 失配代价 + 相邻段变化率持续性惩罚
计算规模：120 行/段；每 4 行采样一次 GR；beam 192；最后保留前 32 条后验路径
关键代码 · 分段扩展候选路径并保留后验最优 beam
def decode_with_beam(md, z, observed_gr, reference, initial_state):
    beam = initialise_rate_hypotheses(initial_state)

    # 每 120 行作为一段，避免逐行搜索导致状态空间爆炸
    for left, right in segment_boundaries(len(md), rows=120):
        expanded = []
        for path in beam:
            for rate_delta in RATE_DELTA_STEPS:
                # 地层变化率应缓慢变化，不能突然跳到任意方向
                rate = path.rate + rate_delta * RATE_STEP
                if abs(rate) > MAX_ABS_RATE:
                    continue

                end_u = path.u + rate * (md[right] - md[left])
                gr_cost = cauchy_segment_cost(
                    path.u, end_u, observed_gr, reference, stride=4
                )
                persistence = 0.5 * ((rate - path.rate) / RATE_SIGMA) ** 2
                expanded.append(path.extend(end_u, rate, gr_cost + persistence))

        # 每段只保留累计代价最低的 192 条路径
        beam = sorted(expanded, key=lambda path: path.score)[:192]

    # 最优单路径给出 MAP，前 32 条加权平均给出 consensus
    best = sorted(beam, key=lambda path: path.score)[:32]
    map_tvt = interpolate_path(best[0], md) - z
    consensus_tvt = posterior_average(best, md) - z
    return consensus_tvt, map_tvt
两种输出
MAP 是总代价最低的单条路径；consensus 是前 32 条路径按后验权重求平均，更平滑也更稳健。
失败保护
Cauchy 代价降低 GR 尖峰影响；缺失 GR 自动跳过；变化率上限与持续性惩罚防止轨迹突然跳层。
步骤六：用模型分歧决定修正多少新轨迹意见一致时正常采用，意见分裂时大幅减弱，最终仍由基础轨迹兜底。

如果最佳单路线和多路线平均答案差得很远，说明这口井存在多种同样合理的解释。此时不应大胆改动，而应更相信稳定基线。

具体计算：先将 STRIDE 轨迹设为 75% consensus + 25% MAP。然后逐井计算两者差值的 RMS 作为不确定性；以当前测试井集合的不确定性第 85 百分位为阈值，高于阈值的井把修正倍率从 1.0 降为 0.25。

不确定性：u_w = RMS(TVT_consensus − TVT_MAP)
最终预测：TVT_final = TVT_base + 0.425 × gate_w × clip(TVT_stride − TVT_base, −40, 40)
门控：普通井 gate = 1.0；高分歧井 gate = 0.25
关键代码 · 根据两条后验轨迹的分歧限制最终修正
def risk_gated_blend(base, consensus, map_path, threshold):
    # 共识轨迹更稳定，MAP 保留最优单路径的局部细节
    stride = 0.75 * consensus + 0.25 * map_path

    # 不看真实答案，只用两条预测的分歧衡量模型犹豫程度
    uncertainty = np.sqrt(np.mean((consensus - map_path) ** 2))
    gate = 0.25 if uncertainty > threshold else 1.0

    # 先把单行差异限制在正负 40 ft，再只采用 42.5%
    delta = np.clip(stride - base, -40.0, 40.0)
    final = base + 0.425 * gate * delta
    return final, uncertainty


# 阈值由当前测试井的不确定性分布得到，不使用隐藏 TVT
threshold = np.quantile(all_well_uncertainties, 0.85)

最大影响
即使两条轨迹相差 100 ft，也先截断成 40 ft：普通井最多移动 17 ft，高分歧井最多移动 4.25 ft。
为什么没有泄漏：门控只比较模型自己的两条预测，不读取测试井真实 TVT。它衡量的是模型是否犹豫，不是根据隐藏答案挑结果。
最终公式：预测 = 基础轨迹 + 0.425 × 风险门控 × clip(STRIDE − 基础轨迹, −40, 40)。

局限与复盘

  • 本地验证偏乐观：按训练井模拟的隐藏后缀与真正隐藏井仍存在分布差异，因此本地误差不能直接等价为最终表现。
  • 空间近邻可能失配：地理距离相近不代表地层历史完全一致，断层和相变会让邻井参考产生偏差。
  • GR 存在重复层段：相似 GR 模式可能出现在多个 TVT 位置，序列搜索仍可能发生层段混淆。
  • 门控是相对阈值：第 85 百分位由当前测试井集合决定，测试井构成变化会改变被衰减的井。
  • 基础轨迹仍有随机性：粒子滤波和集成模型存在方差，因此银牌方案使用截断与弱融合限制新增分支的影响。
